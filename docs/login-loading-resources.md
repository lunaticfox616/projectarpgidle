# 로그인 대기와 에셋 준비

로그인 대기 화면은 게임 시작 전용 경계다. 전투 이미지는 게스트 시작 또는 로그인 후
`ensureBattleAssetsLoadedBeforeEntry`에서 준비한다. 로그인 화면의 탭 갱신으로 이미지 로딩을
시작하지 않는다. 로그인 화면을 열어도 이미 받은 이미지 캐시는 폐기하지 않는다.

## 반복 작업

- UI는 로그인 화면을 열 때 전투 RAF와 모바일 전투 미리보기 타이머를 취소한다.
- `project-idle:startup-visibility`를 받아 main이 전투 tick·자동 저장 예약을 중단/재개한다.
  재개 전에 전투 시계의 잔여 시간을 초기화해 로그인 대기 시간을 몰아서 실행하지 않는다.
- 프레임 측정은 state의 `startupOverlayActive`와 같은 이벤트를 사용한다. 로그인 복귀 시
  이전 프레임 시간을 초기화하여 대기 시간이 느린 프레임으로 기록되지 않는다.
- 로그인 장식 입자는 기존 위치에 정적으로 표시한다. 가려진 게임 패널의 블러 합성과
  CSS 애니메이션도 중단한다. 로그인 배경·로고·폰트·인증/세션 처리는 유지한다.
- 시연 영상은 소개 창을 열었을 때만 재생하는 기존 동작을 유지한다.

로그인 진입이 이미 진행 중인 다운로드를 중단하거나 전체 게임 JavaScript를 분할하는 변경은 아니다.
저장 데이터 shape, 전투 규칙, 스크립트 순서는 변경하지 않는다.

## 로딩 화면

`css/components.css`가 다크·라이트 공통 로딩 스타일을 소유한다. 다른 스타일 파일의 로딩창
덮어쓰기는 제거했다. 게임 공통 surface/text/gold 토큰, 서체, 모서리를 사용하며 작은 화면은
뷰포트 안에서 스크롤한다. 회전 장식은 하나이며 동작 줄이기 설정을 따른다.

진행률은 인증·저장·이미지 준비 단계의 실제 갱신을 따른다. 무작위 타이머로 진행률을 올리지 않는다.
이미지 개수와 준비 단계를 표시하고 내부 이미지 키는 노출하지 않는다. progressbar의 접근성 값도
동일하게 갱신한다. 전체 백분율은 단계별 배분이며 다운로드 바이트 비율은 아니다.

## 측정과 검증 (2026-09-08)

Chromium, 1440×900, 새 브라우저 컨텍스트, 서비스 워커 차단, 외부 인증 요청 대체 조건.
페이지 진입 후 4초를 기다리고 이어지는 5초 동안 측정했다.

| 항목 | 이전 | 수정 후 |
| --- | ---: | ---: |
| img 요청 수 | 236 | 13 |
| img 응답 본문 합계 | 22.86 MiB | 0.475 MiB |
| 전투 RAF / 5초 | 301 | 0 |
| 성능 측정 RAF / 5초 | 301 | 0 |
| 렌더러 TaskDuration / 5초 | 0.168초 | 약 0.0044초 |

이미지 집계는 Resource Timing의 `initiatorType=img` 기준이며 CSS 배경·폰트·스크립트는
포함하지 않는다. TaskDuration은 렌더러의 작업 시간으로, 기기 전체 CPU/GPU·발열 측정이 아니다.
최종 브라우저 검사는 로그인 시 실행 중인 CSS 애니메이션도 0개임을 확인한다.

- `npm test`: 전체 스모크.
- `npm run check:architecture`: 런타임 계층·복잡도 검사.
- `npx playwright test tests/browser/core-ui.spec.js --grep "login waits|asset loading uses|entry skips unused"`:
  PC·모바일에서 로그인 대기 요청/프레임 정지, 실제 게임 진입, 로그인 복귀 반복, 에셋 지연 로딩,
  두 테마의 로딩창 경계·진행률·동작 줄이기 설정을 검증한다.
