# 게임 전체 품질 점검

목표: 저널부터 실제 게임의 각 콘텐츠를 직접 조작하고 이상을 수정한다. 전체 점검과 재검증 전에는 게임 전체 90점 달성으로 간주하지 않는다.
기능성, 가독성, 조작 예측 가능성, 진행/보상 일관성, 반응성, PC/모바일 대응을 함께 평가한다.
실제 플레이어의 재미 평가와 자동 테스트 결과는 구분한다. 이전 탐험 90점 평가는 게임 전체 점수가 아니다.

## 검증 방식

- 실제 게임 소스를 사용하는 저장 분리 환경에서 직접 조작한다. UI 기능 점검에는 후반 상태를 이용하되,
  강화된 시연 장비의 전투 결과로 밸런스를 판정하지 않는다. 전투 난이도는 일반적인 합법 장비 상태로 별도 확인한다.
- 각 콘텐츠는 진입, 핵심 조작, 자원 부족/잠김, 결과와 복귀를 확인한다. PC/모바일, 처음/후반 저장 상태를 구분한다.
- 기존 검사는 보조 증거다. 화면을 직접 확인하지 않았거나 핵심 행동을 검증하지 않은 항목은 미완료로 남긴다.
- 공개 서버 배포·PR은 이 작업의 완료 조건이 아니며 별도 요청 전 수행하지 않는다.

## 발견 사항

1. 저널 읽기의 닫기 버튼이 `form method=dialog`에 의존한다. 현재 sandbox iframe에서 폼 제출이 막혀 닫기 클릭이 동작하지 않는다.
   직접 확인: 세계수 탐험 테스트 → 기록 → 액트 1 읽기 → 닫기 무반응, ESC로는 종료 가능.
2. 저널에 획득한 기록 몇 개보다 미확인/숨겨진 카드 수십 개가 더 큰 면적을 차지한다.
   상단 분류도 조작되지 않는 텍스트여서 필요한 기록을 찾기 어렵다.
3. 빈 장비 비교 열에 텍스트 색 지정이 없어 검은 배경 위 검은 글자로 `장착한 장비 없음`이 표시된다.
   CUA에서 계산된 글자 rgb(0,0,0), 배경 rgb(24,23,19)를 확인했다.
4. 인벤토리의 포인터 배치용 빈칸 버튼 120개가 키보드 Tab 순서에 포함된다. 실제 장비에 도달하기 전에 빈칸을 모두 거쳐야 한다.

## 완료 증거

아직 전체 완료 아님. 수정과 재검증 결과를 아래에 누적한다.

### 1차 수정

- 저널 닫기를 폼 제출에서 `dialog.close()` 버튼으로 변경. CUA에서 프롤로그 삽화 열기/닫기 직접 확인.
- 기본 목록은 획득 기록만 표시. 실제 분류 버튼과 해금 조건 체크박스 추가.
  표시 가능한 해금 조건은 기존 진행 규칙을 사용하며 미확인·숨겨진 제목은 노출하지 않는다.
- 그림 없는 기록의 창 폭을 줄이고, 제목 밑줄과 글씨를 정돈했다. 기존 원문·삽화 경로는 유지했다.
- 모바일 직접 확인에서 한 장뿐인 기록 카드가 화면 반쪽만 사용하는 문제를 추가 발견해, 카드 수와 폭에 따라 열이 채워지도록 수정했다.
  액트 1은 원본 정의에 삽화가 없는 텍스트 기록이며 임의 그림을 배정하지 않았다.
- 빈 장비 비교 안내에 테마 글자색 적용. 두 테마에서 텍스트 대비 4.5:1 이상 확인.
- 포인터 배치용 빈칸은 Tab 순서에서 제외. 검색어 리셋 다음 Tab이 실제 첫 장비로 이동함을 PC·모바일 브라우저에서 확인.
- 저널 브라우저 검사 4개 통과(일반 게임의 기존 열람 검사 2개, sandbox/분류/조건/닫기 추가 검사 2개).
- 장비 선택 흐름 14개 통과. 빈칸 Tab 이동 추가 후 관련 PC·모바일 2개 재검증 통과.
- 전체 스모크 190/190 통과. 저널 JS 구조 변경 후 architecture/lint 통과.
  장비 후속은 색상과 기존 마크업의 tabindex 속성만 바꿔 구조 재검사는 생략했다.
- 미완료: 전체 콘텐츠 직접 조작, 정상 장비 전투 밸런스, 저장/해금의 종합 확인, 미확인 저널 연결.

### 2차 점검 — 플라스크·젬·기본 제작

- 실제 세계수 테스트에서 생명력 II 교체, 품질 +1(유리 10→9), 화강암 I 제작(9→3)을 직접 조작했다.
  발견 수 증가와 다음 단계 후보 갱신, 펼친 제작대 유지도 확인했다.
- 발견한 오류: 재료가 없어도 다음 단계 후보 수를 `제작 가능 6개`로 표시함.
  실제 보유 연금 유리로 구매 가능한 후보 수만 계산하도록 수정했다. 후보 목록의 재료 부족 카드는 유지한다.
- 회복 플라스크 비교가 품질을 무시했다. 실제 회복 계산 `getFlaskEffectiveHealPct`를 재사용한다.
  품질 20% 생명력 II(38.4%) → 미강화 III(40.0%)는 +1.6%p로 검증했다.
- 선택창 안내에 제작 경로를 반영하고 장식 이모지를 제거했다.
- Escape가 선택창을 남긴 채 아래 보조장비 창을 닫는 문제를 CUA로 재현했다.

### 4차 점검 — 연구 검색·탐험 가독성

- 젬 연구에 기존 검색 규칙(이름·효과·태그·능력치)을 재사용했다. 공격/보조 목록을
  전체 폭의 접기 영역으로 바꿔 한쪽을 닫아도 반쪽 빈 공간이 남지 않는다.
  내부 목록 스크롤을 제거하고 카드 수와 창 폭에 맞춰 열 수가 바뀐다.
- 연구 표시 함수는 기존 `skills-ui.js`로 이동했다. UI 갱신에서 공개하는 기존
  `window.getGemSearchText`와 공유 검색 컴포넌트를 사용하며 전역 함수는 추가하지 않았다.
  검색어·입력 포커스는 갱신 후 유지하고, 연구를 마치면 획득한 젬만 후보에서 빠진다.
- 실제 조작에서 공통 접기 복원이 검색의 자동 펼침을 덮어쓰는 오류를 발견했다.
  자체 저장 상태를 관리하는 연구 영역은 공통 복원에서 제외했다. 접은 상태에서 검색하면
  결과 영역이 열리고, 검색어를 지우면 원래 접기 상태가 돌아온다.
- 검색창의 `width:100%`에 padding이 더해져 6px 넘치는 오류를 발견해 해당 검색창에
  border-box를 적용했다. PC/모바일 두 테마에서 가로 넘침 검사를 통과했다.
- 연구 카드 본문·태그·범위와 비용 버튼을 읽기 쉽게 확대했다. 라이트모드에서 옅은 민트색으로
  묻히던 범위 설명은 테마 본문 보조 색상으로 바꿨다. 파문심판의 `light` 태그 번역 누락도 보완했다.
- CUA 직접 검증: 공격 목록 접기 → `동결` 검색 → 빙결 파열창/집중 광선 자동 노출.
  `묵직한 강타` 검색 후 연구하면 잔향 20→11, 공격 수집 5/61→6/61, 검색어 유지 및 후보 제외.
- 테스트 설정 중 진행도 점프로 발생한 새 콘텐츠 안내가 모바일 버튼을 가렸다.
  이미 안내를 본 후반 플레이어 상태로 준비해 연구 흐름을 검증했다. 또 `가속` 검색에서
  `시간 가속` 등까지 없어야 한다는 잘못된 검사를 정확한 보유 젬 제외 검사로 수정했다.
  이 두 테스트 설정 문제를 제품 수정으로 주장하지 않는다.
- 연구의 기존 소스 추출/문자열 UI 검사를 실제 브라우저 행동 검사로 대체했다.
  연구 4개(두 테마×PC/모바일), 기존 젬 조작 12개, 탐험 10개가 통과했다.
- 전체 탐험 → 도전과 원정 → 전직 시련을 직접 비교하고 세부 화면의 보상·조건·행동 글씨를
  확대하고 대비를 높였다. 첫 화면 배치와 전투/보상 규칙은 유지했다.

  갈림길 1/10·위험 +1·여왕 보류 보상 반영 및 6마리 웨이브 시작을 확인했다.
  시연용 고능력 장비이므로 이 결과로 난이도를 평가하지 않는다.
- 남은 구체적 사항: 벌집 선택지 설명이 한 줄 버튼에 몰려 있고 전투 배경이 원정의 장소성을

- 최종 표시 수정 후 연구 브라우저 4개와 전체 스모크 191/191 통과.
  첫 구조 검사는 기존 동적 공개 helper를 암묵 참조한 부분을 발견해 기존 소비자와 같이
  `window.getGemSearchText`를 명시했다. 최종 전체 runtime architecture/lint 재검사도 통과했다.

### 5차 수정 · 벌집 선택과 비용

- 이전 직접 플레이에서 발견한 꽃가루 미지불 보상을 재현했다. 새 갈림길의 재료 대가는
  보유량이 충분할 때만 후보로 나오며, 선택 직전에도 지급 전 보유량을 다시 확인한다.
  꽃가루 5개로 비용 6개 선택은 진행/보상 불변, 6개로 +10 보상 선택은 최종 10개다.
- 저장에서 제거되는 `penalty.apply` 함수와 키 기반 구현의 중복을 없앴다. 독벌침/벌꿀은
  각각 기존 25%/20% 소모 확률을 유지하고, 실제 발생한 소모만 원장에 기록한다.
- 기존 저장 또는 중간 소비로 세 갈래 모두 재료 부족이면 마지막 갈래의 대가만
  `군체 분노 +1`로 표시한다. 보상은 바꾸거나 다시 뽑지 않는다. 화면에 표시된 대가와
  클릭 시 대가가 달라지면 재확인을 요구하고, 미리보기 자체는 저장을 변경하지 않는다.
- 갈림길 카드를 지급 시점 / 보상 / 대가 / 보유량으로 분리하고 저장된 문구를 이스케이프했다.
  일반 장비 직접 화면에서 세 카드 오른쪽에 빈 열이 생기는 배치도 수정했다.
  모바일 캡처에서 보상 원장이 선택지를 아래로 밀고 하단 메뉴가 창을 가리는 것을 발견해,
  모바일 선택지를 우선 배치하고 하단 메뉴 영역을 피하도록 수정했다.
- 원정 포기는 공통 확인 창을 사용한다. 이미 받은 보상 유지, 미수령 웨이브/여왕 보상 소멸,
  열쇠 미반환을 알린다. 중복 클릭은 확인 창을 중복 생성하지 않고, 이전 원정의 확인은
  새 원정을 종료할 수 없다. 취소/확인 동작은 실제 브라우저에서 검사한다.
- 양봉업자 안내의 옛 재화명을 `형체 없는 이슬`/`황금률`로 수정했다.
  벌 이름의 장식 이모지가 전투 타깃 이름에서 깨져 보이는 것을 확인해 생성 시 제거했다.
- 직접 플레이: 테스트의 T14 선별 장비(생명력 4,817, 보호막 92)로 첫 웨이브를 통과했다.
  첫 보상 꽃가루 +9 → 비용 6/+7 선택 후 보유 10 → 비용 6/여왕 보류 선택 후 보유 4 확인.
  세 번째 웨이브까지 통과했고 네 번째는 군체 강화 +2/웨이브 꽃가루 +19를 선택했다.
  첫 웨이브는 1배속, 이후 일부는 테스트 4배속이다. 전체 소요 시간이나 다른 빌드의
  난이도가 검증되었다고 주장하지 않는다. 테스트 입장권 3개만 추가하고 전투 장비는 유지했다.
- 10갈래 진행/5갈래 후 저장 복원/여왕 단독 등장/보류 보상 지급/저널 해금/중복 지급 방지
  행동 회귀 검사를 추가했다. 이 검사는 웨이브 처치 상태를 직접 넘겨 진행 규칙을 검사하며,
  여왕 전투의 재미나 실제 처치 난이도 검증을 대체하지 않는다.
- 남은 발견: 벌집 전장이 성소 배경이며 벌 이름에 일반 몬스터 외형이 붙는다.
  추천 `생존력 부족`과 흡혈 빌드의 실제 생존 차이, 긴 원정의 보상 만족도도 더 비교해야 한다.
  전체 목표는 계속 미완료이며, 나머지 콘텐츠 범위를 줄이지 않는다.
- 추가 직접 플레이: 군체 강화 +2인 네 번째 웨이브도 통과해 보유 꽃가루 23개가 됐다.
  포기 취소 후 갈림길 4/10·여왕 보류 보상·재료 23 유지, 재확인 후 포기 시 액트 1 복귀 및
  입장권 잔여 2개를 확인했다. 테스트 배속은 1배로 복원했고 브라우저 오류 로그는 없었다.
- 최종 검증: 전체 스모크 191/191, 벌집 PC/모바일×두 테마 4개, 기존 특수 전투 브라우저 2개 통과.
  최종 벌집 검사는 모바일 세 선택지가 초기 화면 안에 있고 하단 메뉴에 가려지지 않는지,
  지도 카드의 오른쪽 빈 열이 없는지, 과거 원정의 확인 창이 새 원정을 종료하지 않는지도 확인했다.
  진행도를 점프한 테스트에서 액트 안내가 입장을 가린 것은 기존 장면을 본 상태로 준비해 수정했다.
  첫 구조 검사는 선택 함수의 복잡도 증가를 잡았고, 상태/비용 검증 경계를 분리한 뒤 최종
  runtime architecture/lint 래칫 검사가 통과했다. 검사 기준은 완화하지 않았다.

### 6차 점검 — 탐험 공간 배분·저널 전체 열람

- 직접 비교: 전체 탐험 → 도전과 원정 → 강대한 적. 콘텐츠가 두 개일 때 각 묶음이 전체 행을
  차지하면서 카드 오른쪽 절반이 비었다. PC는 탐험/주변 콘텐츠 묶음을 나란히 두고 각 카드가
  그 열을 채우게 변경했다. 모바일은 한 열로 이어진다. 콘텐츠가 많은 후반 화면도 직접 확인했다.
- 입장 가능한 보스가 없을 때 첫 준비 묶음을 기본으로 펼친다. 재료/진행 조건은 기존 카드의
  실제 조건을 표시한다. 나머지 묶음은 접힌 상태이며 사용자가 직접 접거나 펼친 선택을 우선한다.
  입장권을 얻으면 입장 가능 그룹으로 옮겨지고 보스는 중복 표시되지 않는다.
- 접기 버튼의 handler 문자열을 상태와 무관하게 유지해 기존 포커스 복원 경로를 재사용했다.
  처음 추가한 별도 복원 분기는 구조 검사에서 복잡도 증가로 실패해 제거했다.
- 저널 `나무꾼`은 실제로 혼돈 5층 클리어에서 획득한다(`combat.js`의 시뮬레이터 이벤트).
  기존 `혼돈 밖의 나무꾼 격파` 안내와 뿌리 보스로 향하는 링크를 혼돈 5층/혼돈 등반으로 수정했다.
  잘못된 안내를 읽는 브라우저 회귀 검사는 수정 전 실패했고 수정 후 PC/모바일에서 통과했다.
- 40종 모두를 획득한 상태에서 하나씩 열어 마지막 문단까지 이동하고 삽화 로딩, 가로 넘침,
  스크롤 후 닫기 버튼 가시성, 닫기 및 목록 포커스 복귀를 실제 브라우저로 검사했다.
  PC/모바일 모두 통과했고 저널/보너스 원장/패시브 포인트는 열람 전후 유지됐다.
  이는 전체 열람 검증이며 모든 기록을 실제 플레이로 얻었다는 뜻은 아니다.
- 첫 전체 열람 검사는 기록 ID만 넣고 보상 원장을 비운 잘못된 fixture였다. 배경 전투가
  액트 1을 클리어하면서 미지급 보너스를 정상 지급해 불변 검사가 실패했다. 실제 획득 함수로
  보상까지 준비한 상태로 고쳤다. 이 실패를 저널 제품 버그라고 주장하지 않는다.
- CUA 직접 조작: 나무꾼 본문 읽기/닫기, 후반 4개 카드 배치, 일반 T14의 2개 카드 배치 확인.
  액트 사냥 중 폭풍 군단장 입장권 1개를 실제 획득했고 보스 카드가 입장 가능으로 바뀌었다.
  그 입장권으로 T13 볼타에 도전했다. 전투 중 생명력 4,817 유지, 보호막은 소모/회복되며,
  플레이어 감전/보스 출혈 상태 표시와 피해가 보였다. 전투 후 혼돈 심화 21 자동 복귀,
  볼타 `격파 완료` 및 입장권 1→0을 실제 보스 목록에서 확인했다. 이 한 빌드로 전체 밸런스를 단정하지 않는다.
- 검증: 탐험 브라우저 12개 통과, 포커스 단순화 후 관련 4개 재통과. 저널 대표/나무꾼 4개와
  40종 열람 2개 통과. 최종 전체 스모크 191/191 및 runtime architecture/lint 래칫 검사 통과.
- 남은 범위: 표의 미점검 콘텐츠 전체, 기록별 실제 획득 및 루프 복원 경로, 전투 난이도/보상 체감.
  벌집 전용 배경과 벌 외형 자산은 생성 시안만 있으며 실제 게임에 아직 연결하지 않았다.
  추가 관찰: 루프 가능한 상태로 복귀한 혼돈 심화 전투에 진행률 `진행불가`가 표시된다.
  전투는 계속되고 루프 버튼도 보이므로 표시 의미와 실제 진행 차단 경계를 다음에 대조한다.
  전체 게임 90점 달성은 미완료/미검증이다.

### 7차 점검 — 보스 준비 정보·원정 조작 안정성

- 직접 전체 탐험 → 도전과 원정 → 강대한 적을 다시 확인했다. 첫 화면의 지역 구별은 좋지만
  하위 카드에서 노릴 보상과 입장권 획득처를 알기 어려웠다. 이 단계의 탐험 UI 평가는 78점이며,
  게임 전체의 평가나 자동 검사로 산정한 점수가 아니다.
- 군주의 핵 기능이 잠긴 상태에서 보스 보상 행 자체가 사라졌다. 실제 토벌 로직에는 고유 장비
  확률 보상도 있으므로, 뿌리 보스 카드에 이를 항상 안내하고 군주의 핵은 기존 해금 조건을 따른다.
  확정 지급으로 오해하지 않도록 확률 획득을 명시했다. 드랍·해금·보상 수치는 바꾸지 않았다.
- 기존 ORB_DB에 뿌리 보스 열쇠의 획득처 설명을 추가하고 카드에 표시했다. 일반 뿌리 열쇠는
  혼돈 진입 이후 정예/보스(시련·입장권 보스 제외), 케르베로스는 루프 6부터 혼돈 10층 이상 보스다.
  loot.js의 실제 드랍 조건과 대조했다. 잠긴 성장 재화 이름을 노출하지 않는다.
- 라이트 모드 카드 캡처에서 배경과 글자 대비가 무너지는 문제를 확인했다. 카드·보상·조건·버튼을
  공통 테마 변수로 변경했다. PC/모바일의 두 테마 캡처에서 최종 가독성과 가로 넘침을 확인했다.
- 운석/대균열은 갱신 때 innerHTML을 무조건 교체했고 벌집도 수치가 바뀌면 버튼을 교체했다.
  sideEncounterUi가 본문과 행동 행을 구분해 갱신하도록 바꿨다. 수치 갱신 시 행동 버튼의 실제
  DOM/포커스를 유지하며, 입장 → 전투 보기 같은 행동 전환만 새 버튼을 만든다. 본문 공개/접기는
  기존 disclosure 상태 보존 함수를 재사용한다. 저장 shape/로드 순서 변경은 없다.
- 브라우저에서 실제 캐릭터 레벨을 올려 EHP 추정치가 바뀌는 동안에도 같은 원정 버튼인지 확인했다.
  충전 전 비활성/충전 후 활성/클릭 시 입장과 충전 소모를 PC/모바일에서 검사했다.
- '진행불가'는 생존 적 20마리 이상일 때 진행을 멈추는 기존 군중 규칙이었다. HUD를
  '적 정리 중 · 현재 %'로 바꾸고, 20→19마리에서 진행도 표시로 복귀하며 누적 %를 잃지 않는지
  검사했다. 루프 조건이나 군중 정지 규칙은 변경하지 않았다.
- 초기 검사 fixture 문제도 분리했다. 시연 페이지 자체의 별도 전투 타이머 때문에 정지 조건이
  깨져 실제 게임 게스트 진입을 쓰도록 수정했다. 진행도 점프로 늦게 나타나는 운석 안내를
  이미 본 상태로 준비했다. 이를 제품 버그라고 기록하지 않는다.
- 기존 원정 통합 검사는 접힌 원정 목록을 펼치지 않고 버튼을 찾으며, 원정 포기 확인도 생략했다.
  현재 공개 조작 순서에 맞게 고쳤고 벌집 입장/포기 → 대균열 생존/보스 → 운석 입장 흐름 2개 통과.
  신규 준비/버튼/진행률 6개, 벌집 두 테마 4개 통과. 최종 전체 스모크 191/191(12.5초),
  runtime architecture/lint 래칫 검사 통과. 최종 JS 이후 수정은 CSS·테스트·문서다.
- 실제 조작으로 일반 T14 캐릭터의 보스 안내를 확인하고 혼돈 10층으로 이동했다. 현재 테스트는
  1배속·분리된 저장이다. 운석 준비 화면 충전 0%도 확인했으며, 이번 단계에서 자연 충전 완료와
  운석 전체 전투를 끝냈다고 주장하지 않는다. 다음은 특수 지역 전투/실패/보상과 미점검 콘텐츠다.
- 전체 목표는 계속 미완료다. 저널 실제 획득·저장 복원, 각 콘텐츠의 플레이 흐름 및 밸런스/보상
  체감, 벌집 배경·외형 연결 등 기존 미검증 범위를 유지한다. 작업 범위의 diff 공백 검사는 통과했고,
  전체 작업트리에는 이번 수정과 무관한 js/skills-ui.js의 기존 공백 경고가 남아 있다.

### 8차 점검 — 운석 실전·대균열 전투/안내·HUD 가림

- 직전 평가 턴은 실제 탐험 화면을 다시 보고 하위 안내/가독성/공간 문제를 확인한 진행이다.
  이번 턴은 이전 테스트 프로세스를 재조회한 뒤 수정·실전 확인을 이어갔다. 전체 목표는 미완료다.
- 일반 T14 캐릭터로 혼돈 10에서 운석 자연 충전, 입장, 36%/76% 접근, 검은 별의 심장 전투,
  희귀 장갑 정산을 직접 확인했다. 별쐐기 성장 기능이 잠긴 캐릭터여서 장비만 지급된 경로다.
  수동 입장은 출발 지역 대신 최고 심화로 복귀하던 오류가 있어 일반 액트/혼돈 출발지를 보존했다.
  입장권 특수 지역에서의 무료 재입장을 만들지 않도록 숫자 지역만 기본 복귀지로 사용한다.
  자동 입장이 명시적으로 전달하는 복귀지는 유지한다. 저장 필드/형식은 바꾸지 않았다.
- 운석 보스의 숫자 전용 보정에 이름이 없어 특성에 undefined가 붙었다. 존재하는 특성명만 합친다.
  운석/대균열/벌집/시련 실제 적 생성 회귀로 확인했다. 공격력·생명력 수치는 그대로다.
  핵과 싸우는 동안 100% 대신 '운석 핵 파괴 · 처치 중'을 표시하고, 일반 지역으로 복귀하면
  기본 진행률 표시로 돌아온다. 준비 화면도 실제 해금 상태에 맞춰 장비 또는 별쐐기 보상을 안내한다.

### 9차 점검 — 생존 안내의 한계·원정 결과 보존·미궁 진입

- 직전 턴은 전체 탐험 → 도전과 원정 → 전직 시련을 실제로 열어 가독성/공간/상단 반복을 확인한 진행이다.
  이번에도 전체 콘텐츠 목표를 유지하며 우선 실전에서 드러난 안내 오류와 미점검 미궁을 처리했다.
- EHP는 직접 타격 기준인데 일부 지도는 '생존력', 지하계만 '직격 생존'으로 표시했다.
  공통 준비도를 '직격 생존'으로 통일하고 키보드 포커스/터치 툴팁에 중독·출혈과 장기전 회복은
  포함하지 않는다고 표시했다. 데미지/방어/회복 계산이나 적 난이도는 바꾸지 않았다.
- 대균열 완료/실패의 최근 결과를 준비 패널에 남긴다. 생존 구간 처치 수와 군주 격파 여부,
  실제 awardCurrency 반환량을 표시한다. rewardVoidChisel은 입장 시 null, 정산 시 실제 정수이며
  다음 입장/루프 초기화까지 유지한다. 과거 저장의 누락·잘못된 값은 null(수량 불명)로 복원하고
  '정산 완료'만 표시한다. 화면 열람은 보상 지급을 다시 호출하지 않는다.
- 주얼 해금 전에는 공허의 끌을 지급하지 않는 기존 경계도 확인했다. 준비 화면/전투 HUD가
  그때도 예상 공허의 끌을 표시하던 부분을 고쳤다. 해금 전엔 제작 재화의 선행 조건을 안내하며,
  실제 지급 0은 '지급된 제작 재화 없음'으로 표시한다. 해금/드랍 규칙 자체는 유지한다.
- 미궁 카드 전체에 입장 클릭을 달고 내부 전투력 영역에는 클릭 중단을 달아, 카드 중앙을 누르면
  층 선택 대신 툴팁이 열렸다. 실제 CUA 클릭으로 확인했다. 작은 카드와 설명이 지도 그리드의
  서로 다른 칸에 들어가 공간도 어색했다. 전체 폭의 기존 원정 패널을 재사용해 현재 층/열린 층/
  화석 안내를 나눴고, 명시적인 'N층 입장'과 '층 선택'을 제공한다. 층이 하나면 불필요한 선택창 없이 입장한다.
- 기존 미궁 innerHTML 무조건 교체도 제거했다. 이미 원정에 쓰는 renderPanel이 수치 갱신 시
  행동 버튼/포커스를 유지한다. 실제 브라우저에서 레벨 변경 갱신 중 같은 버튼인지, 층 선택 취소가
  지역을 바꾸지 않는지, 입장 시 실제 지역과 층이 맞는지, 해금 전 화석 보유량을 숨기는지 확인했다.
- T15 제작 캐릭터의 1배속 실제 전투: 미궁 1층 입장 → Lv.25 일반 적 → Lv.27 보스(143,877 HP)
  격파 → '미궁 1층 돌파! [화석 없음]' → 해금 최고 2층을 확인했다. 현재 사냥 설정은 반복이므로
  1층에 남았으며, 층 선택에서 실제 열린 2층으로 이동했다. 이후 2층 돌파 로그도 확인했다.
  화석 제작이 잠긴 캐릭터라 화석 파밍/확률/고층 난이도를 검증했다고 주장하지 않는다.
- 신규 스모크의 첫 지급량 0은 제작 기능이 잠긴 fixture 때문이었다. 해금 상태를 준비한
  121처치/14개 지급 경로와 잠긴 0개 경로를 분리했다. 첫 툴팁 테스트는 잘못된 시련 탭 ID와
  잠긴 시련 fixture를 고쳤다. 초기 결과 캡처는 모바일 로그 토스트가 덮어, 큐 종료 후 다시 캡처했다.
- 검사: 관련 브라우저 26개 통과, 최종 결과 캡처 2개 재통과. PC·모바일/두 테마에서 미궁과
  원정 결과를 시각 확인했다. 전체 스모크 191/191(11.2초) 통과. 기존 EHP 출력 검사는 새 문구로
  갱신했고, 숨겨진 우주계 상세창의 소스 문자열만 고정하던 검사는 제거했다. 공통 준비도는 실제
  포커스·터치 툴팁과 기존 계산/렌더링 검사로 확인한다. 관련 diff 공백 검사 통과.
- 첫 구조 검사는 새 결과 함수 복잡도와 거대 저장 함수 1줄 증가를 지적했다. 중복된 내부 수량 검사를
  저장 경계로 한정하고 공허 저장 정규화를 해당 경계 함수에 모아 수정했다. 최종 runtime architecture/lint
  래칫 검사는 통과했다. 해당 프로세스는 종료 코드 0으로 완료했으며 실행 중인 검사는 없다.
- 마지막 직접 검증에서는 미궁 2층에서 대균열에 입장해 109처치 후 군주를 격파했다. 미궁 2층으로
  복귀했고 준비 패널에 '군주 격파 / 생존 구간 109처치 / 지급된 제작 재화 없음'이 남았다.
  주얼이 잠긴 이 실제 세팅에서 예상치가 아닌 지급 결과를 표시한 것을 확인했다.
- 아직 남음: 상단 중복/작은 글씨/공간 활용 전체 개선, 미궁 전리품·고층·저널 10층 획득, 시간의 균열,
  표의 다른 미점검 콘텐츠, 대균열/벌집 전용 아트와 전투 체감. 전체 90점 달성은 여전히 미완료/미검증이다.

### 10차 점검 — 시간 균열 제작 흐름·군락지 전투 정지·상세 가독성

- 직전 평가는 실제 전체 탐험/도전과 원정/전직 시련을 열어 상단과 작은 본문 문제를 확인한 진행이다.
  이번에는 앞선 시간 균열 작업의 실제 상태와 실행 중 검사 핸들을 재확인하고 군락지 실전을 이어갔다.
  아래 검증은 전체 콘텐츠 표를 대체하지 않는다. 게임 전체 90점 목표는 미완료다.
- 시간 균열을 시간압, 과거, 제단, 미래로 구분하고 기존 renderPanel을 단계별로 재사용한다.
  별도 장비 창을 찾아야 하던 제단에 장비 선택기를 연결했다. 최종 투입과 후보 목록이 같은 자격
  검사(getTimeAltarItemIssue)를 사용하며, 타락/융합/봉인/성장/전당 복제 및 반대 부위 장비를 제외한다.
  미래 입장은 두 재료가 맞아야 가능하며 전투 실패 때 제단을 유지한다. 확률·옵션 손실 수·회수 경로도 표시한다.
- 회수한 재료가 자동 장착되어 인벤토리에서 사라지는 현상을 브라우저에서 확인했다. 회수/융합 산출물은
  기존 addItemToInventory에 skipAutoEquip을 전달해 인벤토리로 반환한다. 일반 드랍의 자동 장착은 유지한다.
  회수/융합 검사에 자동 장착 ON을 포함했다. 잘못된 옛 재화 이름은 황금률·잿불가지·축복의 꽃잎으로 고쳤다.
- 저장 분리 화면에서 과거의 실제 일반전/지배자 격파, 첫 계약+같은 부위 희귀 장비 투입, 미래 입장과
  실제 불안정 융합 산출물을 확인했다. 산출물 툴팁에 희귀 장비 기억과 이전 옵션이 표시됐다.
  강화된 진행 확인용 장비이므로 시간압 난이도/정상 빌드 밸런스의 증거로 사용하지 않는다.
- 군락지 준비 화면은 이전 원정 웨이브/난이도를 사용해 다음 입장과 달랐다. 대기 상태는 다음 입장의
  현재 루프 심화·1웨이브, 진행 중은 지불한 입장 난이도를 고정한다. 완료 수는 다음 웨이브 번호-1이다.
  명시적인 입장 때 combatHalted를 해제하고 중요 저장을 예약해 사냥 정지 설정 때문에 멈추지 않게 했다.
- 실제 군락지에서 3/12 처치 후 적의 공격만 계속되고 플레이어가 접근하지 않았다. 전용 틱이 공통
  updatePlayerGridEngagement/집중 유지/연속 타격/소환수 처리를 건너뛰었다. 동시에 가상 거리 colonyDist가
  적의 실제 사거리를 무시하고 모든 거리에서 공격하게 했다. 군락지는 이제 공통 전투를 사용하고
  일반 지역 진행만 멈춘다. 옛 가상 거리 생성·판정·상태이상 제한은 제거했다. 적 HP/공격 배율은 유지한다.
  적 생성 함수 spawnColonyWave는 UI에서 전투 소유 모듈로 옮겼다. 스크립트 순서/저장 shape는 유지한다.
- 새 회귀는 사거리 밖 적에게 실제 coreLoop를 진행해 접근→처치→웨이브 보상 1회→다음 무리 출현을 확인한다.
  초기 fixture의 미초기화 gridPlayer와 잘못 쓴 required 필드는 실제 ensureCombatGridRuntime/requiredKills로 고쳤다.
  과거 colonyDist가 남은 적도 격자 전투를 따르는 입력을 포함한다. 전투력 helper 이름 개수만 세던
  스모크 assertion은 제거하고 실제 준비 화면의 화력/직격 생존 표시와 기존 계산 검사로 보장한다.

- 마지막 공격의 주 속성을 fatalElement로 별도 보존한다. 기존 primaryElement는 최근3초 누적 피해의 주 속성으로 유지한다. 사망창은 마지막 피해의 출처/속성과 최근 주요 피해를 구분한다. 저장에 없거나 손상된 fatalElement는 null로 복원하고 ‘속성 미기록’으로 표시한다. 이전 기록을 물리 피해로 추정하지 않는다. 복합 공격의 fatalElement는 마지막 공격 중 주 피해 속성이며, 상태이상 사망은 기존 호출부의 기타/상태이상 분류를 유지한다.
- Node 회귀에서 번개90 뒤 물리10으로 사망 시 주요 번개/마지막 물리, 출처, 실제 경험치 감소, JSON 저장 복원, 누락·잘못된 키·객체·숫자 입력, 원본 저장 불변을 검증했다. 재열람으로 경험치가 다시 감소하지 않는다. 전투 피해량·난이도·보상·로드 순서는 유지했다.
- 사망창을 native dialog로 바꿨다. 확인 버튼에 포커스를 두고 뒤쪽 게임 조작을 막으며 Escape/확인으로 닫는다. native Tab이 브라우저 영역으로 이동할 때 document.body가 활성화되는 것은 허용하되, 뒤쪽 게임 버튼으로의 포커스 이동은 차단됨을 검사한다. Node DOM shim에는 실제 플랫폼 경계인 showModal/close를 추가했다.
- 모바일 카드 폭에 border-box를 적용해 좌우 여백을 확보했다. 라이트 테마의 몬스터별 수치는 짙은 글씨로 바꾸고 속성 막대 색은 유지했다. 높이390 화면에서 목록이59.25px로 눌리는 실패를 재현했으며, 짧은 화면에서는 사망창 전체를 스크롤해 목록과 확인에 접근하도록 수정했다.
