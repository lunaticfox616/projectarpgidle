# 모바일 화면 재설계 진행 기록

목표는 PC 화면의 축소가 아니라 탭별 핵심 행동을 터치로 수행하기 쉬운 구조다.
금색 판타지 테마, 기존 해금 조건, 저장 데이터와 전투 규칙은 유지한다.
S24+ Android 16이 대상이며, 현재 검증은 Chromium 모바일 에뮬레이션이다.
실기기 발열·배터리 효과는 아직 측정하지 않았다.

## 기준 측정

2026-09-07, 412×915 CSS px, 합성 루프 100 상태에서 기본 화면 16개를 확인했다.
이 상태는 실제 플레이어 저장이 아니며 일부 특수 콘텐츠는 별도 상태 구성이 필요하다.
기존 하단 메뉴는 15개를 가로로 스크롤했고, 공격 젬 목록 화면은 10,840px였다.
UI 직접 갱신은 일반 화면 약 3–5ms, 지도 약 15–17ms였다.
이는 PC에서 측정한 수치이며 실제 휴대폰 실행 시간으로 해석하지 않는다.
측정 스크립트와 캡처는 로컬 `artifacts/mobile-audit-*`에 있다.

## 현재 반영

- 하단은 전투 + 바로가기 3개 + 전체 메뉴. 전체 메뉴는 기존 콘텐츠 분류별로 정렬한다.
- 모바일 전체 메뉴는 열기/닫기 초점을 관리하고 Tab 순환과 Enter·Space 선택을 지원한다.
  메뉴 갱신 시 열린 상태의 접근성 속성과 선택 초점을 유지한다. 확인 창은 우선 처리하며
  PC로 전환하면 모바일 전용 버튼 역할·키보드 처리를 해제한다.
- 설정에서 모바일 바로가기를 선택할 수 있고 PC 메뉴 설정과 독립적으로 저장한다.
- 가지치기는 독립 탭을 유지한다. 모바일 전체 메뉴에 넣는 것은 기타 콘텐츠에 병합하는 것과 다르다.
- 모바일 가지치기는 현재 가지의 성장·부담과 선행/다음 가지 이동을 한 화면에 배치한다.
  전체 가지 선택도 유지하며 PC의 나무·연결선·스크롤은 변경하지 않는다. 모바일에서는 큰 나무의
  29개 노드와 SVG를 생성하지 않는다. 성장·부담 가지치기·연쇄 반환·비용을 실제 브라우저에서 확인했다.
- 모바일 공격·보조 젬은 검색 및 장착 필터 적용 후 6개씩 카드를 생성한다.
  봉인된 젬도 검색 대상이다. 검색 조건 변경 시 첫 페이지로 돌아가며 PC는 전체 목록을 유지한다.
- 모바일 채팅은 하단 메뉴를 덮는 모달 대신 콘텐츠 영역을 사용한다.
- 전투 HUD와 캐릭터 상세 능력치 표시를 분리했다. 닫힌 캐릭터창의 능력치는 전투 틱마다
  작성하지 않고, 열었을 때 최신 값으로 갱신한다. 공용 텍스트 갱신은 같은 값이면 DOM을 유지한다.
- 전문화는 모바일에서 전문가 선택과 투자 분기를 각각 선택한다. 한 분기의 노드만 생성하고
  호버 없이 효과·조건·비용을 보여준다. 투자·반환·호의 선택은 기존 규칙과 확인 창을 재사용한다.
  PC는 전체 허브 배치를 유지하며 잠긴 노드 트리의 Lv.16 안내도 유지한다.
- 모바일 재능은 장착 슬롯을 먼저 보여주고, 이름·재능·직업 검색과 분류 뒤 6장씩 표시한다.
  카드 자체는 장착을 실행하지 않고 명시적인 버튼을 사용한다. 개화 현황은 별도로 펼친다.
  표시 코드는 `talent-ui.js`와 `talent-mobile-ui.js`, 효과·슬롯 규칙은 기존 `talent-cards.js`가 소유한다.
  초기화 시 데이터·규칙 뒤 UI를 로드하며 저장 shape와 장착 규칙은 변경하지 않는다.
- 캐릭터의 공격·방어/회복·기본/특수 분류를 모바일 상단에서 바로 선택한다.
  키보드 방향키·Home/End를 지원하며 PC의 기존 펼침 상태는 화면 폭 전환 후 복원한다.
- 모바일 루프 성장에서는 원환 패시브와 심화 성장을 전환한다. 원환 노드는 이름·효과·조건이
  보이는 투자 카드로 표시하며 PC 원형 트리는 유지한다. 이정표는 기존 해금 화면에서 확인한다.
- 보조 젬 해금 후 모바일에서 공격·보조 목록을 직접 전환한다. 잠겨 있으면 전환 메뉴를
  표시하지 않는다. 현재 장착 요약은 유지하고 중복 제목을 줄였다.
- 플라스크·전문화·거래소는 실제 표시 중인 패널만 갱신한다. 거래소 자연 갱신은
  숨겨진 동안에도 유지하며, 장비 하위 탭을 열면 정적 UI 갱신을 요청한다.
- 모바일 지도는 기존 탐험·별도 지역 버튼 목록을 목적지 선택 하나로 투영한다.
  버튼의 실제 해금 상태·이동 핸들러를 재사용한다. 메뉴 선택은 사냥 지역을 변경하지 않는다.
  PC의 기존 지역 메뉴는 유지한다.
- 모바일 로그 알림은 한 개씩 표시하고 공통 테마를 사용한다. 알림 큐의 나머지 항목은 유지한다.
- 모바일 전투는 상태 정보를 전장 위에 배치한다. 생명력 14px, 플라스크 터치 영역 44px를
  확보했다. 가로 화면에서는 상태·로그와 전장을 좌우로 배치한다.
- 모바일 로그는 기본 접힘이며 펼치면 전체 기록을 스크롤할 수 있다.
  `settings.mobileCombatLogExpanded`는 PC의 `combatLogCollapsed`와 별도 저장하며,
  이전 저장에 값이 없거나 잘못된 타입이면 접힌 상태로 시작한다.

### 현재까지의 성능 비교

동일한 합성 상태의 스킬 화면 높이는 10,840px에서 1,908px로 줄었다.
이는 공격 젬 페이지화 결과이며 모든 보조 젬 보유 상태는 별도 브라우저 검사에서 확인했다.
화면 높이 감소 자체를 사용성 검증 완료로 보지 않는다.

전투 화면에서 직접 정적 UI 갱신을 100회 실행한 결과:

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 중앙값 | 3.0ms | 2.4ms |
| 95백분위 | 4.1ms | 3.1ms |
| 숨겨진 거래소 DOM 변경 | 1,800건 | 0건 |
| 숨겨진 전문화 하위 탭·트리 DOM 변경 | 200건 | 0건 |

측정은 `artifacts/mobile-render-profile.cjs`, 결과는 `mobile-render-before.json`과
`mobile-render-after.json`이다. 메인 스레드를 연속 호출한 PC 진단이며 실제 전투 프레임이나
모바일 발열·배터리 측정을 대신하지 않는다. 플라스크는 기존에도 변경 감지가 있어 이 상태의
DOM 변경은 0건이었다. 새 방식은 숨겨진 플라스크의 카드 계산도 건너뛴다.
`visible-panels.spec.js`는 숨겨진 DOM 불변, 자연 상품 갱신, 실제 패널 진입을 검사한다.

## 남은 범위와 완료 증거

재능 120장 보유 합성 상태(412×915)에서 카드 DOM은 120→6개, 화면 높이는
22,188→1,991px, 직접 목록 생성 30회 중앙값은 1.6→0.4ms, 95백분위는 2.3→0.6ms였다.
`artifacts/audit-talent.cjs`와 `talent-before.json`/`talent-final.json` 기준이며 실기기 측정은 아니다.
PC 전체 카드 유지, 모바일 전체 검색·페이지·분류·장착/해제·빈 목록을 브라우저에서 검사했다.
재능 변경 검증: `npm test` 175/175, `npm run check:architecture` 통과,
`npx playwright test tests/browser/mobile-talent.spec.js` PC·모바일 2개 통과.
검색 입력의 따옴표 처리, 미보유 상태의 잠긴 슬롯, PC 장착 후 화면 갱신을 포함한다.

완료 판단은 탭 진입 성공이나 가로 넘침 부재만으로 하지 않는다. 대표 보유 상태에서
선택→실행→결과를 확인하고, PC 동작·진행 조건·저장 호환성도 유지되는지 검증한다.
전체 스모크와 구조 검사, 모바일 및 PC 브라우저 검사는 최종 변경 상태에서 실행한다.
전체 구조 검토 범위와 호출 경로는 `structure-review.md`에서 별도로 추적한다.

아르카나는 모바일에서 빈 슬롯 16개를 먼저 보여주던 흐름을 미사용 카드 검색→카드 선택→
바로 아래 위치 선택·장비 증폭 미리보기→명시적 배치로 변경했다. 배치 중인 카드는 별도 목록에서
해제할 수 있고, 해제/봉인 해제 후에는 해당 카드가 있는 페이지를 열어 보여준다. 동일 카드의

### 코어 큐브 입력과 대기 렌더링

큐브 회전은 Pointer Events와 포인터 캡처를 사용한다. 터치·마우스 드래그를 함께 지원하며
드래그 종료·취소·캡처 해제 시 입력 상태를 정리한다. 회전은 장착 재화를 소비하거나 선택 면을
바꾸지 않는다. 별도 면 버튼과 번호 선택으로 각인하는 기존 흐름은 유지한다.
터치가 주 입력인 환경과 동작 줄이기 설정에서는 자동 회전을 중단하고 직접 회전·상태 갱신 때만
그린다. 일반 PC의 자동 회전은 유지한다. 합성 모바일 상태의 동일한 2초 측정에서 큐브 캔버스
다시 그리기는 120회에서 0회로 감소했다. 실기기 배터리·발열 개선량을 의미하지 않는다.
`core-cube-pointer.spec.js`는 PC·모바일에서 정지 화면, 회전 결과, 터치 취소, 재화와 선택 면
보존, 이후 면 선택·동력원 각인을 확인한다.
모바일은 기존 섹션 탐색기를 재사용해 동력원 장착/발현 결과/재료·조합으로 작업을 나눈다.
선택 작업은 재화·면 상태가 갱신되어도 유지된다. 6면은 3열, 번호 목록은 5열이며 최대 45개를
내부 스크롤 없이 페이지에서 탐색한다. 결과는 캔버스 아래에 옵션 4줄을 모두 표시한다.
PC는 기존 동시 표시를 유지한다. DOM의 섹션과 캔버스는 정적 HTML이 소유하고 상태별 내용만
갱신하므로 각인할 때 캔버스와 입력 리스너를 재생성하지 않는다. ResizeObserver로 숨겨진 결과
탭을 열거나 창 폭을 바꿀 때 캔버스 크기를 맞춘다. 브라우저 검사는 빈 목록, 45번 장착, 재료
변경 후 작업 유지, 실제 완성 결과, 옵션 비겹침, 키보드 탐색, PC 전환 후 재진입과 캔버스 유지를
검증한다. 기존 종합 검사의 재능 영역은 PC 전용 개화 표와 모바일 장착 표시를 구분했으며,
모바일 검색·장착은 `mobile-talent.spec.js`에서 별도로 검증한다. 큐브 도메인 파일에 남아 있는
DOM 조립의 계층 분리와 반복 크기 계산 절감은 후속 구조 개선 범위다.

### 생장판 작업 탐색

모바일은 배치판/보관함/제작대를 기존 섹션 탐색기로 분리한다. 보관함에서 배치 버튼을 누르면
선택한 조각을 유지한 채 판으로, 카드 본문을 누르면 해당 제작대로 이동한다. 배치판에는 보관함
바로가기를 두고 모바일 빠른 배치함의 중복 카드를 생성하지 않는다. PC는 판·빠른 배치함,
제작대, 보관함의 기존 순서를 유지한다. 터치 입력은 카드 드래그보다 목록 스크롤을 우선하며
배치 버튼과 칸 선택을 사용한다. 마우스 드래그는 유지한다.
40개 합성 상태에서 탭 전체 DOM은 682→531개, 배치판 화면 높이는 5,449→842px였다.
높이는 작업 분리 결과이며 전체 콘텐츠 제거량이나 실행 속도 측정이 아니다. 보관함의 후속 검색·
페이지 분할은 아래에 기록했다. 배치 확정 전 미리보기, 제작대 비용·효과 탐색과
닫힌 영역의 지연 렌더링은 후속 범위다.
`growth-workspaces.spec.js`는 터치 이동 중 배치·선택 보존, 목록→판 배치, 제작대 전환,
일반→마법 제작과 정수 1개 차감, 다른 아이템 보존을 PC/모바일에서 확인한다. 종합 후반 UI
검사도 양쪽에서 통과했다. 명시적으로 제작대를 열 때 기존 접힘 상태가 요청을 덮어쓰지 않도록
렌더 옵션으로 의도를 전달한다. 새 `growth-workspace-ui.js`는 탐색만 소유하며 게임 저장은
변경하지 않는다. 테스트 런타임도 실제 HTML의 스크립트 순서에 맞춰 로드한다.

생장 보관함은 이름·종류·형태·옵션·수치로 전체 목록을 검색한 뒤 모바일에서 6개씩 표시한다.
주얼·부적과 동일한 목록 페이지 모듈을 사용하며 검색·분류 변경 시 처음 페이지로 돌아가고,
수량 감소 시 마지막 유효 페이지로 보정한다. PC는 전체 검색 결과를 유지한다. 분류·정렬·
자동해체는 모바일에서 접기 영역으로 두고 열림 상태를 갱신 중 유지한다. 기존 40개 합성 상태에서
카드 40→6개, 생장 탭 DOM 531→240개였다. 검색 입력을 재생성하지 않아 입력 중 갱신에 대응한다.
`growth-library.spec.js`는 다른 페이지 잠금, 마지막 아이템 검색·배치·내리기·해체, 옵션 수치 검색,
분류 변경, 페이지 경계, 결과 없음, 빈 보관함을 PC/모바일에서 검증한다. 주얼·부적 목록 검사도
함께 통과했다. 공용 검색 상태와 검색 UI 조립은 `inventory-search-ui.js`로 옮겨 큰 화면 갱신 함수
안에 중첩된 초기화 순서 의존을 제거했으며 기존 헬퍼 재노출 목록에서는 제거했다.
검색어·페이지는 보관함 전용 렌더 키로 분리했다. 검색·페이지 이동 시 보관함만 갱신하고,
아이템·배치·제작 재화가 바뀌면 기존 게임 상태 지문으로 판과 제작대도 갱신한다. 분류 기본값은
지문을 만들기 전에 기존 필터 정규화 함수를 거쳐 첫 검색에서 추가 렌더가 발생하지 않도록 했다.
40개 합성 상태에서 검색 10회 중 판·제작대 DOM 재생성은 20→0회였다. 국소 측정 시간은 약
28.4→4.8ms였으나 생성 옵션의 난수와 측정 변동을 포함하는 참고 수치이며 실기기 성능 수치는
아니다. `growth-library.spec.js`에서 검색·페이지 이동 중 판과 제작대 유지, 실제 배치 후 화면
갱신을 확인하며 제작 갱신은 `growth-workspaces.spec.js`로 확인한다. 보관함 분류의 변수명만
검사하던 스모크 항목은 실제 분류 결과·페이지 보정 브라우저 검사로 대체했다.

생장판 제작은 일반 제작 재화를 임시 주입·복원하는 대신 실제 생장 정수를 직접 차감한다.
레시피는 data/growth-items.js, 결제 검증은 crafting-payment.js가 소유한다.
최근 제작 결과와 반복 버튼은 사용한 재화·비용을 유지하고 대상 변경·재화 부족 시 거절한다.
일반 제작과 포자 비용 규칙은 유지하며 저장 shape는 변경하지 않는다.
재화의 동시 변경 보존, 반복 제작, 부족한 비용, 대상 변경을 회귀 검사로 고정했다.
PC/모바일 생장판 제작 및 일반 장비 반복 제작 브라우저 검사, 전체 스모크 175/175,
architecture/lint ratchet을 통과했다. 실기기 발열·배터리 검증은 포함하지 않는다.

장비 내부 메뉴는 모바일에서 3열로 펼쳐 거래소·장비 전당이 가로 스크롤 밖에 숨지 않게 했다.
412px 화면에서 메뉴의 표시 너비 378px 대비 콘텐츠 584px였던 것을 378px로 맞췄다.
해금 조건과 PC 배치는 유지한다. equipment-navigation.spec.js에서 360/412/768px의
버튼 가림·44px 터치 높이와 PC/모바일 거래소·전당·제작실·장비 전환을 확인했다.
이 변경은 CSS 및 자산 캐시 키만 변경하며 런타임 JS 구조 검사는 다시 실행하지 않는다.

화석 제작대·혼돈 주입기는 작업 영역 상단에서 기존 장착 장비/인벤토리 선택기를 열 수 있다.
모바일 검색·페이지 기능을 재사용하며 선택 후 현재 제작 탭을 유지한다. 전체 목록과 생장 대상은
접기 영역으로 제공하고 닫힌 상태에서는 렌더링하지 않는다. 기존 제작실의 지연 렌더 조건을
세 제작 탭의 실제 details 상태를 확인하도록 확장했다. PC에서도 전체 목록은 직접 열 수 있다.
화석 버튼은 모바일에서 2열로 넓히고 빈 선택 영역의 불필요한 높이를 줄였다.
craft-lazy-lists.spec.js에서 두 제작 탭의 대상 선택·탭 유지, 닫힌 목록, 열었을 때 최신 목록을
PC/모바일에서 확인했다. 화석 효과 설명과 정제·복원·아이템 재련을 목적별로 분리하는 작업,
혼돈 주입 옵션의 비교·교체 흐름은 후속 범위다. 제작 규칙과 저장 구조는 바꾸지 않았다.

혼돈 주입 옵션은 즉시 소비하는 대신 공용 확인 창에서 현재 효과·새 수치 범위·총비용을
비교한 뒤 확정한다. 교체 비용의 마름병 포자도 기존 도메인 비용 함수로 표시한다.
chaos-infuser-ui.js는 비교 시점의 대상·기존 주입만 보존하고, 확정 시 변경되었으면 거절한다.
잔액·해금·장비 유효성은 실제 주입 함수가 최종 검증한다. 취소는 재화와 옵션을 변경하지 않는다.
chaos-infusion-preview.spec.js로 PC/모바일 비교 표시, 취소, 실제 적용, 교체 비용,
확인 중 대상 변경·재화 소진을 검증했다. 주입 제거 버튼의 흐름은 아직 기존 방식을 유지한다.

장비 인벤토리에서 UI 갱신 10회를 실행하면 숨겨진 화석 액션과 혼돈 주입 패널이 각각
10회 다시 생성되는 것을 확인했다. 두 패널의 호출을 선택된 장비 하위 탭으로 제한해
같은 조건에서 각각 0회로 줄였다. 전투 화면은 기존 상위 조건으로 이미 0회였다.
craft-lazy-lists.spec.js에서 숨겨진 상태의 재화·해금 변경은 DOM을 건드리지 않고,
제작 탭을 연 뒤 최신 재화와 선택 대상이 표시되어 실제 제작되는 흐름을 PC/모바일로 검증한다.
실행 시간을 직접 측정한 결과나 실기기 발열 개선 수치는 아니다.

화석 제작대는 모바일에서 장비 재련과 재료 정제·복원을 기존 SectionNavigation으로 분리했다.
PC는 두 작업을 동시에 표시한다. 각 타입 화석의 효과와 1개 사용 비용을 카드 안에 함께 표시하고,
선택 대상 없음·타락 상태에서는 사용 버튼을 비활성화한다. 슬롯별 유효성 판단과 재화 차감은
기존 화석 도메인이 계속 담당한다. 화면 생성은 fossil-workbench-ui.js로 이동해 ui.js의
대형 갱신 함수에서 분리했다. 데이터·저장·제작 비용은 변경하지 않았다.
PC/모바일 브라우저에서 화석 사용 차감, 재료 작업 전환, 수량 입력 후 기본 화석 정제를 검증했다.
후속 점검: applyFossilCraft의 수량 입력 전 잔액 스냅샷과 입력 후 실제 잔액 재검증,
화석 목록의 비활성 화면 갱신 및 많은 재료 보유 시 탐색 길이를 점검한다.

## 모바일 설정 분류

설정 첫 화면은 데이터·알림·전투 카드가 이어져 외형·배율에 도달하려면 긴 스크롤이
필요했다. 모바일에서 화면·외형 / 전투·소리 / 자동 진행 / 알림·채팅 / 메뉴 배치 /
저장·계정의 네이티브 선택기로 나눴다. PC는 기존 전체 배치를 유지한다. 모든 입력은
원래 DOM과 이벤트를 보존하고, 분류 선택은 tab-settings의 표현용 dataset만 변경한다.
설정 저장 구조나 값 처리 규칙은 변경하지 않는다. 새 루프 시작 설정도 자동 진행에 포함했다.

settings-categories.spec.js는 여섯 분류의 실제 항목 접근, 카메라 흔들림·채팅 크기 변경
후 분류 왕복의 값 유지, PC로 전환해 설정 창 재개방 시 전체 표시, 모바일 복귀 시
선택 분류 유지를 확인한다. settings-layout/mobile-library의 메뉴 배치·라이트 테마·
PC/모바일 독립 설정 검사도 실제 분류 선택을 거친다. 관련 브라우저 5개 통과,
PC 전용이 아닌 휴대폰 바로가기 검사의 PC 실행 1개는 기존대로 생략했다.
전체 스모크 175/175 통과. HTML·CSS와 브라우저 검사만 바뀌어 JS 구조 검사는 반복하지 않았다.
기존 전체 입력값 수집은 유지하므로 숨은 분류 때문에 다른 설정이 초기화되지 않는다.
클라우드 계정·저장 이력·불러오기의 실제 로그인 상태 검증과 설정 처리 구조 분리는 남아 있다.

메뉴 배치 편집기도 실제로 펼쳤을 때만 생성한다. 모바일에서 다른 설정 분류로 이동하면
열림 속성이 남아 있어도 숨은 편집기를 갱신하지 않는다. details 열림과 분류 전환은
기존 renderTabOrderSettings를 호출하며 실제 배치 적용·저장 동작은 제한하지 않는다.
settings-categories.spec.js는 초기 접힘의 자식 8개→0개, 숨은 상태 10회 갱신의 DOM
변경 0회, 숨은 사이 배치 변경 후 재개방 시 최신 선택 표시를 확인한다.
기존 PC/모바일 메뉴 편집·바로가기 검사를 포함해 5개 통과했고, 후속 최신 배치 표시
검사도 PC/모바일 통과했다. 전체 스모크 175/175 및 구조·lint 검사 통과. 입력 목록이 보일 때의
반복 재생성과 초점 유지 개선은 아직 별도 범위다.

## 커뮤니티 계정 진입

비로그인 커뮤니티의 버튼은 설정 첫 화면으로 이동했지만 모바일 설정 분류 도입 후
계정 항목을 다시 찾아야 했다. 기존 openStartupGate({accountOnly:true})로 직접
연결하고 버튼을 로그인 화면 열기로 명확히 했다. 로그인 준비 중 표시와 정상 채팅은
변경하지 않는다. community-entry.spec.js에서 수정 전 계정 화면 미표시를 재현했고
PC/모바일에서 직접 진입 및 기존 레벨·루프·지역 유지가 통과했다. 외부 네트워크를
차단한 게스트 상태 검사이며 실제 인증·메시지 전송을 한 것은 아니다.
전체 스모크 175/175 통과. 실제 모바일 빈 커뮤니티 화면도 확인했다.
다음 검토 대상: onSocialChatKeydown의 한글 조합 중 Enter 구분, 키보드가 열린
시각적 뷰포트에서 입력창·첨부·닫기 접근, 전송 대기 중 새 초안 보존 및 중복 요청.

채팅 키 입력은 isComposing 또는 IME keyCode 229 상태, 길게 누른 repeat Enter를
전송에서 제외한다. 일반 Enter는 기존 전송 경계로 전달하고 Shift+Enter 및 다른 키는
기본 처리를 유지한다. smoke-social-identity.js에서 수정 전 조합 Enter가 기본 동작을
막고 로그인 경고를 띄우는 실패를 재현했다. 수정 후 조합·반복·비전송 키가 초안을
유지하고 전송 경계를 호출하지 않으며 일반 Enter의 게스트 경고는 유지됨을 확인했다.
community-entry.spec.js는 실제 브라우저 KeyboardEvent의 조합·반복 플래그 처리와
계정 진입을 PC/모바일 4개 검사로 검증한다. 실제 IME/키보드 장치 입력을 자동화한
것은 아니며 서버에 채팅 메시지를 전송하지 않았다. 전체 스모크 175/175 및 구조·lint 검사 통과.

채팅 전송은 클릭 시 문장·첨부를 캡처하고 첫 비동기 호출 전에 chatSending으로
중복 요청을 막는다. 이전에는 프로필 업로드 후 입력을 비우고 실패 시 과거 문장을
복원해 대기 중 새 초안을 덮어쓸 수 있었다. 이제 POST 성공 뒤에도 현재 문장과
첨부가 제출 당시와 같을 때만 비우며, 실패하면 입력을 건드리지 않는다. finally에서
대기 상태를 해제한다. 계정은 각 비동기 준비 단계 뒤 재확인하고, POST 응답 중
계정이 바뀌면 새 계정의 입력/전송 기록을 갱신하지 않는다. 이 상태는 저장하지 않는다.

smoke-social-identity.js의 네트워크 경계 대역으로 지연·성공·실패·새 초안·첨부·
중복 클릭·응답 중 계정 변경을 확인했다. 수정 전 같은 대기에서 POST 2개로 실패했다.
community-entry.spec.js는 실제 입력창과 전송 버튼을 사용하되 네트워크 API만 로컬
대역으로 바꿔 PC/모바일에서 1회 요청과 새 문장 유지를 확인한다. 커뮤니티 관련
브라우저 6개, 전체 스모크 175/175 통과. 실제 서버에 메시지를 게시하지 않았다.
전송 대기 표시와 실제 휴대폰 키보드가 열린 배치는 별도 후속 점검 대상이다.
계정 준비는 prepareChatSender, 성공 후 조건부 초안 정리는 clearSubmittedChatDraft로
분리해 기존 전송 함수의 복잡도 증가를 피했다. 두 함수는 social.js 내부에서만 사용한다.
최종 소스의 구조·lint 검사도 통과했다.

PR 최종 리뷰에서 이전 계정의 전송 실패가 새 계정 닉네임을 지우는 경로를 추가로
재현했다. 닉네임 충돌 처리를 제출 계정이 여전히 현재 계정인 경우로 제한한다.
네트워크 응답 대기 중 계정을 변경하고 새 닉네임을 설정하는 회귀 검사로 보존을 확인한다.

채팅 전송 중에는 버튼을 비활성화하고 ‘전송 중’과 aria-busy 상태를 표시한다.
입력창과 첨부는 계속 사용할 수 있으며 성공·실패 후 현재 계정의 전송 가능 상태로
버튼을 복구한다. 버튼 상태는 social.js 내부 updateChatSendButton이 소유하고,
화면 재생성 시에도 현재 요청 상태를 반영한다. 모바일 첨부·전송 영역은 최소 44px로
조정하고 대기 문구가 잘리지 않도록 전송 칸을 64px로 넓혔다.
PC/모바일 대기 화면을 시각 확인했고, 지연 응답 중 입력·Enter 중복 방지와 성공 후
버튼 복구를 브라우저 6개 검사로 검증했다. 성공·네트워크 실패 후 복구는 실제 소셜
함수를 실행하는 스모크로 확인했다. 실제 휴대폰 키보드 검증은 포함하지 않는다.
