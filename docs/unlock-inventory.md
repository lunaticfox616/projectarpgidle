# 해금 목록 정리 — 결정 전 자료

2026-09-06. 개편 전 콘텐츠를 정리한 기록이다. 아래 미정 사항과 과거 구현 설명은 당시 상태이며,
현재 적용한 단계·비용·자동 개방·저장 호환 정책은 [콘텐츠 선택 해금](content-progression.md)을 따른다.
선택/자동 구분, 비용, 루프, 선행 연결은 이 문서에서 결정하지 않는다.
실행 코드나 사용자 저장을 변경하지 않았다.

## 합의된 기본 범위

- 루프 1: 캐릭터, 스킬 트리, 장비 장착, 공격 스킬 젬.
- 루프 2부터 선택 해금과 진행에 따른 자동 해금을 함께 사용한다.
- 설정·채팅 등의 기본 이용 기능과 해금 콘텐츠는 구분한다.
- 기존 UI 시안의 항목 배치·화살표·비용은 예시이며 확정 규칙이 아니다.

## 상위 목록과 별도로 관리할 세부 해금

이 표는 확인된 대표 항목이다. 38개에 포함되지 않는 모든 개별 보스·레시피·슬롯을 전수 집계한 수치는 아니다.

| 소속 | 세부 해금 예시 | 확인 위치 |
| --- | --- | --- |
| 컨디션 젬 | 정예 등장, 상태이상, 거리, 최근 피격 등 발동 조건과 목표/위치 운용 | `data/skills.js`의 `CONDITION_PATTERN_TRIGGER_DB`, `CONDITION_PATTERN_ACTION_DB` |
| 젬 성장 | 각인 슬롯, 젬 퀄리티, 보조 젬 창공 가공, 각성 후보 변환 | `js/skills.js` |
| 전문가·제작 | 개별 전문가 조우, 전문가 레벨별 제작·정제 기능 | `js/ui.js`의 `checkUnlocks`, `js/skills.js` |
| 인벤토리 | 보관 행·페이지 확장 | `js/equipment-inventory-grid.js` |
| 생장판 | 배치 가능 칸과 시너지 확장 | `data/maps.js`의 기존 진행표, `data/growth-items.js` |
| 전직 | 후속 전직 시련 | `js/ui.js`의 `checkUnlocks` |
| 탐험 | 다음 지역·층·보스·루프 경로, 고급 의뢰, 군락지 액막이 | `data/maps.js`, `data/bounties.js`, 카탈로그의 하위 경로 |

모든 세부 기능을 독립적인 유료 노드로 만들지는 아직 결정하지 않았다.
예를 들어 ‘젬 성장·각인’을 한 노드로 묶을지, 강화/각인을 나눌지 먼저 정해야 노드 수가 확정된다.

## 현재 코드와 합의의 차이

앞선 구현에는 아직 사용자 확정이 아닌 규칙이 남아 있다.

- 첫 선택 네 가지(보조 젬·위기 대응·재련·현상금).
- 보조 젬 선택 후 루프 3 연구, 루프 4 강화·각인 자동 해금.
- 재련 선택과 거래소 메뉴를 연결한 규칙.
- 카탈로그의 `after` 연결, 비용, 시작 보상.

위 설정을 승인된 정책으로 재사용하지 않는다. 이번 목록 정리에서는 이전 변경을 되돌리거나 추가 변경하지 않았다.

또한 카탈로그의 메뉴 해금과 개별 시스템의 사용 조건이 겹친다.
예: 거래소의 액트 5 클리어, 혼돈 주입기의 나무꾼 기록/조우, 전문가 레벨별 젬 가공 조건.
이 둘을 함께 확인해야 ‘탭은 열렸지만 아직 사용할 수 없는’ 상태를 설계할 수 있다.
`SEASON_CONTENT_ROADMAP`에는 개편 전 문구도 남아 있으므로 새 정책의 단일 기준으로 사용하지 않는다.

## 다음 결정 순서

### 추가로 합의한 설계 기준

- 플레이어의 성장 수단은 직접 해금한다.
- 적의 강화와 진행 조건으로 열리는 전투 콘텐츠는 자동 해금한다.
- 성장 선택은 여러 단계로 배치하고 선행 해금과 진행 조건을 함께 고려한다. 구체적인 연결·비용·시점은 아직 미정이다.
- 기존 **루프 이정표**를 함께 참고해 각 단계가 기존 전투 진행과 맞물리도록 설계한다.

### 루프 이정표 확인 결과

실제 UI는 `index.html`의 `season-content-section`, 데이터는 `data/maps.js`의
`SEASON_CONTENT_ROADMAP`, 표시는 `js/ui.js`의 `ui-season-content-roadmap` 조립 부분이 소유한다.
각 루프에는 `getLoopAbyssRequirementText`가 만드는 루프 진행 조건과 콘텐츠 해금·확장 설명이 함께 표시된다.
보상 수령 기능이 아니라 진행 안내표이며, 과거 이정표를 접는 기능이 있다.

후속 UI 설계에서는 한 이정표 안에서 다음 정보를 구분하는 안을 검토한다.

1. **전투·진행:** 해당 단계에서 자동으로 열리는 지역·적·루프 조건.
2. **성장 선택:** 해당 단계부터 포인트로 고를 수 있는 성장 수단.
3. **실제 상태:** 루프 도달, 추가 조건 충족, 선택 가능, 해금 완료.

현재 이정표의 상태는 루프 번호만 비교하므로, 조건부 콘텐츠까지 실제 해금 완료로 보일 수 있다.
새 선택식 UI에 그대로 복사하지 않고 개별 조건과 구매 여부를 분리해야 한다.
또한 현재 `css/content-progression.css`는 선택식 진행에서 기존 이정표 섹션을 숨긴다.
이번 확인에서는 이를 변경하지 않았다. 실제 연결 시 이정표와 새 UI가 중복되거나 사라지지 않게 정리할 대상이다.

### 미결정 사항

1. 상위 항목을 묶거나 나눌지 결정.
2. 기본 제공 / 선택 해금 / 자동 해금 배정.
3. 선행 관계와 진행 조건 결정.
4. 포인트 수급·비용 결정.

검증: 카탈로그 38개 ID와 위 표의 누락·중복 대조. 문서만 추가했으므로 게임 스모크는 생략.
