# 그루터기 함 — 현재 게임에 맞춘 설계 제안

상태: **제품 설계안, 미구현.** 이 문서는 기존 게임 코드와 Gemini 공유 대화의 요구를
대조해 만든 권장안이다. 아래 수치와 선택은 검토용이며 사용자 확정으로 기록하지 않는다.
구현 기준은 현재 개발본인 pr-repo/다.

## 1. 현재 게임에서 맡을 자리

현재 게임은 루프 1에 장비와 공격 젬으로 진행하고, 액트 10 이후 혼돈 구간을 계속 돈다.
젬 기본 레벨은 20에서 멈추며 루프마다 1로 돌아간다. 기존 생장판은 루프 25부터
구매해 여는 8×4 다칸 아이템 보드다. 부적은 루프 6, 코어 큐브는 루프 20의 별도 장치다.

**권장:** 그루터기 함은 첫 루프 액트 10에서 얻는 *초기~중기 영구 성장 장치*로 둔다.
생장판은 *후기 루프의 계절형 제작·배치 장치*로 유지한다. 두 판은 같은 화면이나
아이템 목록을 공유하지 않는다. 생장판에는 다칸 형태, 제작, 고유 효과와 루프 봉인이
이미 연결되어 있으므로 이를 지금 5×5 단일 칸 체계로 바꾸는 것은 범위가 크다.
함의 스탯 크기와 부여 가능한 효과를 제한해 두 보드가 함께 켜져도 역할이 겹치지 않게 한다.

| 시스템 | 플레이어가 하는 일 | 유지되는 가치 |
| --- | --- | --- |
| 그루터기 함 | 씨앗·수액을 길러 색 공명과 상극 배치를 고른다 | 유물, 칸, 배치 취향, 보관 원재료, 젬 슬롯 흔적 |
| 생장판 | 루프 25 이후 다칸 성장 아이템을 제작하고 공간 시너지를 맞춘다 | 해금 칸·봉인품; 일반 배치/아이템은 기존처럼 루프 초기화 |
| 부적 | 미궁 재료로 루프 안에서 부적 보드를 구성한다 | 기존 해금 조건과 초기화 규칙 |
| 코어 큐브 | 지하계 동력원을 6면에 붙인다 | 기존 프리셋·발견 기록; 현재 동력원은 루프 초기화 |
| 젬·보조 젬·각인 | 스킬 레벨과 공격 방식을 만든다 | 기존 제작·강화·변형 규칙 |

함의 꽃·열매·호박석은 **패시브 능력치**를 준다. 스킬의 투사체 수·범위·시전 방식·
연쇄 같은 행동 변화는 기존 보조 젬과 각인에 맡긴다. 장비 제련·화석·아르카나의
드랍과 재화를 함 해금 때문에 조정하지 않는다.

## 2. 플레이어 경험

1. 첫 루프의 액트 10 구간 완료 시 함을 **별도 고정 보상**으로 받는다. 기존 액트
   보상 선택은 그대로 남는다. 이때 안내에는 “씨앗을 놓으면 전투로 자란다”와
   “보관함에서는 자라지 않는다”를 한 화면에 보여 준다.
2. 처음 사용을 보장하려고 색을 선택할 수 있는 씨앗 1개와 수액 1개를 한 번 지급한다.
   씨앗은 꽃/열매 경로를 고를 수 있고, 수액은 호박석으로 자란다. 초반 아이템 색을
   무작위로 강제하면 현재 사용하는 스킬과 상관없는 보상을 받기 쉽다.
3. 함을 얻기 전에는 함 전용 드랍이 나오지 않는다. 획득 후에는 모든 일반 전투에서
   기존 장비 드랍과 **독립적으로** 씨앗·수액을 굴린다. 기존 제작 재화 확률은 그대로 둔다.
   루프 2부터는 액트 10을 다시 깨기 전에도 함과 전용 드랍을 이용한다.
4. 5×5 판은 처음에 중심 5칸만 활성화한다. 나머지 칸은 유물 내부의 닫힌 영역으로
   보이고, 최고 도달 루프에 따라 자동으로 열린다. 권장 첫 시안은
   액트 10: 5칸 → 루프 2: 9칸 → 6: 13칸 → 10: 17칸 → 25: 21칸 → 50: 25칸이다.
   칸 해금에 별도 콘텐츠 포인트를 요구하지 않는다. 시안 수치는 플레이 시간과
   성장 속도 측정 후 조정한다.
5. 배치된 아이템만 전투 처치·완료 보상에 따라 성장한다. 게임 밖 경과 시간만으로
   성장시키지 않는다. 방치 전투 재생도 실제 처치/보상 기록을 바탕으로 같은 규칙을
   적용한다. 보관함에 둔 동안은 능력치와 성장량이 모두 0이다.

함은 “가끔 배치를 바꾸고 다음 루프에서 다시 키우는 유물”이어야 한다. 매 전투마다
칸을 조정하도록 유도하지 않는다. 꽃/호박석의 획득량과 성장 요구량은 첫 획득
직후 혼돈 구간에서 **첫 완성품 1개를 경험할 수 있는 속도**를 기준으로 시뮬레이션한다.

## 3. 아이템과 판정 규칙

- 아이템은 한 칸만 차지한다. 씨앗은 꽃 또는 열매로, 수액은 호박석으로 자란다.
  씨앗을 놓을 때 꽃/열매 경로를 선택하고 현재 경로를 항상 표시한다.
- 꽃·열매는 조건부 능력치, 호박석은 고정 능력치를 준다. 조건은 플레이어가 전투 중
  확인할 수 있는 것부터 사용한다. 예: 보스 상대, 생명력 절반 이하, 현재 공격 젬
  태그. 조건부 효과도 기존 능력치 합산 경계에서만 적용한다.
- 색은 화염·냉기·번개·카오스 네 가지를 첫 시안에 쓴다. 물리 스킬 사용자는
  방어·공용 꽃/호박석을 쓸 수 있게 하며, 색이 반드시 같은 원소 피해를 뜻하지는 않는다.
  상극은 화염↔냉기, 번개↔카오스를 제안한다. 이 대응은 정적 데이터 한 곳에서 관리한다.
- 성숙하고 억제되지 않은 같은 색 아이템이 판 위에 3개 이상이면 공명한다.
  위치는 묻지 않는다. 한 색당 공명은 한 번만 적용하고, 같은 색 6개로 두 배가
  되지 않는다. 첫 밸런스 목표는 **그 색 아이템에서 나온 능력치만 10% 증폭**이다.
- 상극색 두 아이템이 상하좌우로 맞닿으면 두 아이템 모두 억제된다. 억제 중에는
  능력치·성장량이 0이며 공명 개수에도 넣지 않는다. 대각선은 무관하다.
  두 아이템을 떼면 다음 계산에서 즉시 복구된다. 억제는 모든 인접쌍을 동시에 판정해
  배치 순서에 영향을 받지 않는다.
- 줄 완성·수맥·다칸 모양·회전 규칙을 함에 넣지 않는다. 이것은 기존 생장판의
  공간 시너지와도 구분되는 지점이다.

**밸런스 목표:** 첫 5칸 완성의 전투 기여는 동레벨 장비 한 부위보다 작게,
25칸과 공명을 모두 갖춘 후기 세팅의 순수 추가 피해·유효 생존력은 각각
빈 함 대비 약 15% 안쪽에서 시작한다. 최종 수치는 현재 장비/생장판을 함께 낀
시뮬레이션으로 정한다. 함에서 추가 투사체, 소환수 상한, 최종 피해 곱연산,
스킬 형태 변경 같은 강한 효과를 바로 지급하지 않는다.

## 4. 루프와 저장

**권장 저장 단위:** 함 자체에 획득 기록, 최고 해금 칸, 아이템 목록, 보관함 확장,
칸→아이템 ID 배치, 주 공격 슬롯의 초월 흔적을 둔다. 아이템에는 안정된 ID,
씨앗/수액 계열, 색, 꽃/열매 경로, 단계, 성장량, 옵션, 봉인 여부를 둔다.
공명·억제·최종 능력치는 저장하지 않고 배치에서 계산한다. 하나의 아이템이
보관함과 판에 동시에 복제되지 않도록 배치는 ID 참조로만 남긴다.

| 루프 전환 항목 | 권장 동작 |
| --- | --- |
| 함 획득, 해금 칸, 보관함 확장, 슬롯 흔적 | 유지 |
| 판에 놓인 위치 | 유지; 새 루프에서 재배치 노동을 강제하지 않음 |
| 보관함의 씨앗·수액 및 미성숙품 | ID·색·경로·옵션·진행량 유지 |
| 봉인한 성숙품 | 완성 상태 유지 |
| 일반 성숙품 | ID·옵션은 유지하고 씨앗/수액으로 회귀, 진행량 0 |
| 일반 성장·제작 재료 | 루프 초기화; 구매한 확장 결과는 유지 |
| 공명·억제 | 아이템 단계와 배치를 읽어 재계산 |

회귀는 **설계 제안**이다. 현재 생장판처럼 일반 완성품을 삭제하면 미성장 원재료는
남는데 키운 보상이 사라지는 역전이 생긴다. 완성품을 모두 유지하면 루프 2부터
함의 판이 영구 완성되어 방치 성장의 역할이 줄어든다. 동일 아이템을 다시 기르는
방식이면 색·옵션 파밍은 유지하면서 루프 성장 리듬을 만들 수 있다.
봉인 수단은 기존 나무꾼의 손길과 같은 경제를 사용하되 비용/해금 시점은 별도
밸런스 수치로 정한다. 이 설명은 사용자의 계승 정책 승인으로 간주하지 않는다.

**보관함 권장안:** 함 전용 50칸, +5칸씩 확장해 최대 100칸. 기존 생장판의
40칸 보관함 및 구매한 확장 레벨은 그대로 유지한다. 새 함의 일반 드랍은
보관함이 가득 찼을 때 기존의 선택형 자동 해체 규칙을 따를 수 있지만, 잠금·
고유·보상 아이템은 임의 해체하지 않고 수령 대기함에 둔다. 루프 회귀로
보관함이 넘칠 때도 마찬가지다.

이전 저장은 액트 10 저널 기록 또는 루프 2 이상 기록으로 함 획득 자격을 판정한다.
저장 마이그레이션은 함과 시작 아이템 지급 영수증을 한 번만 만든다.
재접속·클라우드 복원·중복 클리어에서 시작 보상을 다시 주지 않는다.
기존 생장판/코어 큐브/부적 저장 필드는 이 설계에서 변환하거나 삭제하지 않는다.

## 5. 젬 21–30의 연결

현재 공격 젬의 고유 레벨은 전투 경험치로 20까지 오른다. 장비·핵·창공 보너스는
이미 실효 레벨을 20 위로 올릴 수 있다. 따라서 함의 초월은 gemData.level을
30으로 늘리는 방식으로 만들지 않는다.

**권장:** 함의 주 공격 슬롯 하나에 20→30 초월 흔적을 저장한다. 기존 젬 강화
콘텐츠를 해금하고 현재 장착한 *공격 젬*이 해당 루프에서 고유 레벨 20에
도달했을 때만 흔적 보너스가 발동한다. 다음 루프 젬이 1레벨로 돌아가면
흔적은 남지만 효과는 잠들어 있다. 젬을 교체하면 새 젬도 20에 도달한 뒤
같은 주 공격 슬롯의 흔적을 사용한다. 기본 공격, 보조 젬, 소환 젬에는 처음부터
자동 적용하지 않는다.

표시는 “젬 고유 20 / 함 초월 +N / 장비·핵·창공 +M / 실제 적용 레벨 20+N+M”처럼
출처를 나눈다. 21·25·30 이정표에서 성숙 꽃/열매와 호박석을 소비하고,
사이 단계는 기존 젬 관련 재화로 올리는 안을 제안한다. 정확한 종류·수량·
비용은 젬 20 이후 성장 곡선과 현재 강화 비용을 측정해 정한다.
모든 소비는 아이템·재화 차감과 흔적 증가를 한 번의 저장 거래로 처리한다.

## 6. 포식의 위치

“불씨의 흉터”와 8칸 포식은 함의 후반 확장으로 분리한다. 현재 게임의
최종 보스·경계 진행과 연결할 수 있지만 구체적인 드랍 보스는 기존 보스
보상표를 확인한 뒤 정한다. 빈칸을 뽑으면 성장 실패만 기록하고,
차 있는 칸을 뽑으면 그 아이템을 소비하는 원안의 위험성을 유지한다.
완성품은 일반 아이템 대비 최대 3배, 능력치 유형별 상한을 두고,
여러 개를 소유할 수 있다는 방향을 유지한다. 이 기능은 기본 함의
드랍·배치·성장·저장이 안정된 뒤 별도 수치와 UI를 설계한다.

## 7. 구현 경계와 순서

1. data/에 함의 색·상극·아이템·칸 확장 정의를 두고, js/state.js에 기본 상태,
   js/save-migrations.js에 이전 저장 복원 규칙을 둔다. 기존 coreCube/growthBoard
   필드와 해금 원장은 유지한다.
2. 액트 10 완료 경계에서 일회성 획득을 지급한다. 기존 액트 선택 보상과 별도
   영수증을 쓴다. 함 전용 드랍은 기존 장비/생장판 드랍과 독립된 굴림으로 만든다.
3. 함 도메인이 배치·성장·공명·억제·루프 회귀를 소유한다. 전투는 처치 결과만
   전달하고, 능력치 파이프라인은 계산 결과를 한 번 합산한다.
4. 성장 그룹의 “그루터기 함” 화면에 5×5 판, 보관함, 성장 상태, 공명/억제 원인,
   세팅 효과를 표시한다. 기존 장비 그룹의 생장판과 코어 큐브 이름을 구분한다.
5. 기본 함의 플레이 흐름을 확인한 뒤 젬 슬롯 흔적을 붙인다. 포식은 마지막 단계다.

보관함 정지·배치 변경 즉시 효과·기존 생장판/코어 큐브 불변을 실제 게임
