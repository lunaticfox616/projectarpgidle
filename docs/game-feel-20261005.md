# 전투·보상 피드백 개선

기준: `codex/game-feel-juice-20261005`, 탐험 오브젝트 후속 변경 `543f858d` 포함.

효과음은 이후 [생성 효과음과 재생 계약](game-audio-20261006.md)으로 교체했다.
아래 검증 기록은 이 문서 작성 당시 결과다.

## 관찰할 변화

- 모든 스킬의 실제 접촉 위치에 짧은 픽셀 타격선. 일반타 / 치명타 / 큰 피해의 크기·색을 구분한다.
- 처치 띠는 보스 처치만 띄운다. 여러 마리를 한꺼번에 잡을 때 뜨던 `N마리 처치`는 밋밋하다는 의견으로 2026-10-06에 뺐다. 추가 보상·배율·유지해야 하는 콤보는 없다.
- 보스 처치 확인은 일반 처치보다 우선하며, 전투를 멈추지 않는다.
- 상자는 열리는 순간 금빛 조각, 항아리와 목재 상자는 서로 다른 파편과 소리. 지급 성공 이벤트 뒤에만 표현한다.
- 레벨업과 중요 전리품은 별도 소리로 구별하며 일반 희귀템 알림은 무음이다.
  표현은 보상을 직접 지급하지 않는다. 현재 장비·재화·주얼·코어·야생 부적의 바닥 보관과 줍기는 [탐험 보상](act-exploration-integration.md)을 따른다.

## 소유와 경계

### 방 사이 이동의 목표 표시 (2026-10-23)

다른 방을 클릭해 이동할 때는 실제로 지나갈 열린 문의 현재 방 안쪽 바닥 칸에 기존 점선 고리를 표시한다.
방이 화면보다 넓거나 오른쪽 기록·채팅 창이 가리면 문 방향 화살표와 같은 노출 폭 안으로 고리만 옮겨 잘리지 않게 한다.
목표 방에 도착하면 원래 목적지 칸을 표시하며, 같은 방과 연속 지도·키보드 이동의 표시 규칙은 유지한다.
다른 방으로 가는 고리는 그 목표와 문, 안쪽 바닥 칸을 모두 알고 있을 때만 보이며, 전투·관문·도착 유예로 잠긴 문은 표시하지 않는다.
표시만 기존 문 경로를 읽으며 이동 목적지와 저장은 바꾸지 않는다. 클리어 후 전리품을 찾는 이동도 같은 규칙이다.

같은 칸의 전리품 표시는 더미 전체의 최고 등급을 유지하지만, 착지음·그림의 짧은 반동은 새로 떨어진 행의 등급으로 정한다.
일반 장비가 추가됐다고 기존 귀중품의 알림음을 반복하지 않는다. 등급은 비행 시작 때 고정하므로 비행 도중 들어온
다른 드롭에도 영향을 받지 않는다. 수량만 늘거나 화면을 다시 그릴 때는 착지음을 재생하지 않는다.

### 피해 숫자 배치 (2026-10-13 통합 검토, R13)

피해 숫자는 맞은 대상의 몸 중심 가로 위치를 유지한다. 받은 피해를 먼저 놓고, 같은 분류에서는 새 숫자를 먼저 놓는다. 이미 떠 있는 숫자가
겹치면 실제 글자 폭·높이와 치명타 확대, 연타 횟수 표시까지 고려해 필요한 만큼 위로 옮긴다.
준 피해·받은 피해·지속 피해·회피/막기 표시가 같은 배치를 사용한다. 이전의 고정 34px 거리 검사와
23px 밀어 올리기는 제거했다. 이웃 숫자가 사라져도 남은 숫자는 아래로 되돌아오지 않는다.

표시 수 상한 48개, 숫자 색·유지 시간, 같은 스킬/대상의 250ms 합산과 피해량은 유지한다.
숫자 크기(2026-10-26, PC와 휴대폰 같음): 보통 숫자와 회피, 막기 같은 글은 갈무리11 Bold 12px, 가장 큰 타격만 24px이다
(전: PC 24px, 가장 큰 타격 36px. 무리 전투에서 24px 숫자가 쌓여 주인공을 덮었다).
주인공이 받은 피해는 400ms(`HURT_TEXT_MERGE_MS`)마다 한 숫자로 합친다(2026-10-19, 막은 피해는 따로).
위로 옮길 수 있는 거리는 기존 최대치 207px 이내이며 화면 위쪽을 넘지 않도록 제한한다.
아주 좁은 곳에 48개가 집중되면 일부 겹침은 남을 수 있다. 숫자를 없애거나 전투 범위를 바꾸지는 않는다.
배치 정보는 수명이 짧은 `battleVisualState.damageTexts`에만 두며 저장하지 않는다.

밀집 전투 표시(2026-10-29): 같은 대상의 같은 색·문구인 회피/막기 같은 `bodyCue`는 첫 표시의 수명 안에서
하나를 재사용하고 위치만 갱신한다. 첫 시작 시각과 760ms 수명을 연장하지 않고, 다른 대상·다른 판정·다른 색은
합치지 않는다. 경계 표시 `!` 같은 일반 상태 글씨도 합치지 않는다. 받은 피해는 다른 숫자·판정 글씨보다 먼저
자리를 확보하고, 아래쪽으로 밀렸다는 이유로 일찍 사라지는 `crowdFade`는 적용하지 않는다. 정상 만료와 48개 상한은 유지한다.

같은 순간 피격 중인 살아 있는 적(보스 제외)의 몸 범위가 서로 이어져 3마리 이상 겹치면, 그 무리의 몸 전체 피격 섬광을
기존 강도의 40%로 그린다. 화면에 그리는 적만 세며, 1~2마리·떨어진 적·보스는 기존 표시를 유지한다.
강도를 낮춘 피격은 그 섬광이 끝날 때까지 유지해 이웃의 섬광이 먼저 끝나도 갑자기 다시 밝아지지 않는다.
새 피격에서는 겹침을 다시 판단한다. 원래 110/140ms 지속 시간, 적별 220ms 간격, 약한 강조 설정,
등장 섬광·반동·타격선·공격 예고·소리와 전투 계산은 유지한다. 판정은 기존 몸 크기와 위치만 읽으며 저장 상태를 추가하지 않는다.

지속 피해 숫자 합산(2026-10-29): 같은 적·같은 원소의 지속 피해 FX는 첫 숫자가 나타난 뒤 350ms 이내에
한 숫자로 합친다. 이후에는 새 숫자를 만들며 새 틱마다 합산 시간을 밀지 않는다. 직접 타격·서로 다른
적·다른 원소·플레이어 피격과 합치지 않는다. 틱 수를 공격 횟수처럼 보이게 하는 `N타` 표시는 붙이지 않고,
합산됐다는 이유로 큰 타격이나 전멸 타격의 크기·강조로 승격하지 않는다. 기존 색·표시 수명·48개 상한은 유지한다.
이는 이미 표시하기로 한 FX 값의 합이다. 상태이상 FX의 기존 발생 간격 제한은 그대로이므로, 이 숫자를
해당 시간 동안의 전체 지속 피해량이나 DPS로 해석하지 않는다. 실제 피해·처치·보상·상태이상 주기는 바꾸지 않는다.
지하계 검수 저장을 실제 전투 루프로 재생한 마지막 1초의 출혈 FX 11개는 표시 6개로 줄었고, 표시값의 합
9,502를 유지했다. 같은 입력의 전체 게임 상태·난수·발생 FX도 같았다. 첫 표시 후 350/351ms 경계, 대상·원소
분리, 기존 치명타·피격·회피, 48개 상한·만료를 포함한 임시 검사 7개와 전체 스모크 20개·빌드가 통과했다.
이는 특정 저장의 표시 확인이며 밀집 전투의 모든 겹침이나 실제 저사양 기기 성능이 해결됐다는 뜻은 아니다.
원시 기록은 `artifacts/encounter-variety-20261029/damage-dot-review.json`에 있다.

임시 Chromium 검사에서 일반전·적 5마리·보스의 표시 입력을 PC/휴대폰, 기존/옆보기 전장으로
비교했다. 수정 전에는 다수/보스 장면에서 숫자가 겹쳤고, 수정 후 12장면의 6시점 모두 겹침이 없었다.
숫자 표기 4종과 정렬 3종에서 합산 값·연타 횟수·지속 피해·피격 표시, 48개 상한과 만료도 확인했다.
한국어 단위 `만`의 실제 글자 끝을 읽어 연타 꼬리표가 붙는 문제를 함께 고쳤다.
전체 스모크 20/20, 구조·빌드, 관련 기존 브라우저 11개(기기별 제외 1개)가 통과했다. 영구 검사는 늘리지 않았다.

합성 레벨 100 장비와 소환수 8마리, 체력을 늘린 액트 2 적 12마리를 유지한 12초 부하 표본은
PC 47.3 → 47.5fps, 휴대폰 크기의 데스크톱 Chromium 약 60fps였다. 적 12마리가 전 구간 시야에 있었고
안내 창·정지·오류는 없었다. 카운터의 마지막 글자 간격 정리 전 배치 구현을 측정한 값이며,
밸런스나 실제 저사양 휴대폰 증거가 아니다. 밀집 전투 전체 성능과 극단적 겹침은 여전히 남은 작업이다.

`combat`은 기존 FX에 적 이름을 담고, 오브젝트 지급은 `exploration-object` 이벤트로 위치와 결과만 전달한다.
`canvas-combat-feedback.js`는 기존 캔버스 표현 소유자인 `worldTreeSkillFx.feedback` 아래에 둔다.
게임 상태·난수·드롭 확률을 바꾸지 않고 기존 `battleFx`와 시각 시계만 소비한다.
새 저장 필드나 새 전역은 없다. 장면 초기화/숨김 시 기존 `lootEpoch`로 임시 표시도 폐기한다.
250ms 이상 렌더 공백 뒤에는 새 FX 예약과 같은 벽시계로 시각 시계를 재동기화한다.
지난 이펙트·히트스톱은 넘기며, 전투 시계와 보상·저장 상태는 바꾸지 않는다.

타격선은 프레임당 최대 8개, 파편 묶음은 최대 10개, 처치 집계는 최대 32건/450ms다.
확인 글은 하나만 표시하고, 보스가 일반 처치를 덮어쓴다. 오래된 FX는 알림·소리를 재생하지 않는다.
모션 줄이기는 이동 파편과 카메라 흔들림을 끄고 정적인 확인만 남긴다.
`hitEmphasis=mild`, `cameraShake=false`, `uiSounds=false`, 오프라인 계산을 존중한다.

재미의 향상은 플레이테스트 가설이며 자동 검사나 정지 화면만으로 입증하지 않는다.

### 다시 확인하기

이 브랜치 루트에서 `$env:PLAYWRIGHT_PORT='4242'; npm run dev` 실행 후
`http://127.0.0.1:4242/scripts/review-game-feel/index.html`을 연다.
게스트 저장으로 진입한 뒤 `전투 준비`, `5마리 처치`, `보스 마무리` 등을 누른다.
`상자 앞으로`/`항아리 앞으로`는 이동만 준비하므로 게임 안 오브젝트를 직접 누른다.
`일반 / 치명타`만 FX 비교이고, 처치·개봉·레벨·전리품 버튼은 실제 정산 코드와 별도 테스트 저장을 바꾼다.
`자동 전투`로 정상 탐험을 재개할 수 있다. 기존 4241 포트의 저장은 공유하지 않는다.

연속 캡처는 실제 캔버스 두 레이어를 합치며 DOM 전리품/창은 제외한다.
화면 밖 모바일 iframe의 RAF 제한을 피하기 위해 캡처 중 2.6초간 실제 렌더러를 30Hz로 호출한다.
이 도구의 재생은 성능 벤치마크가 아니다. 검토 도구는 `scripts/`에만 있고 배포 게임에서 로드하지 않는다.

### 효과음 설정 (2026-10-05 사용자 결정)

효과음은 그대로 두고, 끄는 스위치를 설정 맨 위 '소리' 칸으로 옮겼다(`index.html` `.cfg-group--sound`, 기존 `chk-ui-sounds`·`game.settings.uiSounds` 그대로).
분류가 없어서 PC와 모바일의 모든 설정 분류에서 첫 줄에 보인다. 렌더 측정 결과 처치음 · 목재 상자음은 대부분 300Hz 아래라
휴대폰 · 노트북 스피커에서 거의 들리지 않는다. 소리를 다시 다듬을 때 참고한다.
