# 브라우저 CI 운영

## 2026-09-08 반복 실패 원인

PR #1020, #1021의 Actions 로그에는 실제 assertion 실패와 작업 제한 시간 초과가 함께 있었다.
전체 검사는 두 기기 프로젝트에서 380개이며, 변경 관련 검사 몇 개의 통과는 전체 통과를 뜻하지 않는다.

- 플라스크·전직 시련 검사의 저장 상태가 새 해금 루프 조건을 충족하지 않았다.
- 모바일의 더보기, 설정 분류, 캐릭터 분류, 가지치기·아르카나 선택기를 거치지 않고 PC 전용 요소를 조작했다.
- 낚시 도감의 지연 렌더링, 장비 검색의 비일치 항목 흐림 표시, 현재 테마와 로그인 안내가 검사에 반영되지 않았다.
- 기존 4개 묶음은 일부 실패의 대기 시간까지 겹쳐 15분 작업 제한으로 취소됐다.

테스트는 실제 메뉴 이동과 유효한 해금 상태를 사용한다. 게임 규칙을 우회하거나 실패 검사를 새로 제외하지 않는다.
캐릭터 능력치·실효 체력은 모바일에서 탭과 반복 선택으로도 설명을 열고, 선택한 항목의 마우스 이탈만으로
설명이 닫히지 않도록 한다. 브라우저 검사에서는 초기 설정에 사용한 마우스를 화면 밖으로 옮겨 터치와
가상의 마우스 hover가 서로 다른 설명을 띄우는 간섭을 방지한다.

## 실행과 결과 해석

```powershell
npm test
npm run check:architecture
npm run test:browser
```

수정 중에는 `--grep`으로 관련 검사만 실행할 수 있지만 결과 보고에 반드시 선택 범위를 적는다.
최종 결과는 실행 커밋, 통과·실패·기존 기기별 제외 개수, 로컬 또는 GitHub 실행 여부를 구분한다.
GitHub 결과가 아직 진행 중이면 통과로 안내하지 않는다.

CI는 PC 4개와 모바일 4개, 총 8개 작업으로 전체 검사를 분산한다. 각 작업의 Chromium worker는 기존 2개다.
동일 저장소의 PR은 push 실행 결과를 사용하여 중복 실행을 피하고, 외부 포크는 pull_request에서 실행한다.
새 푸시로 이전 커밋 실행이 취소된 경우에는 최신 커밋 실행을 확인한다.

Playwright 전체 제한은 작업당 12분이고 GitHub 작업 제한은 15분이다. 실패 시 남은 시간에 프로젝트·묶음별
스크린샷, 동영상, trace를 업로드한다. 게임 실행 오류인지, 오래된 검사 전제인지, 로딩 지연인지 이 자료로 구분한다.
묶음이 반복해서 제한에 도달하면 개별 검사 시간을 먼저 확인한다. 재시도 횟수 증가나 검사 삭제로 감추지 않는다.
