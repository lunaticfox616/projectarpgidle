# 탐험 UI/UX 집중 개선 — 2026-09-14

## 범위와 판단 기준

전체 탐험 → 권역 → 개별 콘텐츠 진입까지를 검토했다. 게임 전체의 재미나 개별 콘텐츠의 모든 내부 화면에 대한 점수는 아니다.
자동 검사의 성공률을 UX 점수로 환산하지 않는다. 아래 평가는 실제 화면과 조작을 확인한 개발자의 정성 평가이며,
초보 플레이어의 독립적인 사용성 검증은 아직 없다.

## 수정한 문제

- 상단의 중첩 테두리와 여백을 줄이고, 권역과 세부 콘텐츠의 제목 크기·배경·경로 버튼을 맞췄다.
- 현재 위치와 준비된 원정 목록을 한 줄로 묶었다. 원정 목록은 눌러 펼치며, 화면 갱신에도 펼친 상태를 유지한다.
- 액트 이름은 17px, 보조 정보는 12px로 표시한다. PC는 최대 두 열, 좁은 영역은 한 열을 사용한다.
- 액트의 다음 진행 지역과 즉시 이동을 배너 안으로 합쳤다. 동일한 다음 지역을 별도 카드로 반복 표시하지 않는다.
  모바일 393×851 화면에서 첫 액트 카드가 종전 수정본보다 약 60px 위로 올라왔다.
- 보스 목록의 첫 분류는 실제 입장 가능한 보스다. 미격파 보스를 먼저 표시한다.
  선행 조건이나 입장권이 부족한 보스는 기존 종류별 접힌 분류로 남겨 찾을 수 있게 했다.
- 동일한 보스가 입장 가능 목록과 준비 목록에 중복되지 않는다. 루프 준비 등 이동 제한도 반영한다.
- 현재 싸우는 보스는 전투로 돌아가기만 수행한다. 입장권 소비나 전투 재시작을 하지 않는다.
- 보스 목록의 내용이 동일하면 DOM을 다시 만들지 않는다. 내용이 바뀌어도 남아 있는 버튼의 키보드 포커스를 복원한다.
- 세부 콘텐츠 진입 직후 목적지 선택값이 이전 화면을 가리키던 갱신 순서를 수정했다.

## 유지한 계약

- 액트 순서, 콘텐츠 해금, 보스 선행 조건·입장권·보상, 전투 계산과 저장 형식은 변경하지 않았다.
- 보상 받기/완료는 왼쪽, 이동은 오른쪽이다. 새 아이콘이나 화살표는 추가하지 않았다.
- 시련 안내의 두 줄기 테두리 빛과 reduced-motion 대체 표현을 유지한다.
- 기존 UI의 입장 가능 상태와 지도 요약 함수를 재사용한다. 새 전역·타이머·캔버스 작업은 없다.
- 실제 게임 소스에 반영했으며, artifacts/world-tree-journey는 같은 소스를 저장 분리 상태로 사용한다.
- PR 생성이나 공개 배포는 수행하지 않았다.

## 검증

- 실제 브라우저: 1048×742, 1280×720 PC 화면과 393×851 모바일 화면.
- Playwright: exploration-regions + mobile-map-navigation 12개 통과(기존 10개 및 원정 펼침/포커스 추가 검사 2개).
  최초/후반 해금, 보상 오버레이 실제 수령, 무료 시련, 보스 조건·입장권,
  이동 제한 시 목록 변경, 목록 중복 방지, 포커스 복원, 보스 복귀 무소모, 원정 펼침 유지까지 포함한다.
  원정 추가 검사의 최초 실패는 테스트가 탐험 화면을 열지 않은 준비 누락이었다. 실제 전체 탐험 버튼을 누른 뒤 검사하도록 수정해 PC/모바일 모두 통과했다.
- 전체 스모크: `npm test` 190/190 통과.
- 최종 `npm run check:architecture`: runtime architecture/lint ratchet 통과.
- 변경 파일 문법 및 diff 공백 검사 통과.
