# 도트 UI 통일 + 디아블로 2 향 (2026-09-29)

전장(한 칸 16도트)은 도트인데 UI는 매끈한 벡터 틀·명조 글꼴이라 따로 놀던 것을 도트 결로 맞췄다.
디아블로 2 느낌은 "살짝"만: 돌판 재질, 청동 테와 금빛 징, 금빛 제목, 생명 구슬, 물약 허리띠.

## 무엇이 바뀌었나

| 부분 | 전 | 후 |
|---|---|---|
| 글꼴 | IBM Plex Sans KR · Song Myung · Cinzel | 물마루(12px 격자, UI 전반) · 갈무리14(15px, 긴 글) · DOS새물(16px, 제목, 겹쳐 찍기 굵게) |
| 모서리·그림자 | 둥근 모서리, 흐린 그림자·빛 번짐 | 각진 모서리, 흐림 없는 도트 그림자(4px 어긋남) |
| 창·대화 상자·HUD 판 | 1px 선 + 그라디언트 | 청동 도트 테(border-image 9칸 자르기, 한 도트 = 2px) + 돌판 체크 무늬 |
| 하단 HUD | 장식 그림 틀 + 가로 체력 막대 | 돌판 왼쪽의 **생명 구슬**(아래에서 위로 참, 에너지 보호막은 파란 막) · 이름/레벨 · 물약 허리띠 · 경험치 막대 · 젬 칸 |
| 대상 적 체력바·미니맵 | 장식 그림 틀, 둥근 고리 | 도트 막대(보스는 무거운 테), 네모 틀 둘레가 탐험 비율만큼 금빛 |
| 로고 | 붓글씨 원화 | 같은 로고를 52도트(메뉴 레일)·120도트(시작 화면)로 다시 찍은 것 |
| 장비·젬·재화 아이콘 | 원화 | 32도트 사본(짧은 변 32·긴 변 48도트, 1도트 윤곽) — 설정 "아이콘 그림"에서 원화로 되돌릴 수 있다 |
| 전장 캔버스 글자 | 명조·맑은 고딕, shadowBlur | 도트 글꼴, 한 도트 그림자 (보스 등장·레벨업·정예 이름표·전리품) |

도트 글꼴은 제 크기(물마루 12·갈무리 15·DOS새물 16과 그 배수)에서만 또렷하다. 8~11px로 줄어 있던 글자는 12px로 올렸고,
한글은 단어 중간이 아니라 띄어쓰기에서 끊는다(`word-break: keep-all`).

## 파일

| 파일 | 하는 일 |
|---|---|
| `css/themes/pixel.css` | 글꼴·모서리·도트 판(창·대화 상자·툴팁·기록·레일·시작 화면)·버튼·입력·작은 글자 |
| `css/themes/pixel-hud.css` | 전투 화면: 생명 구슬 HUD, 물약 허리띠, 젬 칸, 대상 적 체력바, 미니맵, 지역 줄 |
| `css/themes/pixel-mobile.css` | 휴대폰: 지역 줄·귀환/목표 버튼·전투 기록 막대·하단 메뉴·메뉴 서랍·목표 서랍 |
| `css/themes/pixel-menu.css` | 메뉴: PC 하단 HUD에 담긴 메뉴(둥근 소켓·이름표·기타 목록), 휴대폰 하단 메뉴 띠(HUD와 한 판)·서랍 아이콘 |
| `scripts/build-pixel-ui.cjs` | 테(무거운·가벼운·오목)·둥근 테(구슬·미니맵·메뉴 소켓, 1px 도트)와 구멍 가면·물약 병/액체·메뉴 아이콘 줄·도트 로고를 코드로 찍어 `assets/ui/pixel/`에 쓴다 |
| `scripts/pixel-menu-icons.cjs` | 메뉴 아이콘 21개(13×13 도트 글자 그림). 순서가 CSS `--px-icon` 번호 |
| `scripts/build-pixel-icons.cjs` | 원화 아이콘을 도트 사본으로 `assets/px/`에, 목록을 `data/pixel-icons.js`에 쓴다(Playwright Chromium 사용) |
| `js/utils.js` `pixelIconPath` | 사본이 있으면 도트 경로로. 장비·인벤토리·젬·재화 아이콘 해석 함수가 이를 거친다 |
| `js/icon-art-ui.js` | 설정 "아이콘 그림"(도트/원화) |

네 CSS는 `@layer overrides`의 맨 끝(css/main.css 마지막 import)이라 스킨(rift 등) 위에 얹힌다.
구슬은 기존 막대와 같은 `--gauge-fill`(js/ui.js `setUiImageGaugePercent`)을 세로 `clip-path`로 읽으므로 스크립트는 그대로다.

## 다시 만들기

```bash
node scripts/build-pixel-ui.cjs       # 테·구슬·물약·로고 그림을 바꿨을 때
node scripts/build-pixel-icons.cjs    # 원화 아이콘을 추가·교체했을 때(사본과 data/pixel-icons.js 갱신)
```

`npm test`의 `smoke-pixel-icons`가 사본 누락·크기·도트/원화 전환을 검사한다(원화를 새로 넣고 사본을 안 만들면 실패).

## 알림 자리 (2026-09-29 추가)

- **새 콘텐츠 카드**(`#tutorial-overlay`): PC는 플레이어 HUD(생명 구슬·정보 판) 바로 위 가운데
  (`placeTutorialCard`, `js/tutorial-ui.js`). 전투 로그·미니맵을 가리지 않는다. 옆에 붙은 창(장비·스킬 등)이 열려 있으면
  창을 덮지 않도록 왼쪽 빈 전장으로 비켜선다(자리가 없으면 HUD 위 그대로). 휴대폰은 하단 메뉴 위 시트 그대로이고
  확인 · 화면 열기를 한 줄에 놓아 높이를 줄였다(세로로 쌓으면 화면 아래 1/3을 덮었다). 안내가 떠 있는 동안 전투는
  기본값으로 멈춘다(`settings.pauseGameOnOverlay`).
- **DPS 변화**: 공용 알림(PC 오른쪽 위 = 미니맵·창 닫기 단추 위, 휴대폰 아래 = 생명 구슬 위) 대신 생명 구슬 바로 위의 작은
  도트 칩(`.build-dps-chip`, `js/build-feedback-ui.js`). 휴대폰에서 구슬 위에 전투 로그 줄이 있으면 그 위, 구슬이 안 보이는
  화면(장비 탭 등)에서는 하단 메뉴 위 가운데, 새 콘텐츠 카드와 겹치면 카드 위에 뜬다.
- **공용 알림**(`#game-toast-region`, 2026-09-30 손질): 자리는 그대로(PC 오른쪽 위, 휴대폰 아래)이고 모양만 바꿨다.
  도트 돌판을 반투명하게(뒤 전장·미니맵이 비친다), 왼쪽 띠와 표시 색이 종류(정보 금 · 성공 초록 · 경고 호박 · 위험 빨강),
  폭 330px로 좁게. **누르면 바로(0.09초) 사라진다.** 휴대폰 전투 로그 알림(`#mobile-toast-root`, `showNextMobileToast`)도
  같은 모양이고 누르면 바로 다음 알림으로 넘어간다. 휴대폰에서는 두 알림이 겹치지 않게 공용 알림을 로그 알림 위로 쌓고
  가장 최근 두 개만 보인다. 안내 카드가 떠 있는 동안 휴대폰 로그 알림은 기다렸다가 카드가 닫히면 나온다(카드 단추를 덮었다).

## 안내 카드 (2026-09-29 추가)

`js/tutorial-ui.js` · 스타일 `css/ui-game-overhaul.css`(카드는 components, 메뉴 단추 깜빡임은 overrides).

- **머리말로 종류를 가른다**(`tutorialNoticeKind`): 처음 하는 조작은 `시작 안내`(이끼색), 새로 열린 콘텐츠는
  `새 콘텐츠`(금색), 루프 도달은 `새 루프`(보라). 예전에는 전부 "새 콘텐츠"였다. 이야기 장면은 그대로.
- **본문**(`tutorialBodyHtml`): 첫 줄은 무슨 일이 생겼는지, 나머지 줄은 할 일 목록(도트 점). 따옴표로 시작하는 줄이
  있으면 목록 대신 문단으로 둔다. 문구를 쓸 때는 줄마다 한 가지만 말한다.
- **단추 이름**: 조작 안내가 있으면 `따라 해보기`, 없으면 `○○ 열기`(`TUTORIAL_TAB_NAMES`, 메뉴 이름과 같게).
- **다음 안내 N**: 뒤에 기다리는 카드 수를 카드 오른쪽 위에 적는다(이야기 장면에서는 숨김).
- **메뉴 단추 깜빡임**(`setTutorialCallout`): 카드가 가리키는 화면의 메뉴 단추에 금빛 테. 단추가 기타(PC)·전체(휴대폰)
  메뉴 안에 있으면 여는 단추와 메뉴 속 단추 둘 다. `확인`으로 닫아도 6초 동안 남는다. 움직임 줄이기 설정이면 깜빡이지
  않고 테만 둔다.
- **액트 제목과 겹치지 않는다**: 이야기 장면이 아닌 카드는 액트 제목(`actTitleCard.busy()`)이 떠 있거나 뜰 차례면
  기다린다. 제목은 전장 시계로 흐르므로 전장이 실제로 그리고 있을 때만 기다린다(전장이 안 보이면 막지 않는다).
- **새 캐릭터의 첫 조작**(`queueStarterGuides`, 루프 1만): 탭이 처음부터 열려 있어 예전 "스킬트리 개방"·"장비/제작 개방"
  카드가 뜨지 않으면서 그 카드에 달린 따라 해보기도 사라져 있었다. 레벨 2에서 `첫 패시브 포인트`, 첫 장비를 주우면
  `첫 장비` 카드를 띄우고 예전 안내를 이어 붙인다. 예전 카드를 본 세이브는 다시 띄우지 않는다.
- 시작 순서: 프롤로그 → 액트 1 이야기 → 액트 제목 → `첫 여정` → `첫 스킬 젬 장착` → (레벨 2) `첫 패시브 포인트`
  → (첫 장비) `첫 장비`.
- **글 색**(2026-09-30): 본문의 `‘메뉴·단추’`는 카드 종류 색(어디로 갈지), `[이름]`은 하늘색(무엇인지)으로 칠한다
  (`tutorialMarkup`). 카드 위 테 아래에 종류 색 가는 줄. 문구를 쓸 때 메뉴·경로는 ‘…’, 아이템·젬 이름은 […]로 감싼다.
- **액트 제목**(2026-09-30): "액트 N"과 액트 이름만. 한 줄 부제는 목표 창과 같은 말이었고 PC에서는 목표 창, 휴대폰에서는
  미니맵 밑으로 들어갔다. 부제는 액트 클리어 보상 창에는 그대로 남아 있다.

## 새 콘텐츠 카드 (2026-09-30)

콘텐츠 대부분이 해금 창에서 사서 열리게 바뀐 뒤로, 사도 "○○ 해금" 알림 한 줄뿐이었다. 예전 해금 카드는 사기 전에
떠서, 아직 열 수 없는 창을 가리킨다는 이유로 보이지도 않고 사라졌다(대기열이 넣는 순간 '본 것'으로 적는다).

- **콘텐츠마다 카드 한 장**(`contentUnlockUi.announceContent`, `js/content-progression-ui.js`): 제목은 콘텐츠 이름,
  첫 줄은 해금 목록의 설명(`CONTENT_UNLOCK_CATALOG.description`), 둘째 줄은 `‘장비 → 거래소’에 있습니다`
  (`CONTENT_ROUTE_PATHS`, 메뉴 이름 그대로). 단추 `○○ 열기`는 하위 탭·탐험 목록까지 정확히 연다(`openTutorialTarget`).
  - 산 콘텐츠: 사는 순간. 같이 열리는 무료 콘텐츠(장비 제련 → 거래소·장비 전당)도 한 장씩.
  - 무료 콘텐츠: 루프·조건에 닿아 처음 열린 순간(`checkUnlocks`의 `syncOpened`). 불러온 저장에서 이미 열려 있던 것은 알리지 않는다.
  - 자기 카드가 따로 있는 콘텐츠(`CONTENT_CARD_DEDICATED`: 그루터기 함·생장판·시간의 균열·코어 큐브·혼돈계·창공·지하계·
    우주계·심해·낚시·경계 너머·운석 낙하 지점)와 루프 1 기본 콘텐츠는 카드를 따로 만들지 않는다.
- **사기 전에 뜨는 안내**(`queueContentNotice`, `js/state.js`): 봉인된 카드 발견·재능 개화·전문가 조우·첫 고유 장비·첫 나이테·
  주얼·직업전직처럼 해금에서 사야 하는 콘텐츠의 안내는, 아직 사지 않았으면 "‘해금’에서 ○○을 열면 …"이라 쓰고 해금 창을
  가리킨다. 이미 샀으면 그 화면을 가리킨다.
- 남은 카드 문구 35개도 같은 형식으로 고쳤다. 틀린 곳도 바로잡았다: 대균열 단추는 `대균열 입장`, 생장판 카드는 플라스크 창이
  아니라 `보조장비 → 생장판`, 버려진 날붙이 결투는 `지도 → 탐험 → 강대한 적`, 직업 탭 이름은 `직업전직`.
- 검사: `scripts/smoke-content-unlock-cards.js`.

## 하단 HUD (2026-09-30)

디아블로 계열 하단 바처럼 **왼쪽 생명 구슬 · 가운데 미니맵 · 오른쪽 경험치 구슬**, 그리고 PC는 **메뉴도 이 바 안에** 있다.
둥근 셋이 낮은 돌판 위로 솟고, 장식은 창과 같은 청동 테 하나뿐이다(뿔·기둥 같은 장식은 넣지 않는다).
스타일: `css/themes/pixel-hud.css` 끝 부분(HUD) · `css/themes/pixel-menu.css`(메뉴). 그림: `scripts/build-pixel-ui.cjs`.

- **둥근 테는 1px 도트**: 구슬·미니맵·메뉴 소켓만 화면 크기 그대로(한 도트 = 1 CSS px) 찍는다. 2px 도트로 찍은 작은 원은
  계단이 굵어 팔각형처럼 찌그러져 보였다. 색은 여전히 몇 단으로 끊어 칠하고(그라데이션 없음), 빛은 왼쪽 위에서 둘레를 돌며
  다섯 단으로 바뀐다(대각선에서 밝음/어둠이 딱 갈리던 자리가 찌그러짐처럼 보였다). 그림: `orb-ring-96/68` · `orb-hole-96/68`,
  `map-ring-136/100` · `map-hole-136/100`, `key-socket(-on)`(40px). 네모 틀·아이콘은 그대로 2px 도트.
- **PC 배치**: [생명 구슬] [플라스크] [정리 · 메뉴 날개] [미니맵] [메뉴 날개 · 기타] [젬] [경험치 구슬] 한 줄, 양쪽 칸 폭이 같아
  미니맵이 바 한가운데 온다. 균열(기본) 스킨은 바가 화면 가운데 기준으로 넓게 펴져 주인공 · 대상 적 체력바와 같은 세로축에 서고,
  전투 기록은 바 위로 올라간다. 다른 스킨은 전투판 아래에 그대로.
- **메뉴**: 왼쪽 기둥 레일(`#tab-header-main`)을 `js/ui-window-manager.js`의 `dockRailIntoHud`가 HUD 돌판 안으로 옮기고,
  탭을 미니맵 양옆 두 날개(`.ui-rail-tab-layer` 둘)에 고르게 나눠 싣는다(`spreadRailWings`, 순서는 설정의 메뉴 순서 그대로).
  날개 한 줄에 못 들어가는 탭은 예전처럼 **기타**로 간다. 날개 폭이 바뀌면(젬·플라스크 칸 수, 화면 폭) 다시 나눈다.
  단추는 둥근 청동 소켓 + 13도트 금빛 아이콘, 열린 창은 금빛 테. 이름(과 단축키)은 올려 두면 위에 뜬다. 로고는 PC 전투 화면에서 뺐다.
  휴대폰으로 바뀌면 레일을 원래 자리로 되돌린다.
- **창**: 관리 창의 작업 영역은 HUD 윗변(솟은 미니맵 포함) 위까지만이라 창을 열어도 메뉴 단추가 가려지지 않고 흐려지지 않는다.
  HUD는 레일이 있던 층(z-index 1500)이라 기타 목록·이름표가 창 위에 뜬다.
- **아이콘**: `scripts/pixel-menu-icons.cjs`(13×13 도트 21개, 금빛 3단) → `menu-icons.png` 한 줄. CSS는 버튼마다 `--px-icon` 번호로 고른다
  (아이콘을 더하면 `--px-icon-count`도 맞춘다). 휴대폰 하단 메뉴 · 전체 메뉴 서랍 · PC 기타 목록이 같은 아이콘을 쓴다.
- **생명 구슬 글자**: 현재 생명(위) · 가는 금 · 최대 생명(아래) 두 줄. 한 줄("87.0/98")이면 휴대폰 구슬에서 테에 걸쳤다.
  PC는 경험치 구슬(레벨 15px · 퍼센트 12px)과 짝을 맞춰 현재 생명이 갈무리 15px.
- **미니맵**: 둥근 청동 테 안쪽 홈에 탐험 비율이 금빛 호로 찬다. 지도는 테 구멍 모양으로 잘리고, 아래 "지도" 단추로 크게 본다.
- **경험치 구슬**: 경험치 막대(`.combat-exp-bar`)를 생명 구슬과 같은 유리·테로 그리고, 같은 `--gauge-fill`을 세로로 읽어
  금빛 액체가 아래에서 위로 찬다(스크립트 변경 없음). 레벨(`#ui-exp-level-label`)과 퍼센트는 구슬 안에.
- **휴대폰**: HUD 판과 하단 메뉴 띠가 한 판이다(전투 화면에서 HUD는 아래 테를, 메뉴 띠는 위 테를 빼고 가는 금 한 줄로 나눈다).
  메뉴 칸은 아이콘 위 · 이름 아래, "가득 참"은 아이콘 위에 도장처럼 겹친다. 다른 탭에서는 메뉴 띠만 온전한 테.
  HUD는 바로 위가 접힌 전투 기록이라 둥근 셋이 솟지 않고 판 안에 앉는다(이름과 직업은 두 줄).

## 그대로 둔 것

- 이야기 삽화(프롤로그·저널), 시작 화면 배경 그림, 패시브 트리 노드 그림, 상태 이상 아이콘 묶음은 원화 그대로.
- 구글·카카오 로그인 버튼은 각 사 표기 규정대로 원래 글꼴.
- Windows 데스크톱은 글자에 서브픽셀 안티앨리어싱이 걸려 확대하면 글자 가장자리에 색 번짐이 보인다(1배에서는 티 나지 않음).
