# 실제 게임 넓은 맵 탐험 이관

## 현재 적용 상태 (2026-09-23)

일반 액트 1~10의 새 전투 진입은 실제 게임에서 넓은 맵을 기본으로 사용한다. 기존 저장의
진행 중 웨이브는 그대로 마친 뒤 다음 진입부터 전환한다. 아래 날짜별 기록의 opt-in 설명은
당시 단계의 기록이며, 최신 동작은 마지막 「기본 진입과 자동 진행」 절을 따른다.
특수 콘텐츠는 기존 전장을 유지한다. 전리품 일괄 연출은 연결했고, 액트 1~6의 전용 미술을 연결했다.
액트 7~10의 전용 미술과 일반 성장 캐릭터의
밸런스/성능 검증이 남아 있으므로 전체 목표 완료 또는 배포 완료를 의미하지 않는다.

## 목표와 완료 기준

승인된 act1-biome 프로토타입을 실제 게임의 일반 액트 진행에 연결한다. 액트 1~10은
각기 다른 프리셋 지형을 갖는다. 카메라/보행/판정 일치와 오브젝트 깊이 정렬을 공통화하고,
특수 콘텐츠의 고유 출현/진행 규칙은 보존한다. 프로토타입만 갱신한 상태는 완료가 아니다.

- 일반 액트: 넓은 연결 지형, 발견 안개와 미니맵, 직접 이동/보스 직행/전체 탐색.
- 몬스터 사전 배치와 저장, 가까운 적만 전투 계산. 정예 처치로 단일 보스 입구 해제.
- 액트 4의 연속 보스 등 기존 스토리/해금/액트 보상 흐름 유지.
- 임시 전리품은 보스 클리어 후 정확히 한 번 지급. 사망/중도 포기는 미정산 보상 소멸.
  지역 변경 시 손실 확인, 인벤토리 초과 보호, 연출 생략과 보상 지급 분리.
- 기존 저장 마이그레이션, 재접속의 적/안개/이동/정산 상태 보존. 전투 경험치는 기존 지급.
- 자동 다음 지역/재도전/중지와 방치 정산이 같은 진행 규칙을 사용.
- 대균열, 벌집, 시련, 계별 전투의 기존 전용 진행은 회귀 검사로 보호.
- 실제 게임 브라우저 플레이, 10개 액트 경로/전투/저장 검사, 스모크 및 구조 검사.

## 모듈 경계

`data/act-exploration-maps.js`는 정적 프리셋만 소유한다.
지형 컴파일/탐색은 순수 도메인 모듈이 맡으며 전투나 DOM을 호출하지 않는다.
런타임은 기존 createEnemy/전투/드랍/진행 함수를 호출하는 상위 오케스트레이터로 연결한다.
렌더러는 상태를 읽기만 하고, UI가 이동/모드/포기 명령을 도메인에 전달한다.
별도의 전투 계산 복제나 프로토타입 전역 함수 덮어쓰기 방식은 실제 게임에 이식하지 않는다.

## 작업 기록

현재 9×8 크기 고정, 일반 진행률 기반 스폰, 지역 이동 시 전투 초기화와 저장 좌표 제한을
함께 변경해야 한다. 구현/검증 완료 항목은 증거가 생길 때 기록한다.

### 기반 구현 완료, 전체 이관은 미완료

- `data/act-exploration-maps.js`: 10개 수작업 프리셋. 회전한 지형도 포함한다.
- `js/act-exploration-map.js`: 캐시된 지형 컴파일, 경로 검색, 지형을 따르는 발견 범위.
- `getCombatGridSize(state)`를 그리드 경계/배치/광역 판정/직선 투사체/범위 렌더링에 연결했다.
  일반 실행의 `game.actExploration`은 아직 null이다. `startEncounterRun(true)`로 실제 적 생성과
  탐험 저장 상태를 준비할 수 있지만, 렌더러와 정산 연결 전까지 자동으로 활성화하지 않는다.
  최종 전환 시 이 임시 검증용 인자를 제거하고 일반 액트의 기본 진입으로 옮겨야 한다.
- 특수 콘텐츠와 별도 방치 계산 snapshot은 서로의 크기를 변경하지 않는다.
- `smoke-act-exploration-maps.js`: 10개 모두 전체 바닥 연결, 정예 접근, 보스 관문 우회 불가,
  선택 방 영역을 통째로 막아도 주요 진행 가능, 시작 안개 확인.
- `smoke-exploration-grid-bounds.js`: 10개 크기, 2×2 경계, 빈 칸 탐색, 특수 전장과 replay 분리.
- 로드 순서 검사 통과. 기존 브라우저 프로토타입 재접속/완료 화면 정상, 신규 콘솔 오류 없음.

### 이어서 진행할 실제 연결 지점

1. 임시 보상/정산 소유 모듈: 장비와 재화 외에도 보조 젬 단계, 아르카나, 플라스크 발견,
   주얼/생장 아이템 등 `rollLootForEnemy`의 직접 지급 경로를 모두 확인해 포획해야 한다.
   경험치는 처치 즉시 지급한다. 정산 id/사망 손실/초과 수령은 아직 연결 전이다.
2. `combat.js`: startEncounterRun에서 지형/적 준비, advanceMapProgress에서 탐험 전진,
   coreLoop의 기존 100% 완료 조건을 새 던전 완료 조건과 연결. startMoving/handlePlayerDefeat의
   임시 보상 처리, finishEncounterRun의 기존 해금/진행/액트 보상 보존.
3. `combat-grid.js`: 지형/봉인/대기 적 점유 추가. 공통 보행 위치와 실제 칸 판정 분리,
   일반 공격 시작 조건 수정. 전용 순간이동은 일반 보행과 구분한다.
4. 캔버스/UI: 맵별 지형/에셋, 캐릭터 추적/안개/미니맵, 사전 배치 적, 관문 깊이 정렬.
   기존 9×8 전장의 UI/공격 예고가 깨지지 않도록 분기.
5. 온라인/방치 계산에 같은 전투/진행을 사용. 준비되지 않은 동안 무조건 옛 방식으로
   정산하는 우회 구현을 완료로 간주하지 않는다.

현재 넓은 맵 실제 진행, 보상 정산, 저장 이관, 10개 액트의 시각 표현은 아직 작업 대상이다.

### 적 배치와 저장 계약 연결 (2026-09-22)

- `act-exploration-state.js`: 실제 createEnemy 결과를 waiting과 game.enemies 중 정확히 한 곳에서
  소유한다. 발견 시 참조를 전투 배열로 옮기고 다시 추첨하지 않는다. 지형/발견/목적지,
  적별 체력·좌표·타이머, 무리별 생존 id, 정예 id, 보스 단계가 저장에 포함된다.
- `startEncounterRun(true)`는 일반 액트에서만 준비 가능하다. 보스는 한 단계당 1명이며
  액트 4는 기존 STORY_ACTS의 두 보스를 미리 준비해 순차적으로 전투에 들어간다.
- `handleEnemyDeath`에 실제 처치 추적을 연결했다. 중복 처치는 정예 수를 다시 줄이지 않는다.
  전체 탐색은 일반/곁가지 적이 남으면 보스 목적지보다 우선한다.
- 그리드 배치/이동의 공통 유효성 검사에 바닥과 봉인 관문을 연결했다. 대기 적도 칸을 점유한다.
- 탐험 저장에서는 기존 9×8 좌표 clamp를 적용하지 않는다. 맵 바깥/중복·누락 적/잘못된 완료
  상태는 저장 경계에서 명시적으로 거절한다. 입력 저장의 탐험 객체를 직접 변경하지 않는다.
- 클라우드의 두 직렬화 경로가 기존에는 적과 일부 전투 상태를 지웠다. 탐험 중에는 실제 적,
  시전/지속효과/보호막/대기 타격을 유지하며, 기존 작은 전장에서는 종전 정책을 유지한다.
- `smoke-act-exploration-state.js`: 10개 실제 액트 적 생성/가시 범위 전투 편입/실제 사망 처리,
  정예 관문, 순차 보스, 로컬 및 두 클라우드 저장 경로, 손상 저장 거절을 검사한다.
- 전체 스모크 203/203 통과 (`artifacts/act1-biome/smoke-act-state.log`).
  기존 act1-biome 브라우저의 재접속/완료 화면 정상; 새 런타임 오류 없음.
  격리 페이지의 기존 Supabase 미로딩 경고는 클라우드 연결을 하지 않는 검증 구성 때문이다.

남은 필수 연결: 실제 coreLoop의 탐험 이동/완료/자동 다음 지역, 임시 전리품, 사망·포기,
큰 맵 캔버스·카메라·보행 시간, 10개 바이옴 자산, 실제 브라우저 전 과정과 방치 재생 검증.

### 실제 전투 루프의 탐험 진행 검증 (2026-09-22)

- `act-exploration-progress.js`가 기존 `coreLoop`에 이동 목적지, 발견된 적 편입, 완료 조건을
  제공한다. 공격/피해/경험치/처치 계산은 기존 전투 함수가 수행한다.
- 직행은 정예와 보스를 우선하고 전체 탐색은 일반/곁가지 적을 모두 처리한다. 직접 이동은
  발견한 바닥 목적지에서 멈춘다. 진행 복구 코드가 빈 encounterPlan을 새 전투로 바꾸지 않는다.
- 보스 완료를 한 번만 기존 스토리 진행에 전달한다. 액트 4의 두 보스는 한 탐험에서 순차
  처리한다. 중지 설정으로 완료 맵에 남았을 때 살아 있는 곁가지 적의 저장 소유권을 유지한다.
- `smoke-act-exploration-progress.js`: 실제 coreLoop로 10개 액트 각각 직행/전체 탐색을 끝까지
  진행하고 중간 저장 복원, 직접 이동, 완료 후 반복 호출/저장 복원을 검증했다. 경로 검사를
  위한 합성 고성능 장비를 사용했으므로 정상 성장 캐릭터의 난이도 검증은 아니다.
- 전체 스모크 204/204 통과 (`artifacts/act1-biome/smoke-act-progress.log`). 기존 프로토타입의
  새로고침/완료 상태 복원 정상, 브라우저 신규 오류 없음. 이 브라우저 결과를 신규 실제 액트
  화면 검증으로 간주하지 않는다.

아직 일반 액트는 기본 활성화하지 않았다. `startEncounterRun(true)`의 명시적 검증 진입만
새 진행을 사용하며, 다음 액트/재도전 기본 진입 전환은 렌더러와 보상 정산 완료 후 수행한다.
실제 게임 전체 적용의 완료를 선언하지 않는다. 다음 필수 작업은 다음과 같다.

1. 임시 전리품 포획/정산, 사망/지역 이탈 시 손실과 확인, 수령 초과 보호.
2. 저장 가능한 연속 보행과 칸 판정, 동일 위치를 읽는 카메라/캐릭터 렌더링.
3. 10개 액트 지형/안개/미니맵/관문 깊이 표현과 실제 게임의 조작 UI.
4. 일반 액트 기본 진입 및 반복/다음 액트 연결, 방치 재생, 성장 캐릭터 플레이 검증.
5. 넓은 맵의 벽을 사이에 둔 공격, 이동 스킬/소환/함정 탈출도 지형과 봉인을 준수하는지
   확인한다. 현재 작은 전장의 모든 특수 이동을 탐험 지형에 맞춰 검증한 상태는 아니다.

공통 함정 회피 검토에서 `findNearestSafeGridRoute`가 경계/점유만 검사해 벽을 안전 칸으로
선택하는 문제가 재현됐다. 기존 `canPlaceGridFootprint`를 사용하도록 고쳐 지형·봉인·유닛
크기를 함께 검사한다. 10개 지형에서 전체 바닥이 위험할 때 벽으로 도주하지 않고 제자리에
남는 회귀 검사가 수정 전 실패/수정 후 통과한다. 일반 그리드와 컨디션 검사도 통과했다.

실제 시작 경계인 `recoverRuntimeState`에서도 빈 encounterPlan 때문에 탐험을 초기화하는
문제가 재현됐다. `main.init`과 복구 경계 모두 기존 `ensureEncounterRun` 도메인 계약을
호출하도록 통일했다. 진행 검사는 단순 역직렬화뿐 아니라 이 UI 복구 경계를 통과해 남은 적과
발견 지도가 그대로 유지되는지 확인한다.

### 연속 보행, 실제 렌더러와 지도 UI 연결 (2026-09-22)

- `act-exploration-motion.js`가 보행 시작/진행/취소/복원 계약을 소유한다. 칸 경계를 넘는
  중간 시점에 피격 판정 좌표가 바뀌고, 카메라와 캐릭터는 같은 소수 좌표를 읽는다.
  일반 공격은 보행을 끊지 않으며 전용 순간이동은 대기 보행을 취소한다.
