# 전투 진입 에셋 로딩

2026-09-08

- 기존에는 전투 이미지 242개(49.27 MiB)가 모두 끝나야 진입했다. 큰 스킬 전용 시트 19개 중 현재 공격 스킬의 시트만 우선 로딩한다. 캐릭터·적·공용 공격 이미지는 기존 준비 단계에서 완료한다.
- 미사용 전용 이펙트는 기존 이미지 키의 지연 접근자로 등록한다. 스킬 HUD의 장착 목록이 바뀌면 해당 시트를 요청하며, 렌더러가 직접 사용할 때도 요청된다. 별칭·반복 접근은 하나의 요청과 디코딩 이미지를 공유한다. 새 로딩 세대는 별도 이미지 뱅크를 사용하여 이전 요청이 새 뱅크를 덮지 않는다.
- 실패한 요청은 5초 후 다시 시도할 수 있으며, 15초 동안 끝나지 않는 요청도 재시도 가능 상태로 돌아간다. 실패는 경고 로그로 남고 전체 게임 진입을 막지 않는다. 아직 로딩 중인 전용 스킬은 기존 렌더러의 미로딩 동작을 유지한다.
- 이펙트 PNG 50개의 무손실 WebP 사본은 32.82 → 26.45 MiB다. 원본/결과를 RGBA로 디코딩해 모든 픽셀과 크기가 동일함을 확인했다. PNG는 편집·기존 시연 도구의 원본으로 보존하고, 전투 로더만 같은 이름의 WebP를 사용한다. 새 이펙트 추가 시 대응 WebP를 함께 만들어야 하며 스모크가 누락을 검출한다.
- PNG 수정 후 Pillow가 설치된 Python으로 `python scripts/compress-battle-effects.py`를 실행한다. 원본과 결과의 픽셀 일치를 검증하고 해시 증명을 갱신한다. 스모크는 양쪽 해시를 확인하여 원본만 수정하고 압축본을 갱신하지 않은 배포도 차단한다.
- 스크립트 순서에 `battle-asset-loading.js`를 추가했다. 함수는 에셋 준비 시점에 호출하며, 기존 저장 형식·전투 계산·이펙트 판정과 그림을 변경하지 않는다. HTTP 캐시/서비스 워커의 업데이트 정책도 유지한다.

측정: 새 Chromium 컨텍스트, 캐시 비활성, 20 Mbps/지연 40 ms 조건에서 전투 로더만 실행했다. 기존 코드와 변경 코드는 같은 서버·설정으로 각각 측정했으며 반복 측정의 통계치는 아니다.

| 기본 공격 캐릭터 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 진입 대기 이미지 | 242 | 223 |
| 이미지 응답 본문 | 49.27 MiB | 22.39 MiB |

실제 네트워크·기기·현재 공격 스킬에 따라 달라진다. 로그인/저장 복원/방치 계산 시간은 이 측정에 포함하지 않는다. 첫 방문하는 스킬의 다운로드는 필요하며 장착 시 미리 요청한다.
