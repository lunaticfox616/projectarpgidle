# 전투 진입 에셋 로딩

## 현재 소유 경계 (2026-11-12)

이미지 URL 목록은 `modules/browser/battle-image-manifest.mjs`, 요청 큐·준비 상태·이미지 은행은
`battle-asset-startup.mjs`, 별칭 공유·지연 로딩은 `battle-asset-loading.mjs`가 소유합니다.
입력 데이터와 Image·시계·타이머·화면 콜백은 바깥 어댑터가 연결합니다. 생성 시에는 요청하지 않습니다.

`modules/battle-assets-classic.mjs`와 남은 픽셀/아틀라스 조각을 빌드한 `js/canvas-battle-assets.js`가
이전 전투 이미지 파일의 로드 자리를 대체합니다. 별도 `js/battle-asset-loading.js` 스크립트와 그 전역 함수는
소비자를 모듈 import로 바꾸고 제거했습니다. 이미지 목록을 편집할 때 생성 파일을 직접 고치지 않습니다.
스킬 효과 편집기·`scripts/compress-battle-effects.py`도 같은 원본 목록을 읽습니다.

`initBattleAssets()`의 중복 호출은 같은 준비 Promise와 이미지 은행을 공유합니다. 저장을 다시 불러와도
은행을 새로 만들지 않습니다. 선택 자산 실패는 진행을 막지 않고, 필수 실패 키·아틀라스 실패는 기존 방식으로 기록합니다.
최종 부팅 전환의 종료 경계에서 `initBattleAssets.dispose()`를 호출하면 준비 대기는 `false`로 끝나고,
콜백·지연 타이머·은행·아틀라스 참조가 해제됩니다. 늦게 도착한 응답은 반영하지 않습니다. 종료 뒤에는 새 인스턴스가 필요합니다.

2026-11-12: 구 구현과 준비 행동 95건, 스킬 효과 편집기 44개와 압축 대상 42개의 경로를 비교했습니다.
전체 스모크 20개·구조·DB·언어 검사 및 실제 PC/모바일 크기 Chromium의 이미지 디코딩·방 진입·저장 복원을 통과했습니다.
실물 휴대전화·전체 게임 분기 검증은 아닙니다. 아래 수치는 과거 성능 측정이며 이번 구조 변경의 속도 향상 수치가 아닙니다.

## 이전 구현과 측정 (2026-09-08)

- 기존에는 전투 이미지 242개(49.27 MiB)가 모두 끝나야 진입했다. 큰 스킬 전용 시트 19개 중 현재 공격 스킬의 시트만 우선 로딩한다. 캐릭터·적·공용 공격 이미지는 기존 준비 단계에서 완료한다.
- 미사용 전용 이펙트는 기존 이미지 키의 지연 접근자로 등록한다. 스킬 HUD의 장착 목록이 바뀌면 해당 시트를 요청하며, 렌더러가 직접 사용할 때도 요청된다. 별칭·반복 접근은 하나의 요청과 디코딩 이미지를 공유한다. 새 로딩 세대는 별도 이미지 뱅크를 사용하여 이전 요청이 새 뱅크를 덮지 않는다.
- 실패한 요청은 5초 후 다시 시도할 수 있으며, 15초 동안 끝나지 않는 요청도 재시도 가능 상태로 돌아간다. 실패는 경고 로그로 남고 전체 게임 진입을 막지 않는다. 아직 로딩 중인 전용 스킬은 기존 렌더러의 미로딩 동작을 유지한다.
- 이펙트 PNG 50개의 무손실 WebP 사본은 32.82 → 26.45 MiB다. 원본/결과를 RGBA로 디코딩해 모든 픽셀과 크기가 동일함을 확인했다. PNG는 편집·기존 시연 도구의 원본으로 보존하고, 전투 로더만 같은 이름의 WebP를 사용한다. 새 이펙트 추가 시 대응 WebP를 함께 만들어야 하며 스모크가 누락을 검출한다.
- PNG 수정 후 Pillow가 설치된 Python으로 `python scripts/compress-battle-effects.py`를 실행한다. 원본과 결과의 픽셀 일치를 검증하고 해시 증명을 갱신한다. 스모크는 양쪽 해시를 확인하여 원본만 수정하고 압축본을 갱신하지 않은 배포도 차단한다.
- 스크립트 순서에 `battle-asset-loading.js`를 추가했다. 함수는 에셋 준비 시점에 호출하며, 기존 저장 형식·전투 계산·이펙트 판정과 그림을 변경하지 않는다. HTTP 캐시/서비스 워커의 업데이트 정책도 유지한다.

추가 개선: 진입 큐에는 현재 지역 배경과 액트 1 대체 배경만 포함한다. 다른 액트·혼돈·이전 배경
34개는 같은 지연 이미지 로더를 사용한다. 목적지 렌더 시 해당 배경을 한 번 요청하며 준비 중에는
액트 1 배경을 표시한다. 배경 뱅크 전체를 열거하면 지연 getter가 모두 실행되므로 렌더러는 목적지와
대체 배경만 읽는다. 로그인 중 선로딩 정책은 `login-loading-resources.md`를 따른다.

측정: 새 Chromium 컨텍스트, 캐시 비활성, 20 Mbps/지연 40 ms 조건에서 전투 로더만 실행했다. 기존 코드와 변경 코드는 같은 서버·설정으로 각각 측정했으며 반복 측정의 통계치는 아니다.
