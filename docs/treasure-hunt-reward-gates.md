# 보물사냥 전투 복구와 지도 보상 해금 경계

2026-09-08

- 보스 10회 처치 후 표적 확인 → 추적 시작 → 일반 사냥터 진행도 55에서 표적 등장 → 처치 전리품 → 추가 보물 수령 순서다.
- 기존 여섯 표적의 특성과 전리품을 복구했다. 황금률·요정의 고리·고유 장비 등 현재 보물 추첨은 추가 보상으로 유지한다. 잠긴 성장품은 기존 장비 대체 보상을 사용하고, 잠긴 재화는 지급하지 않는다.
- 표적은 현재 사냥터의 일반 적 생성·공격·사망 경로를 사용한다. 새 레벨 배율을 덧붙이지 않는다. 특수 원정에서는 표적이 등장하지 않으며, 추적 상태를 유지한 채 일반 사냥터에서 다시 진행한다.
- 저장 `bountyHunt` v3의 pending은 표적 ID와 offered/queued/reward 상태를 보존한다. 재접속·귀환으로 표적과 추가 보상을 다시 추첨하지 않는다. 살아 있는 표적과 중복 사망으로 보상을 받을 수 없으며, 이미 발견한 v2 보물은 즉시 수령 권리를 유지한다.
- 추적 중 플레이어가 패배하면 보상 없이 실패로 종료한다. 표적·추가 보물·출처를 비우고 보스 10회 처치 조건부터 다시 시작한다. 성공 횟수·장비·재화는 실패 처리로 변경하지 않는다. 조건을 다시 채워도 직접 추적을 선택하기 전에는 표적이 등장하지 않는다. 미선택 상태와 이미 처치해 수령 대기 중인 보물은 일반 사망으로 소멸하지 않는다.
- 추적 시작 시 루프 정산 대기를 해제하여 사냥을 재개하되, 이미 달성한 이번 루프 기록은 보존한다. 진행 중인 추적과 처치 후 미수령 보물만 루프를 막는다. 실패 후 또는 추적을 선택하지 않은 상태에서는 루프할 수 있다.
- 지도 보상은 보조 젬·보조 젬 한도·관련 재화의 해금 정책을 따른다. 잠긴 선택지는 숨기고, 가능한 선택지가 없는 액트는 수령 버튼과 목표/알람 안내에서 제외한다. 미수령 기록은 유지하여 해금 후 다시 표시한다. 선택지 원래 인덱스를 유지하고 수령 시 재검사한다.
- 정적 자산 쿼리만 갱신했으며 classic script 순서는 그대로다. 전투는 기존 bountyRuntime 공개 객체를 호출하고, 지도 표시와 지급 경계는 같은 보상 정책을 사용한다.
- 실패 상태 변경은 bountyRuntime, 사망 연결은 combat이 소유한다. 기존 player-defeated 이벤트의 bountyFailed/noToast 필드를 bounty-ui가 받아 실패 로그를 표시한다. 상태 저장 형식은 v3 그대로다.

검증: 보물사냥·이벤트 맥락·액트 보상·지도 알림·목표 스모크, 전체 `npm test`, `npm run check:architecture`, PC/모바일 Playwright의 추적/처치/추가 수령·루프 정산·지도 해금 전후 6개 시나리오. 실제 휴대폰 성능이나 플레이어 재미 검증은 이 변경의 검증 범위에 포함하지 않는다.
