가로 넘침 없음이 모바일 사용성 완료를 의미하지는 않는다.

일반 사냥터 화면에서 정적 UI를 10회 갱신했을 때 숨겨진 ui-underworld-panel,
ui-ocean-panel, ui-fishing-panel에 각각 10회 DOM 변경이 발생했다.
현재 renderOceanDepthMapPanel·renderFishingPanel은 ensureOceanState를 호출하며,
이 함수는 산소·수심 보정과 루프 조건에 따른 해금을 수행한다. 렌더 호출만 막기 전에
이 상태 처리가 전투·저장·진행 경계에서 보장되는지 추적해야 한다.
renderUnderworldMapPanel도 underworldProgress를 대입한다. 읽기 전용 표현으로
정리하고 비활성 화면 렌더를 제한하는 순서로 진행한다.

다음 구현·검증 순서:

1. 심해 상태 갱신의 생산자·소비자와 오프라인 경로 추적, 렌더 여부와 무관한 진행 검증.
2. 낚시를 채집 현황·전략 / 도감 / 제작으로 분리하고 닫힌 도감의 전체 카드 생성을 줄이기.
3. 지하계 실제 입장 가능·룬 보유 상태에서 장착·교체·강화 비용 및 실패 경로 검증.
4. 우주계는 cosmos-atlas.js의 directory/atlas/detail/mastery와 모바일 선택·확정 흐름을
   별도 계측한다. 이번 화면 측정에는 포함하지 않았다.

이번 변경은 조사 문서만 추가했다. 실행 코드·스타일 변경이 없어 전체 테스트는 다시
실행하지 않았다. 후속 구현에서는 각 경로의 행동 검사와 기존 전체 검증을 실행한다.

## 심해 표시 경계 개선

전투의 tickOceanOxygen, 공격·웨이브 보상, 루프 보존 경로가 ensureOceanState를 직접
호출함을 확인했다. 지도 갱신에서 상태 보정·해금 호출은 한 번 유지하고 심해·낚시·바다의 선물
HTML 생성만 선택된 지도 하위 탭으로 제한했다. 일반 사냥터의 갱신 10회에서 심해·낚시
패널 변경은 각각 10→0회였다. 지하계는 여전히 10회이며 별도 정리가 필요하다.
mobile-map-navigation.spec.js에서 숨겨진 상태의 게이지·산소 변경은 DOM에 쓰지 않고,
탭을 열면 최신 값이 표시됨을 PC/모바일에서 검증한다. 전체 스모크 175개에는 UI 없이
수심·산소·낚시 진행을 검증하는 smoke-ocean-fishing-progression.js도 포함되어 통과했다.
상태 정규화 호출을 전부 렌더 밖으로 옮긴 것은 아니며, 현재는 표시 경계만 최적화했다.

## 낚시 작업 분리

모바일은 채집·전략 / 도감 / 제작을 기존 SectionNavigation으로 전환한다. 도감 호스트를
갱신되는 채집 HTML 밖의 고정 details로 옮겨 작업 선택과 PC 접힘 상태를 유지한다.
PC는 기존처럼 채집과 제작을 함께 보고 도감을 직접 펼친다. 바다의 선물 바로가기는
모바일 제작 탭을 선택한 뒤 이동한다. 같은 합성 상태에서 처음 화면 높이는 3266→794px였다.
전체 DOM은 475→482개로 내비게이션만큼 늘었으므로 메모리·렌더 속도 개선 수치가 아니다.
mobile-map-navigation.spec.js에서 모바일 도감 선택·갱신 중 유지·제작 바로가기·채집 복귀를
확인했다. 전체 스모크의 어종·게이지·도감·제작 검증도 새 도감 호스트에 맞췄다.
도감이 보이지 않을 때의 카드 생성과 제작 목록의 모바일 탐색은 후속 범위다.

도감의 어종·보상 목록은 PC에서 details를 펼치거나 모바일 도감 작업을 선택할 때 생성한다.
한 번 열고 다른 작업으로 이동한 뒤에도 숨겨진 목록을 갱신하지 않는다. 고정 호스트와
선택 상태를 확인하는 표현 함수는 ocean-collection-ui.js가 소유한다. 발견 수 요약은
기존 데이터 계산을 사용하며 카드 생성만 제한한다. 같은 초기 상태의 DOM은 482→380개였다.
모바일 숨은 도감의 DOM 변경 0회, 다시 열었을 때 새 포획 기록·보유량 표시, PC 펼치기를
브라우저에서 확인했다. 미발견 어종은 재고만 주입해도 공개되지 않는 기존 규칙을 유지한다.

바다의 선물 제작은 UI 갱신 시 옵션 계열 선택이 저항→공격으로 되돌아가는 문제를
PC/모바일에서 재현했다. renderSeaGiftPanel은 기존 DOM에서 레시피 id별 선택값을 보존해
재생성한 선택창에 복원한다. 별도 저장 설정이나 도메인 상태는 추가하지 않는다.
sea-gift-selection.spec.js는 실제 선택 후 재료 변경·정적 갱신·제작 패널 직접 갱신에서
선택값이 유지됨을 확인한다. 레시피 표시 길이와 선택창 DOM 자체를 보존하는 개선은 남아 있다.

이후 sea-gift-ui.js에서 고정 레시피 id를 기준으로 기존 카드를 유지하도록 바꿨다.
초기 생성 뒤에는 대상 설명·재료 표시·제작 가능 상태만 바꾸고 선택창과 접기 영역은 유지한다.
같은 HTML이면 갱신을 건너뛴다. 앞 단계의 선택값 복사·복원은 제거했다.
브라우저 검사에서 재료 갱신·실제 제작 후에도 선택창이 같은 DOM 노드로 유지되며,
재료 충족→제작 가능→소비 후 비활성화가 반영된다. 같은 상태 10회 갱신에서 대상 패널의
childList·attributes 변경은 0회였다. HTML 문자열 생성 비용은 여전히 남아 있다.
레시피 정의는 세션 중 고정이라는 계약을 모듈에 명시했다. 잠금으로 패널을 비우면 다시 생성한다.

모바일 제작에는 재화 정제 / 장비 가공 / 심연의 비전 선택기를 추가했다. 선택한 분류만
보여주며 재화 정제에서는 장비 대상 영역을 숨긴다. PC의 전체 분류·접기 배치는 유지한다.
선택기는 갱신되는 제작 패널 밖에 있어 재료 갱신에도 유지된다. 레시피·비용은 동일하다.
sea-gift-selection.spec.js에서 분류 전환, 심연 그룹 열기, 옵션 계열 유지와 실제 재료
소비를 PC/모바일로 확인했다. 전체 스모크 175/175 통과. JS 모듈 구조 변경이 없는
HTML·CSS 변경이므로 구조 검사는 반복하지 않았다. CSS 캐시 키를 갱신했다.

화면 크기 변경 회귀도 추가했다. 모바일 도감→1440px에서 접힘→보유량 변경→393px로 복귀 시
도감이 이전 수량을 표시했다. 도감 열림 이벤트를 PC에만 제한하던 조건을 제거해
반응형 전환으로 다시 열려도 최신 내용을 생성한다. 숨겨진 도감의 렌더 제한은 유지한다.
PC/모바일 지도 검사 및 전체 스모크 175/175로 확인했다. HTML 이벤트 조건 수정이며
JS 모듈 구조는 바꾸지 않았다.

## 지하계 숨은 렌더 제한과 펼침 상태

지도에서 지하계가 선택된 경우에만 패널·입장 목록을 만든다. 렌더 함수의
underworldProgress 대입은 제거했다. 상태 기본값은 state.js, 저장 복원은
save-migrations.js가 이미 소유하며 입장 동작의 상태 처리는 유지한다.
창공 상태 보정은 기존 선행 renderSkyTowerMapPanel 호출에서도 수행되므로
이 변경은 그 호출 순서나 보정 시점을 바꾸지 않는다. 창공 렌더의 상태 결합은 후속 범위다.

보유 룬 details는 기존 capture/restoreUiDisclosureState로 펼침 상태를 유지한다.
mobile-map-navigation.spec.js에 숨은 지하계 패널·입장 목록 변경 0회,
다시 선택 시 최신 룬 조각 표시, 갱신 후 목록 열림 유지 검사를 추가했다.
수정 전 숨은 패널 검사에서 변경 2회로 실패했고 수정 후 PC·모바일 모두 통과했다.
동일 합성 상태에서 지도 갱신 10회에 대한 지하계 패널 재생성은 10→0회였다.
412×915 화면의 기존 배치는 유지했다. 전체 스모크 175/175 및 구조·lint 검사 통과.
룬 장착·투자 및 실제 입장 가능 상태의 모바일 흐름 재설계는 아직 남아 있다.

## 룬 선택·승급 창 탐색

30종 보유 상태에서 목록 끝으로 이동하면 닫기 버튼이 화면 밖으로 사라짐을
underworld-rune-mobile.spec.js로 재현했다. 공통 창을 세로 flex로 바꿔 목록만
스크롤하고 현재 룬·닫기·해제를 고정했다. 모바일은 한 열을 사용하며 하단 메뉴와
겹치지 않는 공간을 확보한다. 파란 고정 배경·제목색은 공통 테마 변수로 대체했다.
초기 수정에서는 하단 메뉴가 해제 클릭을 가로채는 실패도 확인해 높이를 조정했다.

PC/모바일에서 30종 탐색 후 교체·해제, 반환 수량 보존, 빈 목록·해제 비활성,
승급 3개와 조각 5개 소비 및 자동 장착을 확인했다. 모바일 라이트 승급 화면도
이미지로 확인했다. 브라우저 2개 및 전체 스모크 175/175 통과. CSS·HTML 캐시 키와
브라우저 검사만 변경해 JS 구조 검사는 반복하지 않았다. 장비 인챈트·강화 등의
나머지 지하계 조작과 실제 입장 가능 상태의 종합 흐름 점검은 계속 필요하다.

## 우주계 캔버스 가시성과 프레임 수명

우주계 내부 탭의 active만 검사해 별지도 details를 접거나 성도술·장비 탭으로
이동해도 우주석 강조 애니메이션이 계속 그려질 수 있었다. 실제 캔버스 clearRect를
관찰한 브라우저 검사에서 접은 지도는 8프레임 동안 8번 그려졌다.
기존 가시성 판정에 부모 지도 탭, 내부 아틀라스 선택, 별지도 펼침 상태를 포함했다.
성도술에서 아틀라스로 돌아올 때 프레임을 요청해 중단 후 재개를 보장한다.
레이아웃 크기 읽기나 새로운 타이머는 추가하지 않는다.

realm-workflow.spec.js는 지도 펼침에서 양수, 접힘·성도술·장비 탭에서 0회,
각 복귀에서 다시 양수인 실제 그리기를 PC·모바일에서 확인한다. 기존 목적지 선택과
전투 입장도 통과했다. 전체 스모크 175/175 및 구조·lint 검사 통과. 이는 숨은 그리기 제거 근거이며
실기기 발열 개선량은 미측정이다. 우주계 DOM 생성과 성도술의 상태 정규화 결합,
목적지 목록과 상세 화면의 모바일 탐색 개선은 별도 잔여 범위다.
