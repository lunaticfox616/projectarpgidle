# 광창 강림 — 공격 젬과 낙하 이펙트

## 사용자 확정 — 2026-09-09 v3.7

- **캐릭터 반경 3칸 안에 있는 모든 몬스터에게 광창이 각각 떨어지는 공격 스킬**이다. 별도의 한 칸을 조준하지 않고 캐릭터를 중심으로 대상들을 선택한다.
- 이름 **광창 강림**, **공격 / 번개** 분류를 유지한다. 기존 번개 속성 키는 `light`이며 신성/빛 속성이나 주문 태그를 신설하지 않는다.
- 각 창의 크기는 한 칸이며, **각 창은 착지한 1칸만 한 번 타격**한다. 창 주변으로 폭발 피해가 퍼지지 않는다. 반경 안의 여러 적은 각각 자신의 창에 맞는 것이며, 근처의 여러 창 때문에 한 적이 중복으로 맞지 않는다.
- 기존 인수인계 거리 `max(abs(dx), abs(dy))`를 적용한다. **대각선 포함 3칸**, 중앙 기준 최대 7×7칸이며 전장 밖 칸은 제외한다. 사각 격자의 거리 규칙으로, 별도의 원형/유클리드 반경을 도입하지 않는다.
- “창만 떨어지는” 연출을 유지한다. 바닥 충격파·파편·적중 원환은 출력하지 않는다. 씨앗은 53종, 비소환 이펙트는 45종을 유지한다.

## 대상 시점과 연출 제안

- `[제안: 현재 구현]` 한 시전의 시작 위치를 캐릭터 중심으로 고정하고, 그 순간 반경 3칸 안의 생존 몬스터가 점유한 칸들에 낙하를 예약한다. 대상 수는 제한하지 않으며 빈 칸에는 창을 추가하지 않는다.
- 이전 1칸 낙하의 지면 판정 방식을 유지한다. **착지 순간 예약된 칸의 생존 적**을 다시 읽고 적 ID마다 한 번만 적중시킨다. 예약 칸에서 벗어난 적은 맞지 않고 그 칸으로 들어온 적은 맞는다. 예약하지 않은 빈 칸으로 새로 들어온 적에게는 해당 시전의 창이 생기지 않는다. 이동하는 대상을 추적하는 창으로 확정하지 않는다.
- 같은 칸에 여러 적이 있으면 모든 적을 각각 한 번 타격한다. 완전히 겹치는 창의 시각 출력만 칸당 하나로 합친다. 이 병합이나 출력 상한으로 피해 대상 수를 줄이지 않는다.
- `[제안]` 대기 180ms → 수직 낙하 260ms → 꽂힌 창이 144ms에 걸쳐 사라짐. **모든 창의 기준 적중 시점은 동시에 440ms**다. 시간·공격 속도 조절은 연출 제안이며 피해량·쿨다운 확정값이 아니다.
- 대상이 없으면 창과 적중 이펙트를 출력하지 않는다. 중단하면 예정된 적중을 취소한다.

## PixelLab 원화와 미리보기

- 32px 씨앗 `assets/gems/active/radiant-lance-seed-32-v1.png`를 그대로 사용한다. `[제안]` 상아색 목질 씨껍질과 노란 창끝 배아의 형상이며 새로운 종교·클래스·식물 설정을 부여하지 않는다. 32×32 RGBA, 2px 투명 여백, 10색 이내, 이진 알파, 디더링 없음.
- 기존 PixelLab 64px 창 원화 한 장을 여러 대상 위치에 재사용한다. 창끝은 아래를 향하고 보이는 높이는 48px 이하이다. 이번 수정에 새 AI 생성 이미지는 없다. 이전 충격파 원화는 아틀라스·원본 시트에만 보존한다.
- 결과 폴더 `output/skill-effects-43-v3-pixellab-mz/`, 갤러리 `?version=3.7&skill=45`, `radiant-lance-showcase.gif`, `animations/45.webp`에 여러 창의 일제 낙하를 반영했다. WebP는 432×384 투명 모션이며 생성 원화의 이동·투명도로 렌더한 결과다.
- 미리보기에서 **칸 클릭은 캐릭터 위치 변경**이다. 초록 칸은 반경 3칸, 금색 테두리는 실제 낙하할 몬스터 칸이다. 몬스터 배치는 여러 마리/전체 배치/한 마리/대상 없음으로 바꿀 수 있다. 기존 범위 확장 예시 슬라이더는 이 스킬에 적용하지 않는다.

## MZ 연결과 성능

- 갤러리 번호 **45**는 MZ 데이터베이스 Skill ID가 아니다. `category: attack`, `tags: attack, lightning, aoe`, `targetMode: all-enemies-around-caster`를 사용한다. `aoe`는 주변 모든 적을 선택하는 분류이며, **창별 `impactRadius:0`**과 구분한다.
- `WorldTreePixelLabFX.radiantLance.createCast({source,getEnemies,emit,onImpact,startAt,speed,channelId})`로 사용한다. v3.6의 조준 `target` 인수는 더 이상 사용하지 않는다. `source`는 시전자 칸, `getEnemies`는 현재 적 목록을 제공한다.
- `emit`은 `e => layer.fx.emit(e)`로 연결하고 전투 시계에 따라 `cast.update(now)`를 호출한다. `onImpact`는 착지 순간 생존 적 전체와 `category:'attack', element:'light', targetRadius:3, hitCountPerEnemy:1, cells, at`를 한 번에 전달한다.
- 시각 취소는 `layer.fx.cancel(channelId,now)`, 판정 취소는 `cast.cancel()`로 처리한다. 같은 시전의 식별자를 사용한다. 피해량·방어·면역·공격 보정·DB 연결은 호출하는 전투 코드가 담당한다.
- 여러 창을 **낙하/착지/적중 최대 3개 시각 이벤트**로 묶어 적이 많아도 이벤트 128개 상한을 넘기며 일부 대상이 누락되는 구조를 피했다. 대상 좌표는 이벤트마다 한 번 계산하고 이미지와 Sprite를 재사용한다.
- **432프레임 / 1024×1728 / RGBA 6.75MiB / 공유 텍스처 1장 / 기본 Sprite 풀 48개** 유지. 아틀라스는 v3.5·v3.6과 바이트 단위로 같다.
- 기본 예시는 12마리/12개 창, 중심을 제외한 반경 3칸 전체 배치는 48마리/48개 창이다. 한 프레임에 다른 스킬까지 합쳐 출력 예산을 넘으면 일부 시각만 생략하며 실제 피해 대상은 보존한다. 시전자 칸까지 적 49명이 있는 검증에서는 기본 시각 48개·피해 49명을 확인했다. 모든 장면에서 모든 창의 시각 출력을 보장하는 무제한 풀로 바꾸지 않는다.

## 검증

- 반경 3칸 선택 5,184조합, 창별 1칸 판정 5,184조합, 중앙 49/변 28/모서리 16칸, 범위 밖 배제, 모든 창의 수직 낙하·정확한 착지·동시 적중을 확인했다.
- 같은 칸 200명 모두 1회 타격/창 시각 1개, 적 이동·사망·중복 ID 처리, 대상 없음, 중단, 목표 조준/범위 슬라이더가 반경을 바꾸지 않음, 미리보기 캐릭터 이동과 배치 선택을 확인했다.
- 기존 44종 176화면 SHA-256 일치, 전체 아틀라스 보존. 실제 MZ 1.10.0 / PIXI 5.3.12에서 시연 명령 45, 다중 창, 48개 풀·128개 이벤트·공유 텍스처, 부하 상한·정리·이전 플라스크 투명도 복원 검사 통과. `qa/lance-verification.json`을 따른다. CPU 제출 시간은 모바일 전체 게임 FPS 보장이 아니다.

## 이력과 참조 상태

- `[SUPERSEDED]` v3.5의 한 창 중심 3×3 피해·충격파는 v3.6에서 폐기됐다.
- `[SUPERSEDED]` v3.6의 시전 거리 2칸·한 곳 조준·총 창 1자루는 v3.7의 캐릭터 반경 3칸 내 전체 대상 낙하로 대체됐다. **창마다 1칸 타격·창만 낙하**는 유지한다. 이전본은 `revisions/v3.6-before-radius-all/` 및 v3.6 ZIP에 보존한다.
- 사용자가 하보크 쇼크를 참고하도록 요청했고 참고 영상은 소실됐다고 설명했다. 원작 영상의 모션을 직접 확인하거나 그대로 재현했다고 주장하지 않는다. 사용자 설명 “창만 떨어지는” 모습을 연출 기준으로 사용한다. 이전에 명칭을 확인한 [아스가르드 사이트 이용자 게시글](https://asgard.nexon.com/Community/server/712194)은 모션 검증·현행 공식 밸런스 자료가 아니다.

- `docs/world/00_CANON_INDEX.md`, `01_WORLD_PREMISE.md`, `05_PLAYER_CLASSES.md`, `06_VISUAL_REFERENCE_MANIFEST.md`; 연계 규격 `docs/items/00_ITEM_ART_SPEC.md`, `01_SKILL_GEM_ART_SPEC.md`, `02_SKILL_PIXEL_EFFECT_SPEC.md`를 사용했다. 최신 사용자 수정으로 과거 범위를 대체했으며 확인된 정사 충돌 없음.
