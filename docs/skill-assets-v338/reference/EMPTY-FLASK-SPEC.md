# 빈 플라스크 — 물리 투사체 공격과 유리 파편 v3.28

> **v3.35 모션 갱신:** 유리 파편이 포물선을 그리며 날아가고, 끝이 진행 방향을 따라 회전하도록 변경했다. 개수·확률·피해 시점·원화는 유지한다. 현재 모션 규격은 `30_EMPTY_FLASK_SHARD_ARCS_SPEC.md`를 따른다. 아래는 원래의 동작·원화 제작 이력이다.

## 동작과 추가 발사

포션 내용물 없이 빈 유리병 한 개를 포물선으로 던진다. 병은 지정한 착지 칸에서 깨지고 그 칸의 몬스터 한 마리를 물리 공격으로 타격한다. 이후 1~4개의 기본 파편과 확률로 추가된 파편이 주변 몬스터를 향해 날아간다. 파편도 물리 투사체 공격이며, 각 파편의 도착 시점에 대상 한 마리씩 판정한다.

| 항목 | 적용 기본안 |
|---|---|
| 투척 사거리 | 시전자 칸 중심 기준 유클리드 거리 4칸 |
| 파편 대상 범위 | 착지점 중심 기준 유클리드 거리 3칸 |
| 기본 파편 N | 매 시전 1~4개 균등 무작위 |
| 추가 확률 P | 각 기본 파편마다 0~100%로 1회 판정 |
| 총 파편 수 | N + 성공 횟수, N~2N개 |
| 추가 파편의 재발동 | 없음 — 추가 파편이 다시 파편을 생성하지 않음 |
| 기본 파편 4개, P=0% | 4개 |
| 기본 파편 4개, P=50% | 4~8개, 평균 6개 |
| 기본 파편 4개, P=100% | 8개 |

미리보기에서 기본 개수를 1~4개로 고정하는 선택지는 비교용이다. 기본 무작위 설정에서 ‘처음부터’ 버튼을 누르면 개수와 경로를 새로 뽑는다. 확률 조절기 50%는 시연값이며 스킬 자체의 기본 추가 발사 확률이 아니다. 런타임 API에 확률을 전달하지 않으면 0%다.

`src/stat-presets.js`의 기존 `additional_projectiles`는 **개수(count)** 스탯이다. 이를 확률로 오해하거나 기존 스탯 정의를 변경하지 않는다. 새 API는 호스트가 계산한 **확률(percentage points)** 을 `extraProjectileChance`로 받는다. 예를 들어 50%는 `50`으로 전달한다. 기존 추가 개수 스탯과 이 확률을 합산하는 실제 게임 연결 규칙은 OPEN이다. 100%를 넘는 입력은 100%로 제한하는 현재 기본안이다.

## 대상과 예외

48px 논리 셀의 중심으로 거리를 계산하며 보드 밖 칸을 제외한다. 사거리 밖 조준은 유효 범위의 가장 가까운 칸으로 제한한다. 병의 시작점·착지점은 시전 때 고정한다. 병은 착지 칸의 살아 있는 대상 한 마리를 타격하며, 명시적 primaryTargetId가 있으면 그 대상만 검사한다.

병의 피해 콜백이 끝난 뒤 주변 적을 다시 조회한다. 먼저 최초 병의 대상을 제외한 주변 몬스터에게 중복 없이 파편을 분산한다. 그 목록을 한 번씩 사용한 뒤 남은 파편은 그 주변 적들에게 무작위로 재분배한다. 다른 몬스터가 한 마리도 없으면 살아 있는 최초 대상에게 재적중한다. 기본 파편과 추가 파편은 같은 선택 규칙을 사용한다.

각 파편은 발사 시 조준한 좌표로 향하며 자동 추적하지 않는다. 도착 때 대상이 죽었거나 그 칸을 떠났으면 빗나간다. 주변에 살아 있는 몬스터가 없으면 파편은 외곽으로 흩어져 사라지는 시각 효과만 표시한다. 죽은 적·중복 ID·잘못된 좌표를 피해 대상으로 삼지 않는다. 범위 안의 모든 적에게 무조건 피해를 주는 범위 공격은 아니다.

## 전투 연결 API

`WT_EMPTY_FLASK.createCast({source, aim, primaryTargetId, getEnemies, emit, onImpact, onShatter, onCancel, onVisualError, rng, baseCount, extraProjectileChance, startAt, speed, channelId})`를 제공한다. MZ에서는 `WorldTreePixelLabFX.emptyFlask`로도 접근한다.

- `update(now)`는 비행·파손·파편 도착을 진행한다. 지연 갱신도 최대 병 1회 + 파편 8회의 판정을 처리한다. `getEnemies(at)`는 요청한 예정 시점의 권위 있는 스냅샷을 제공해야 한다. 과거 적 위치를 임의로 복원하지 않는다.
- `onImpact`는 phase(flask/shard), at, targets, targetIds, cells, isHit, bonusShard, projectileIndex를 전달한다. 대상이 없는 도착은 isHit=false, targets=[]다. 물리 공격 분류와 `damage:null`을 전달하며 실제 HP 계산은 호스트가 맡는다.
- `onShatter`는 기본 수·추가 수·총 파편 수·확률·타깃이 있는 파편 수를 알린다.
- `canTriggerAdditionalProjectiles:false`로 같은 투척의 판정을 이미 소모했음을 표시한다. 호스트는 병이나 파편의 피해 콜백에서 이 확률을 다시 굴리지 않는다.
- 취소·재진입·중복 update는 처리한 타격을 반복하지 않는다. onCancel은 해당 시전의 렌더링 채널도 취소해야 하며, 시전별 고유 channelId를 쓴다. 시각 콜백 실패와 Sprite 상한은 전투 판정을 누락시키지 않는다.

이 파일은 시각 플러그인과 전투 연결용 콜백을 제공한다. MZ DB에 스킬을 자동 등록하거나 실제 피해량을 확정하지 않는다.

## PixelLab 원화와 성능

PixelLab의 네이티브 32px 빈 병·파편·파손 원화와 젬을 사용한다. 젬은 활처럼 보이던 후보를 제외하고 둥근 목질 외피와 넓은 빈 공간의 씨앗으로 보완했다. 원본·미채택 후보·팔레트·처리 기록은 `pixellab/empty-flask-v328/`에 보존한다. 최종 젬 8색, 병 7색, 파편 6색, 파손 7색이다. 공통 감색 후 원본 투명도를 복원하고 이진 알파·정수 패딩·최근접 샘플링을 사용한다.

병은 밑면을 기준으로 회전하며 지정 칸에 닿는다. 파편의 날카로운 끝이 대상에 도달하고 몸체는 뒤따르도록 앵커를 맞췄다. 파손은 작은 범위에서 한 번만 나타나고 사라진다. 큰 폭발광·화면 흔들림·미세 파편 구름을 추가하지 않는다. 미리보기는 처음 정지하고 사용자가 한 번씩 재생한다.

기존 459슬롯 뒤에 원화 3슬롯을 추가한다. 총 **462슬롯·1024×1856·7.25MiB·텍스처 1개**, 아틀라스 메모리 증가 **0바이트**다. Sprite 풀 48개·시각 이벤트 상한 128개를 유지한다. 최대 구성의 시각 이벤트는 18개이며, 검수 장면 최대 출력은 8Sprite였다. 비행과 적중은 같은 파편 원화를 재사용하며 매 프레임 원화·무작위 파편을 생성하지 않는다.
