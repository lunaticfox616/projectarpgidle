# 시간 가속 — 플레이어 추적 시계 장판 v3.17

## 요청과 상태

사용자는 **시간 가속**이라는 새 주문 젬을 요청했다. 플레이어 아래 바닥에 시계 이펙트가 나타나 지속 피해를 입히며, 후속 답변에서 **카오스 피해**, **반경 3칸·5초·1초마다**, **플레이어를 따라 이동**을 선택했다.

- `[최신 사용자 확정]` 위 이름·분류·속성·범위·지속·주기·추적 방식.
- `[WORKING: 구현 해석]` 원형 유클리드 거리와 0초 선행 피해 없이 1~5초에 다섯 번 적용하는 시점은 위 요청을 구현한 기본값이다. 별도 시간 가속 버프는 추가하지 않는다.
- `[WORKING: 적용 규격]` 효과 카탈로그 번호 **46**, 전체 젬 컬렉션 순번 **54**, 버전 **3.17.0**. 이 번호는 실제 RPG Maker MZ 데이터베이스 ID를 뜻하지 않는다.
- `[제안: 제작 조형]` 보라색 속씨와 목질 씨껍질의 32px 젬, 바닥의 큰 시계 원환과 분리된 시곗바늘, 주기 피해의 짧은 접촉광. 조형·색 배분·회전 속도는 최종 사용자 채택 전 제안이다.
- `[OPEN]` 틱당 피해량·계수, 쿨다운·마나 소모, 젬 레벨 성장, 재시전 시 중첩·교체 정책과 실제 전투 DB 연결.

## 전투 동작

| 항목 | 적용 규격 |
|---|---|
| 분류 | 주문 젬 / `spell` |
| 피해 속성 | 카오스 / `chaos` |
| 피해 방식 | 지속 피해 / `dot`; 일반 적중 이벤트와 구분 |
| 중심 | 매 시점의 플레이어 위치; 바닥 시계도 함께 이동 |
| 범위 | 원형 반경 3칸, 유클리드 거리 `dx² + dy² ≤ 9` |
| 지속 | 5,000ms |
| 주기 | 1,000ms마다, 시작 후 1·2·3·4·5초의 총 5틱 |
| 시작 순간 | 0초 선행 피해 없음 |
| 대상 | 각 틱의 현재 범위 안에 있는 살아 있는 모든 적 |
| 속도 버프 | 별도 이동·공격·시전 속도 증가 없음 |
| 수치 피해 | 미확정. 모듈은 `null`을 유지하고 호스트의 확정 수치 적용을 기다림 |

시간 가속은 시계가 생성된 첫 칸에 고정된 장판이 아니다. 플레이어가 이동하면 다음 틱은 이동한 위치를 기준으로 다시 검사한다. 범위를 벗어난 적과 이미 죽은 적은 해당 틱에서 제외하고, 새로 들어온 적은 포함한다. 같은 적 ID의 중복 입력은 한 번으로 정리하며, 시각 출력 예산 때문에 실제 대상 수를 줄이지 않는다.

마지막 피해는 정확히 5,000ms에 적용한다. 그 뒤 200ms의 표시용 소멸 시간을 두는 것은 모션 제안이며, 이 구간은 추가 틱이나 지속시간 증가가 아니다. 소멸 중에는 마지막 중심에 머물러 끝난 시계가 다시 플레이어를 따라가지 않게 한다.

반경 3칸은 전투판의 `48×48px` 논리 셀 기준이다. 대각선 세 칸인 `(3,3)`은 원 밖이며 `(2,2)`는 원 안이다. 보드 경계에서는 유효한 `9×8` 칸만 검사한다. 이 거리 규격을 기존 광창 강림 등 다른 스킬의 거리 계산에 소급 적용하지 않는다.

## 런타임 연결

구현 소스는 번들의 `time-acceleration.js`, 전역 API는 `WT_TIME_ACCELERATION`이다. `catalog.js`와 기존 미리보기 빌더를 읽은 뒤 로드하며, 기존 45종을 수정하지 않고 46번을 추가한다. MZ 번들에서는 `WorldTreePixelLabFX.timeAcceleration`으로도 접근한다.

MZ에서는 전장 바닥·배우·전경 이펙트가 같은 부모를 사용하도록 배치한 뒤 `layer.mountGround(layer.parent, actorIndex)`로 바닥 레이어를 배우 앞 순서에 삽입한다. Canvas에서는 바닥을 그린 뒤 `fx.render(ctx, now, {clear:false, layer:'ground'})`, 배우, `layer:'foreground'` 순으로 그린다. 바닥/전경을 나누어도 동일한 48개 스프라이트 예산을 공유한다.

`createCast({ getSource, getEnemies, emit, onTick, startAt, channelId, onCancel, onVisualUpdate, onVisualError })`는 한 시전의 상태를 만든다. `getSource(at)` 또는 호환 이름 `getCasterCell(at)`는 시전자 격자 좌표를, `getEnemies(at)`는 적 상태 목록을 제공한다. `source`와 `sourcePath`는 정해진 경로를 재생하는 미리보기에서 사용할 수 있다.

- `update(now)`를 호스트 업데이트에서 호출한다. 처리한 틱을 다시 발생시키지 않으며 시간이 거꾸로 간 호출을 무시한다.
- `onTick`은 틱 번호·예정 시각·현재 중심·중복 제거된 대상 목록과 카오스 지속 피해 분류를 전달한다. `damage`, `damagePerTick`은 확정되지 않은 값이므로 `null`이다. 실제 피해 적용은 이 콜백을 받는 전투 코드의 책임이다.
- 표시용 시계는 지속 이벤트 하나로 유지하고 위치 변경은 반환된 이벤트 핸들에 반영한다. 새 프레임마다 시전 이벤트나 텍스처를 만들지 않는다.
- `cancel(at)`는 아직 처리하지 않은 틱과 표시를 중단한다. 시전자 사망·맵 전환·전투 종료의 실제 취소 연결은 호스트가 제공한다.
- 프레임 지연 시 최대 다섯 개의 예정 시각만 처리한다. 각 시각은 상태 공급자에 전달되지만 과거 상태를 자체 복원하지 않는다. 현재 상태만 제공하는 호스트에서는 지연 처리 시 현재 상태를 사용한다.

`onTick`과 시각 `emit`은 별개다. 시각 이벤트가 제한되거나 표시 콜백이 실패해도 정상적인 지속 피해 콜백을 표시 성공 여부에 묶지 않는다. 테스트용 카탈로그와 MZ 표시 플러그인의 등록은 실전 `Skills.json`이나 피해 공식을 자동 연결했다는 뜻이 아니다.

## 젬과 이펙트 제작 규격

32×32 투명 PNG 젬은 기존 개별 씨앗 규격을 따른다. 카오스 보라색 핵과 목질 씨껍질을 큰 형태로 구분하며, 시계 모티프는 스킬 식별용 조형 제안이다. 보라색을 모든 세계관 마법의 공통 물질로 정의하지 않는다. 기계 장치·새 기관·시간 회귀의 원리도 이 아이콘에서 추론하지 않는다.

젬은 `assets/gems/active/time-acceleration-seed-32-v1.png`와 번들 `icons/46.png`에 저장했다. PixelLab 네이티브 32px 원화의 후보 59번을 선택하고 12색 감색 설정을 적용했으며, 실제 출력은 **11색·이진 알파·2px 투명 여백·741바이트**다. 확대·축소 없이 제작했고 기존 45개 번들 아이콘과 53개 씨앗 파일의 해시 보존을 검사했다. 생성 기록과 검증은 `pixellab/time-acceleration/gem/records.json`, `gem/verification.json`에 있다. 기술·육안 제작 검수를 최종 사용자 조형 채택과 구분한다.

PixelLab 소재를 사용하는 이펙트의 구성은 160px 원화를 손실 없이 패딩한 `192×192px` 시계 원환의 9개 타일, 시곗바늘 2개, 짧은 접촉광 1개다. 각각 `64×64px` 슬롯에 배치해 총 12슬롯을 추가한다. 원화에 따로 붙어 있던 검은 점 51px를 제거하고 주된 원환은 리샘플링 없이 정수 위치로 정렬했다. 원환은 2배, 동일 바늘 원화는 2배·1배로 표시한다. 시계 장식의 지름은 약 256px이며, 실제 원형 피해 지름 288px 안에 놓인다. 정확한 판정 칸은 범위 표시에서 확인한다. 크기·회전의 적용값은 런타임과 `pixellab/individual/reviewed.json`의 46번 기록을 따른다.

무의미한 점·미세 뿌리·그물망·촘촘한 디더링을 피하고, 투명한 중심과 큰 표식으로 시계가 읽히게 한다. 범위를 채우는 불투명 면이나 계속 중첩되는 밝은 섬광으로 캐릭터를 가리지 않는다.

## 출력과 검증 기록

최종 기술 검사 `3.17.0 / final-technical`를 통과했다. 입력 19개 해시가 고정된 상태에서 독립 로직 5,404검사, 새 모션 4,896레이아웃, 실제 MZ 1,084프레임을 검사했다. 일반 시전은 최대 39/48스프라이트였으며 텍스처 1개와 마스크 3개를 재사용한다. 배우 뒤 배치, 이동, 마지막 5초 피해, 5.2초 소멸, 취소, 파괴·재생성과 Showcase를 확인했다. MZ에 플러그인·아틀라스를 설치하고 데이터베이스 25개 보존을 확인했다.

기존 45종의 메타데이터·432슬롯 원본 픽셀·90개 시퀀스·Canvas 360표본을 보존했다. 아틀라스 높이가 1728→1792로 바뀌면서 원래 크기끼리의 MZ 비교에서는 180표본 중 39개에서 PIXI의 UV 정밀도에 따른 일부 픽셀 선택 차이가 있었다. 스프라이트 위치·크기·회전·프레임은 동일했다. 이전 PNG에 검사용 투명 64행만 메모리에서 추가해 GPU 텍스처 크기를 맞추면 MZ 180표본 모두 일치한다. 독립 확대 확인에서도 3번 10픽셀·43번 45픽셀 차이는 큰 형태와 접촉 위치를 바꾸지 않았다. 역사적 PNG와 모션 파일은 수정하지 않았다.

아래 상대 경로의 기준은 `output/skill-effects-43-v3-pixellab-mz/`다. 폴더명의 43은 최초 제작 당시 이름이며 현재 수량이 아니다. 제작 중인 경로의 존재만으로 검증 완료를 의미하지 않으며, 완료 여부는 해당 버전·입력 해시·`passed`를 가진 최종 보고서를 따른다.

- 개별 재생: `time-acceleration.html`
- 젬: `icons/46.png`
- 준비된 원화: `pixellab/time-acceleration/ready/0.png`부터 `11.png`
- 전체 투명 모션: `motions/46.webp`, `animations/46.webp` — `432×384px`
- 성분 시트: `sheets/46.png` — `256×192px`, 4×3 슬롯
- 전장 포함 검수 모션·주요 프레임: `qa/time-acceleration/46-after.webp`, `46-after.png`
- 시각 확인 기록: `pixellab/individual/reviewed.json`의 46번
- 독립 로직 검사: `qa/time-acceleration/mechanics-verification.json` — `mechanics-only` 범위이며 최종 통합 검사를 대신하지 않음
- 최종 기술 검사: `qa/time-acceleration/time-acceleration-verification.json`
- 출력 해시: `qa/time-acceleration/export.json`
- 실제 MZ 설치와 DB 보존: `installation-report.json`
- 최종 납품 목록: `delivery-manifest.json`

최종화 도구 `finalize-time-acceleration.cjs`는 시각 확인·최종 기술 검사·출력 해시·현재 MZ 설치 파일을 대조한 뒤 새 출처 기록과 납품 목록을 작성한다. `--check`는 검증만 한다. `package-time-acceleration.ps1`은 기존 ZIP을 덮어쓰지 않으며 압축 후 모든 포함 파일을 다시 풀어 SHA-256으로 검사한다.

## 정사 근거와 미확정 항목

사용한 정사는 `docs/world/00_CANON_INDEX.md`, `01_WORLD_PREMISE.md`, `02_PLAYER_AND_TIME_LOOP.md`, `05_PLAYER_CLASSES.md`, `06_VISUAL_REFERENCE_MANIFEST.md`다. 씨앗 규격은 `docs/items/01_SKILL_GEM_ART_SPEC.md`, 전장 표시 규격은 `02_SKILL_PIXEL_EFFECT_SPEC.md`를 따른다. 원본 인수인계의 51종을 수정해 새 스킬의 출처로 꾸미지 않으며, 이번 54번째 젬은 최신 사용자 요청과 선택 답변에서 추가됐다.

기존 `[LOCKED]` 세계관·플레이어·클래스·회귀 설정과 충돌은 없다. 시계의 조형을 세계수 회귀를 조종하는 새 서사 능력으로 확정하지 않는다. 시간 가속 자체의 사용자 확정 동작은 유지하면서 **피해와 성장 수치, 재시전 정책, 최종 조형 채택, 실전 DB·상태·사망 콜백 연결, 실제 기기 전체 게임 성능**은 `[OPEN]`으로 남긴다. 기존 관통 사격 첫 초과 피해 전이의 설명/코드 차이도 이번 작업에서 수정하지 않는다.
