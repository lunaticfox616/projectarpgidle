# 파문심판 — 전방 2칸 향로 내려찍기와 십자 번개 v3.30

> **v3.37 최신 수정:** 사용자 요청에 따라 향로·사슬을 은색으로 바꾸고, 착지점과 상하좌우 칸에 낙뢰가 위에서 아래로 내려온다. 기존 청동·바닥 전류 조형은 시각 이력이다. 전방 2칸·십자 5칸·480ms에 각 적 1회 판정은 유지한다. 최신 성능·조형 규격은 [32_RIPPLE_JUDGMENT_DESCENDING_LIGHTNING_SPEC.md](32_RIPPLE_JUDGMENT_DESCENDING_LIGHTNING_SPEC.md)를 따른다.

## 요청과 적용 상태

- `[최신 사용자 요청]` **파문심판** 신규 스킬. **공격**으로 분류하고, 향로로 플레이어 전방 **2칸**을 내려찍은 뒤 공격 지점에서 **십자 모양 번개**가 발생한다. 피해 속성은 번개다.
- `[WORKING: 적용 기본안]` 캐릭터의 상하좌우 4방향을 따른다. 십자는 착지점과 상하좌우 1칸, 총 5칸이다. 범위 선택 질문 후 기본안으로 안내했으며 명시적 사용자 확정과 구분한다.
- `[WORKING: 타격]` 내려찍기와 십자 번개를 하나의 번개 공격 판정으로 처리한다. 십자 안의 살아 있는 적에게 각각 1회 적중하며 중앙 적을 두 번 타격하지 않는다. 대각선은 제외한다.
- `[WORKING: 제작 번호]` 전체 젬 59번째·이펙트 카탈로그 51번. 실제 RPG Maker MZ 데이터베이스 ID는 별도다.
- `[제안: 조형]` 두꺼운 목질 능선과 황금 번개 틈이 있는 씨앗, 청동 향로, 손과 향로를 잇는 사슬, 절제된 황금빛 십자 전류. 이름에서 특정 종교·클래스·의식을 추정하지 않는다.
- `[OPEN]` 십자 길이·4방향·적당 1회 기본안의 최종 선택, 조형 채택, 피해량·계수·재사용 시간·소모량·성장·실제 전투 DB 연결.

## 범위와 동작

9×8 전투판의 48px 논리 셀을 사용한다. 시전 시작 때 플레이어 셀과 바라보는 방향을 고정한다. 착지점은 그 방향으로 정확히 2칸이다. 전방 2칸이 보드 밖이면 시전하지 않으며, 임의로 1칸 공격으로 줄이거나 다른 방향으로 돌리지 않는다. 보드 안의 착지점에서 십자 팔이 바깥으로 나가는 부분만 제외한다.

| 방향 | MZ 방향값 | 착지점 |
|---|---|---|
| 아래 | 2 | (x, y+2) |
| 왼쪽 | 4 | (x−2, y) |
| 오른쪽 | 6 | (x+2, y) |
| 위 | 8 | (x, y−2) |

향로를 당겨 들어 올리고 전방으로 넘긴 뒤, 마지막 구간은 착지점의 바로 위에서 **화면 아래로 수직 내려찍는다**. 향로의 실제 바닥 끝이 착지 셀의 중심에 닿는다. 사슬은 손과 향로 윗고리 사이를 계속 연결하므로 하늘에서 분리된 물체가 떨어지는 연출이 아니다. 화면 위쪽 가장자리에서는 들어 올리는 높이를 줄이며 착지 칸과 공격 거리는 유지한다.

기본 속도에서는 0.48초에 착지와 십자 번개가 동시에 시작되고 그 시각의 몬스터 위치로 공격을 1회 판정한다. 사슬과 향로는 착지 후 0.14초 이내에 사라지고, 십자 번개는 약 0.42초 동안 부드럽게 나타났다 사라진다. 별도의 물리 타격·감전 확률·디버프·반복 낙뢰·연쇄 공격을 추가하지 않는다.

번개는 **착지점 중심**의 가로·세로 십자다. 플레이어 중심 십자나 대각선 X자가 아니다. 중앙 1칸과 각 팔 1칸의 적을 모두 타격한다. 모서리 착지에서는 유효한 3칸만 남는다. API는 팔 2칸 기본안을 비교할 수 있도록 `crossRadius:2`도 지원하지만 현재 미리보기와 기본 규격은 1이다.

## 전투 연결 API

`WT_RIPPLE_JUDGMENT` 및 MZ의 `WorldTreePixelLabFX.rippleJudgment`를 제공한다.

```js
const judgment = WorldTreePixelLabFX.rippleJudgment;
const cast = judgment.createCast({
  source: playerCell,
  direction: playerDirection, // 2, 4, 6, 8
  crossRadius: 1,
  getEnemies: at => getLivingEnemySnapshotAt(at),
  emit: event => layer.fx.emit(event),
  onImpact: hit => resolveLightningAttack(hit),
  onCancel: (id, at) => layer.fx.cancel(id, at),
  startAt: now,
  channelId: uniqueCastId
});
if (cast.ok) cast.update(now);
layer.tick(now);
```

예제의 적 스냅샷과 피해 처리 함수는 호스트에서 구현할 연결 지점이다. `light`는 기존 카탈로그의 **번개** 속성 코드이며 별도 빛 속성을 뜻하지 않는다. `category:'attack'`, `damageType:'hit'`, `damage:null`을 전달한다. 피해량·공격 스탯·저항·HP 계산은 호스트가 담당한다.

- `landingCell(source,direction)`은 정확한 전방 2칸 또는 null을 반환한다. `crossCells`와 `inCross`로 십자 범위를 조회한다.
- `createCast`는 `ok`, `reason`, `landingCell`, `direction`, `impactAt`, `endAt`, `impacts`, `done`, `update(now)`, `cancel(at)`를 제공한다.
- `getEnemies(at)`는 예정된 적중 시각의 권위 있는 스냅샷을 제공해야 한다. 죽은 적·잘못된 좌표·중복 ID·십자 밖 대상은 제외한다. 시전 도중 움직인 적은 적중 시점의 위치로 판정한다.
- `onImpact`는 targetIds·targets·전체 십자 cells·착지 셀·방향을 포함하는 하나의 배치를 전달한다. 각 적은 1회만 타격한다. 대상이 없어도 정상 시전이며 빈 대상 배열을 전달한다.
- 그림 생성이나 출력 실패가 전투 콜백을 막지 않는다. 콜백 재진입과 예외 뒤 재갱신으로 같은 타격을 중복 처리하지 않는다. 호스트의 자체 피해 계산 오류 복구는 호스트가 담당한다.
- 향로가 내려찍기 전에 취소하면 미래 타격과 모든 관련 시각 이벤트를 중단한다. 이미 처리한 HP 피해는 시각 취소로 되돌리지 않는다. 같은 시간으로 시전 갱신 후 `layer.tick(now)`를 호출해 종료한 시각 이벤트를 정리한다.
- 실제 공격 대상 수를 Sprite 예산으로 제한하지 않는다. 같은 칸에 200개 대상이 있을 때도 모두 판정하는 검사를 포함한다.

## 픽셀 원화와 성능

PixelLab Pixen으로 향로·사슬·번개 줄기·중앙 전류·씨앗을 생성하고 직접 검수했다. 사슬에 잘못 붙은 장식, 화살처럼 보이는 번개, 과도한 별 모양 전류와 작은 잎 묶음처럼 보이는 젬을 교정했다. 제한된 청동·황금 팔레트를 공통 적용하며 원본 투명도를 복원한다. 미세 점·그물망·반복 섬광을 사용하지 않는다.

향로·사슬은 1배 원본 픽셀, 번개 줄기는 2배 정수 크기로 사용한다. 사슬 끝부분만 잘라서 연결하며 픽셀을 길게 늘리지 않는다. 중앙 전류와 네 팔을 조합해 명확한 십자 형태를 만든다. 번개는 최대 알파 0.84이며 약 90ms에 걸쳐 나타나고 끝에서 부드럽게 사라진다. 가산 합성·화면 흔들림·전체 화면 섬광·매 프레임 난수·새 텍스처 생성을 사용하지 않는다.

네 구성 요소를 하나의 64px 아틀라스 슬롯에 배치한다. Canvas 미리보기·내보내기용 통합 아틀라스는 **465슬롯·1024×1920·7.5MiB**다. 기존 464슬롯이 가득 차 한 행이 늘어났으며 이 통합 이미지의 RGBA 증가는 256KiB다.

**MZ 실행에서는 기존 1024×1856 텍스처를 그대로 보존**하고 파문심판만 **64×64 확장 텍스처**에 배치한다. 통합 이미지의 크기 변경으로 발생하던 기존 효과의 UV 픽셀 샘플링 차이를 이 방식으로 제거했다. 실행 메모리는 **7,618,560바이트(7.265625MiB), 증가 16KiB**, 텍스처 2개·48Sprite 풀·시각 이벤트 상한 128개다. 확장 텍스처는 레이어 사이에서 공유하며 프레임마다 생성하지 않는다. 파문심판 자체의 모든 구성 요소는 그 작은 텍스처 하나를 공유한다. MZ에 복사할 파일은 `img/WorldTreePixelLabFXBase.png`와 `img/WorldTreePixelLabFXExtra.png`이며, `img/WorldTreePixelLabFX.png` 통합본은 MZ 전투 중 로드하지 않는다.

검수 장면 최대 10Sprite, 스킬별 검수 예산은 12Sprite 이내다. 모든 몬스터 수와 별개로 십자 번개는 중앙 1개와 팔 4개만 그린다. 기본 메커니즘 12개 그룹, 플레이어 5개 위치×4방향, MZ 452개 시점과 미리보기 제어 13개를 검사했다. 기존 50종의 100개 시퀀스·200개 Canvas 장면·100개 MZ 장면은 이전 버전과 동일하다. 전체 게임의 저사양 장치 성능을 측정한 결과로 확대하지 않는다.

단독 미리보기 `ripple-judgment.html`은 처음에 정지하고 버튼으로 1회 재생한다. 방향·몬스터 수를 바꾸거나 보드 칸을 눌러 플레이어를 이동할 수 있다. 타격 범위 밖 대각선 몬스터도 배치해 십자 범위와 구분한다. 원화 `pixellab/ripple-judgment-v330/`, 검수 `qa/ripple-judgment/`, 배포 젬 `assets/gems/active/ripple-judgment-seed-32-v1.png`, 이펙트 아이콘 `icons/51.png`.
