# 젬 핵 강화

군주의 핵과 창공의 힘 강화는 본편 성장/각인 화면의 별도 섹션에서 연다.
두 재료 모두 5강까지 성장하며 기존 강화 단계는 그대로 유지한다.

| 재료 | 단계당 효과 | 5강 효과 |
| --- | --- | --- |
| 군주의 핵 | 젬 피해 4% 증폭 | 피해 20% 증폭 + 젬 레벨 1 |
| 창공의 힘 | 젬 공격/시전 속도 2% 증폭 | 속도 10% 증폭 + 젬 레벨 1 |

같은 재료의 증폭 수치는 강화 단계에 비례한다. 4%를 단계마다 복리로 곱하지 않는다.
다른 피해/속도 계수와는 곱한다. 소환 공격 젬은 소환수 피해와 공격 주기에 적용한다.
스킬 고유의 고정 재사용 대기시간, 고정 지속 피해 간격과 기존 공격 속도 한도는 유지한다.
두 강화가 모두 5강이면 합계 젬 레벨 보너스는 +2다. 이전의 단계마다 +1 방식은 폐기한다.
응축 창공 영구 강화, 퀄리티, 각성, 각인은 기존 효과와 규칙을 유지한다.

| 목표 단계 | 시도당 재료 | 기본 성공률 | 실패 후 다음 성공률 |
| --- | --- | --- | --- |
| 1강 | 1개 | 100% | 확정 |
| 2강 | 2개 | 60% | 70%, 79.6%, 88.6%, 96.8%, 100% |
| 3강 | 3개 | 40% | 50%, 59.6%, 68.6%, 76.8%, 84%, 90%, 95%, 100% |
| 4강 | 4개 | 20% | 30%, 39.6%, 48.6%, 56.8%, 64%, 70%, 이후 +5%p씩 100%까지 |
| 5강 | 5개 | 10% | 20%, 29.6%, 38.6%, 46.8%, 54%, 60%, 이후 +5%p씩 100%까지 |

첫 실패는 +10%p, 이후 증가폭은 +9.6, +9, +8.2, +7.2, +6%p로 줄어든다.
그 뒤 최소 +5%p를 유지하고 성공률 100%에서 멈춘다.
실패해도 재료는 소모되고 강화 단계는 내려가지 않는다. 젬 파괴도 없다.
성공 시 해당 재료의 실패 보정만 초기화하며 전문가 경험치는 성공 시에만 지급한다.
각 젬의 `bossCoreFailures`, `skyCoreFailures`에 실패 횟수를 저장한다.
구버전 저장에는 실패 횟수 0을 적용한다. 최대 강화의 실패 횟수는 0으로 정규화한다.
재접속과 창 닫기로 보정을 잃지 않으며 루프 전환에서는 기존 젬 초기화 정책을 따른다.

## 구현 경계

- `data/gem-core-forge.js`: 강화 확률/효과 정의. 스킬 데이터보다 먼저 로드.
- `js/gem-core-forge.js`: 읽기 전용 효과/가능 여부와 강화 상태 전이. UI 의존 없음.
- `js/state.js`: 저장 형태 정규화.
- `js/skills.js`, `js/combat.js`: 젬 레벨, 실제 피해/속도, 소환수와 표시 계산 연결.
- `js/gem-core-forge-ui.js`: 재료 선택과 네이티브 모달. 상태 전이 직후 저장 예약.
- `css/gem-core-forge.css`: 군주의 핵 금색, 창공의 힘 청색, 다크/라이트/모바일.

450ms의 피드백 구간은 연속 클릭과 닫기를 막는다. 확률 판정과 재료 지불은 클릭 시점에 끝나며
연출 완료를 기다렸다가 결제하는 구조가 아니다. 상시 타이머, 입자 루프, 캔버스는 추가하지 않았다.
키보드 포커스와 reduced-motion을 지원한다.

2026-09-15 표현 수정: 충전 중에는 시도 전 단계, 효과, 확률, 보유 수량을 표시한다.
실제 상태와 저장은 즉시 반영하되, 450ms가 끝나면 화면 결과를 함께 공개한다.
최대 강화의 젬 레벨 +1은 큰 보너스 표시와 850ms의 일회성 강조로 구분한다.
최대 강화 창을 다시 열면 성공 확정 대신 적용 중인 보너스를 표시한다.
젬 그림은 PC 56px, 모바일 48px로 축소했다. 확률, 비용, 강화 효과는 변경하지 않았다.

## 검증

- `node scripts/smoke-gem-core-forge.js`: 실패 보정 천장, 독립성, 재료 지불, 저장 복원, 실패 원자성,
  구버전 기록, 실제 공격/주문/소환 피해와 속도, 공유 공속 재능, 풀강 레벨 보너스.
- 기존 콘텐츠 해금, 소환 젬, 그리드 전투 검사에 새 생산자/규칙 반영.
- `npm test`: 199개 통과.
- `npm run check:architecture`: 통과. 최종 수정도 동일 규칙의 인덱싱 검사로 재확인.
- Playwright `gem-selection-flow.spec.js`의 강화/표시 관련 3개 흐름을 PC와 모바일에서 실행.
  6개 통과. 성공, 실패, 최대 강화, 재료 부족, 다크/라이트, 화면 안 버튼 배치를 확인.
- 2026-09-15 강화 흐름 PC/모바일 2개 재검증: 충전 중 결과 비노출, 연타 중복 결제 방지,
  최대 강화 공개 시점과 재진입 보너스 표시. 전체 스모크 199개 및 동일 규칙 인덱싱 구조 검사 통과.
- 로컬 체험: `/artifacts/gem-forge/index.html`. 본편 코드를 사용하고 저장을 메모리에 분리한다.

수치는 첫 밸런스안이다. 단계당 비용은 기존과 같지만 실패 소모가 생기므로 총 소모량은 늘어난다.
실제 플레이어의 파밍 속도와 강화 만족도 검증은 아직 필요하다.
