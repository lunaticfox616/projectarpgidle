# 탐험 플레이 경험 개선 목표

목표는 실제 플레이 경험의 자체 평가 90점이다. 외형 점수나 자동 테스트 통과만으로 완료하지 않는다.
기존 세계수 시연에서 실제 플레이 평가는 68점이었다. 이전 외형 평가 86점과 구분한다.

## 완료 검증 범위

- [x] 탐험 탭 전체의 진입을 세계수 권역 지도와 공통 목적지 선택으로 연결한다. 각 콘텐츠 내부의 전투 규칙은 유지한다.
- [x] 전투 중 목적지와 전체 여정 진행을 확인한다.
- [x] 발견·완료·중단·실패의 이유와 다음 행동이 전투 화면에도 명확하다.
- [x] 벌집을 드나들어도 남은 여정을 이어갈 수 있다.
- [x] 심도별 수호자 호위와 적 무리 규모가 달라진다. 적용 중인 혼돈계 특성을 출발 전에 확인한다.
- [x] 주요 보상과 열린 목적지가 완료 순간 전달된다. 보상 중복 지급은 없다.
- [x] 이미 발견한 목적지의 반복 파밍이 불필요한 재이동을 요구하지 않는다.
- [x] 해금·입장권·강제 선택·실패 규칙을 기존 콘텐츠별로 유지한다.
- [x] PC·모바일 플레이, 저장 복원, 실패 후 재도전과 구조 검증을 통과한다.
- [x] 수정 후 실제 UI로 다시 플레이하고 근거와 한계를 기록한다.

아이콘 금지, 짧은 설명, 기존 어두운 금색 판타지 분위기를 유지한다.
일반 캐릭터 밸런스와 장기적인 재미는 강화 테스트 캐릭터의 진행 검사로 검증됐다고 주장하지 않는다.

## 작업 순서

여정 기록과 전투 피드백 → 지도 내부 거점과 전체 탐험 진입 통합 → 심도별 경험과 완료 보상 전달
→ 실제 플레이 재평가. 한 단계가 끝나도 전체 목표를 완료한 것으로 취급하지 않는다.

## 실제 플레이에서 수정한 문제

1. 발견·수호자 완료 뒤 진행도가 0%로 보이던 상태를 완료/실패/중단 상태로 구분했다.
2. 이동 계획은 `plan.nodes/stage/index`로 보존한다. 전투 큐와 분리해 발견 정지, 수동 정지,
   실패 재도전, 저장 복원, 벌집 방문에서 남은 경로가 유지된다.
3. 벌집 입장 전 탐험 중단을 요구하고, 귀환 후 자동으로 같은 지역을 다시 싸우지 않는다.
4. 지도 열기가 열린 창을 다시 닫던 토글 문제, 반복 UI 갱신이 지도 이미지를 삭제하던 코드를 수정했다.
5. 목적지가 하나인 권역은 한 번 눌러 바로 연다. 나머지는 해당 권역의 콘텐츠만 표시한다.
6. 중복된 상단 탭/좌측 목록을 하나의 목적지 선택기로 통합했다. 기존 버튼은 접근 조건과
   경로의 원본으로 남으며, 선택기는 그 버튼의 실제 동작을 호출한다.
7. 수호자 지역이 일반 혼돈계 3웨이브 계획을 타던 연결을 수정했다. 심도 I은 단독 보스,
   II는 정예 호위 1무리, III는 2무리 후 보스다. 호위는 보스 보상을 지급하지 않는다.
8. 전투 화면의 다음 심도 버튼이 값만 바꾸고 끝나지 않고 실제 다음 지도를 연다.

## 실제 UI 플레이 기록

- 기본 UI 조작으로 입구 → 숲 발견 → 벌집 방문 → 꽃가루 즉시 보상 선택 → 벌떼 1웨이브 완료
  → 원정 포기 → 남은 탐험 3/4 재개 → 회랑 → 수호자 처치를 확인했다.
- 벌집 열쇠는 3개에서 2개로 감소했고 꽃가루 +6은 즉시 지급된 보상에 표시됐다.
- 수호자 처치 뒤 전투 화면에 완료와 다음 심도 버튼이 보였다.
- 후반 권역 fixture에서 전체 세계수 → 우주계 → 항로 화면 → 세계수 복귀를 확인했다.
- 이 검증은 진행 확인용 강화 장비를 사용했다. 통상 장비의 전투 난이도, 장기 파밍 동기,
  실제 플레이어의 재미가 검증된 것으로 확대 해석하지 않는다.

## 추가 검증과 남은 목표

- 전체 스모크 189/189 통과. 발견/정지/실패 복원, 벌집 입장 비용과 복귀, 경로 보존,
  손상된 계획 데이터, 중복 완료, 심도별 실제 전투 계획을 포함한다.
- PC·모바일 세계수 브라우저 검사는 실제 전투, 완료 안내 가림, 다음 심도 전환, 이미지 유지,
  전체 권역 진입과 목록 복귀를 포함한다. 기존 계 UI/목적지 선택 검사도 함께 실행한다.
- 전체 지도의 진입 통합과 기존 네 수호자 → 최종 관문의 진행 연결은 구현했다.
  여정 중 실제 획득품 전달과 일반 세팅을 통한 반복 플레이 평가는 아직 남아 있다.
  **90점 목표는 완료로 처리하지 않는다.**
- 시연 상단 `후반 권역`은 저장과 분리된 루프 50 상태를 만든다. 실제 사용자 저장에 해금을 지급하지 않는다.
- 최종 브라우저 묶음(world-tree-journey/mobile-map-navigation/realm-workflow/ui-refinement)은
  `test-results/.last-run.json`에서 passed, 실패 목록 없음으로 확인했다. 구조 검사도 통과했다.
- 393×851 화면에서 후반 권역 지도 → 지하계 직접 진입 → 세계수 복귀를 실제 UI로 확인했고,
  점검 뒤 임시 화면 크기를 복원했다. 내부 콘텐츠의 기존 스타일은 전체 리디자인 완료로 간주하지 않는다.

## 최종 탐험 목표 연결

- 루프 31부터 기존 `pinnacle_observer.requiresPinnacles`를 읽어 세계수 지도에 최종 목표를 표시한다.
  네 권역의 미격파/조건 달성/격파 상태를 짧게 보여주고 선택한 수호자의 조건만 펼친다.
- 조건과 보상은 `getSeasonBossProgressGate`, `SEASON_BOSS_ZONES.firstClearReward`, 실제 재화 이름을
  재사용한다. 조건 미달은 해당 권역, 달성 시 기존 `changeZone` 입장 경계로 연결한다.
- 최초 보상·요구 열쇠·이동 제한을 유지한다. 완료한 관측자와 경계 너머 해금을 갖춘 경우
  다음 콘텐츠로 이어진다. 새 저장 필드, 전투 배율, 강제 수집 과제, 보상 지급 경로는 추가하지 않았다.
- PC·모바일 브라우저에서 실제 공격으로 지핵군주 처치, 1/4 반영, 재도전 보상 중복 방지,
  아스트라 열쇠 부족/충족, 루프 은하 기록 초기화 후 영구 격파 기록 유지,
  관측자 실제 처치 → 저장 복원 → 경계 너머 진입을 확인했다.
- 전체 브라우저 묶음 20/20 통과 뒤, 전투력 표시·후속 콘텐츠 진입을 추가한 최종 목표 검사
  2/2가 통과했다. 이 전투도 진행 확인용 강화 장비이며 일반 세팅의 난이도 검증은 아니다.
- 이후 시연 타이머를 전체 권역으로 확장한 최종 세계수 검사 4/4 통과. 지하계 30층은
  실시간 타이머로 출발/진행을 확인한 뒤 실제 전투 시간을 가속해 돌파하며 기록을 직접 올리지 않는다.
  전체 스모크 189/189, 최종 프로덕션 소스의 구조 검사 통과.
- 시연 갑옷에 합성 재생 20%를 추가했다. 생명력만 큰 기존 시연 캐릭터는 지하계의 비례 피해로
  계속 사망했기 때문이다. 실제 장비·몬스터·지하계 수치는 변경하지 않았다.

### 환경 피해 안내 수정

지하계 30층은 `coreLoop`에서 100ms마다 최대 생명력의 1.5%를 직접 차감한다(창공석 완화 적용 전
초당 15%). 적의 직접 공격만 평가하던 안내를 다음과 같이 수정했다.

- `getUnderworldLifeDrainPerTick`을 실제 전투와 준비도 표시가 함께 사용한다. 15/30/40층 경계,
  창공석 0~75% 완화, 100ms마다 정수 처리하는 기존 피해량을 유지한다.
- 지속 피해 지역은 '직격 생존'과 '지속 회복 부족'을 구분한다. 툴팁은 실제 최대 생명력 대비
  초당 환경 피해와 지속 재생을 표시한다. 방어도·회피·에너지 보호막은 해당 피해를 막지 않으며,
  조건부 재능·임시 보호막·플라스크·흡수는 이 비교에서 제외한다고 명시한다.
- 중력만 적용되는 지핵군주/개화 시련에 지속 피해 경고를 잘못 붙이지 않는다.
- 지하계의 최고층 입장 버튼에 낮은 현재 선택 층의 안내가 표시되던 문제를 함께 수정했다.
  최고층 지역 정의를 실제 지역 생성과 공유하며, 같은 지역 ID라도 층이 바뀌면 중력 차이를 비교한다.
- 저장 필드와 밸런스 변경 없음. 준비도 조회는 일시 보호막을 소모하지 않는다.
- 전체 스모크 189/189, PC·모바일 환경 피해/최고층 안내 검사 2/2 통과. 실제 페이지의 마우스·터치
  툴팁과 화면 안 배치를 확인했다. 낮은 최대 생명력에서는 정수 처리 때문에 표시가 15%와 다를 수 있다.
- 소스 문구 모양만 강제하던 중복 스모크 assertion 1개를 제거했다. 아래의 실제 HTML 출력 검사와
  추가한 준비도 행동·브라우저 검사가 기존 표시 계약을 보장한다.
- 지역 패널티 계산을 분리한 뒤 전체 스모크 189/189와 세계수·권역 브라우저 묶음 18/18을 다시 통과했다.
- 최종 프로덕션 소스 구조 검사 통과. 큰 준비도 함수의 조건 수를 늘리는 대신 지역 패널티 투영을 분리했다.
- 장시간 시연에서 발견한 별도 문제: 후반 권역 fixture에 해금된 심화 층 목록이 없어 일반 사냥이
  혼돈 20→21로 넘어가면 지하계가 다시 잠겼다. 후반 모드의 심화 20~30층 목록과 이번 루프 29층
  격파 기록을 일치시켰다. 실제 플레이어 진행·해금 규칙은 그대로다.

## 다음 실제 플레이 검증 기준

강화 무기로 빨리 통과하는 검사는 마무리됐다. 다음은 정상적으로 얻고 장착 가능한 장비·연결된
패시브·젬 구성으로 첫 진입과 반복 파밍을 비교한다. 성능 부하용 `offline-endgame-fixture`는
불법 패시브/합성 능력치를 포함하므로 밸런스 근거로 사용하지 않는다.

- 진입 가능한 전사 빌드에서 숲길/균열길의 소요 시간, 사망, 전용 재료 획득을 비교한다.
- 목적지를 선택하고 완료 후 다시 도전하기까지 실제 클릭 수와 강제 중단 이유를 기록한다.
- 장기 성취(최종 관문)와 반복 동기(제작 재료·고유 파밍)를 구분해 평가한다.
- 해당 장비와 빌드가 실제로 유효한지 먼저 검증하며, 빠르게 깨도록 임의 피해량을 보태지 않는다.
- `node scripts/audit-passive-requirements.js` 재확인: 전사 연결 경로 25포인트로 힘 132를 확보한다.
  일반 장비 빌드의 요구사항 확보에 사용할 수 있는 경로이며, 이 결과만으로 전투력·난이도를 검증하지 않는다.

### 일반 장비 전투 측정

- `scripts/audit-world-tree-play.js`로 실제 베이스 생성·요구사항·장착·패시브 연결·젬 장착·전투를 실행한다.
  사용자 저장은 읽지 않는다. 루프 10/레벨 100은 비교 시나리오이며 실제 육성 소요 시간을 의미하지 않는다.
- T14 희귀 후보 40개씩에서 선택한 11부위, 99 패시브 포인트, 연속 베기 20레벨과 장착 가능한 보조 젬을 사용한다.
  잠긴 세 번째 반지와 특수 입장 조건이 있는 베이스를 제외했다. 전직·영구 투자·성장판은 없는 예시 빌드다.
- HP 4,817, 표시 DPS 약 28,120, 재생 약 5.75%/초. 저항이 음수여서 후반 완성 빌드의 대리 지표로 쓸 수 없다.
  저장 왕복 시 능력치 유지, 요구사항으로 비활성화된 장비 없음, 포인트 예산 준수를 브라우저에서 검증한다.
- 기존 구성에서는 난수 3개 모두 입구의 일반 보스에게 72.5~93.1초에 사망했다.
  입구·갈림길에 반복 보스를 두는 대신 3차례 무리 전투로 변경했다. 회랑은 정예 무리,
  마지막 수호자는 기존 보스 능력치를 유지한다. 반복 보스 삭제에 따라 해당 보스 드랍 기회도 줄어든다.
- 변경 후 3개 조건 모두 입구 통과. 숲길은 215.2/236.8초 사망 및 300초 제한 시간 초과 1회,
  균열길은 144.7~149.6초 사망했다. 긴급 회피 규칙 추가만으로 이 결과가 개선되지는 않았다.
  이 샘플로 전체 난이도를 더 낮추거나 성공률을 확정하지 않는다.
- 무리 전투 준비도는 한 무리의 생명력과 2.5초 동시 공격 추정으로 분리한다. 존재하지 않는 보스 패턴·보스 저항 압박을
  적용하지 않는다. 정예의 무작위 특성, 플레이어의 광역 효율·이동 등은 근사치 한계다.
- 체험 페이지의 `일반 장비 체험`에서 동일한 장비를 실제 전투로 확인할 수 있다. 기존 강화 장비 모드는 화면 흐름 확인용이다.
  `legal-build.json`, `legal-build-report.json`, `legal-combat-before.json`, `legal-combat-report.json`에 시나리오와 결과를 분리 보관한다.
- 전체 스모크 189/189, PC·모바일 세계수/최종 관문/일반 장비 체험 6/6 통과.
  패시브 요구량 감사도 공용 경로 계산 추출 후 재실행했다. 최종 소스의 구조 검사 통과.
  첫 검사에서 무리 준비도 함수의 조건 수 증가를 찾아 등급별 입력을 묶었으며, 재검사에서 통과했다.
  실제 브라우저에서도 일반 장비의 입구 통과·숲길 사망·경로 유지·다른 목적지 재선택을 확인했다.
  감사 함수 정리 후 장비 생성부터 12개 전투 사례를 다시 실행해 같은 능력치와 결과를 재현했다.
- 아직 미완료: 저항을 갖춘 후반 빌드의 완주/반복 파밍, 보상 체감, 권역별 내부 UI의 완성도.
  자동 검사 통과를 실제 플레이 경험 90점 달성으로 취급하지 않는다.

### 탐험 획득 내역

- 전투 HUD의 발견·완료·실패 상태에 획득 재화 종류/장비 개수와 `획득 보기`를 연결했다.
  지도 안의 접힌 획득 내역을 바로 열며, 목적지를 바꿔도 펼친 상태를 유지한다.
- 실제 몬스터 보상 생성과 균열 완료 보상에서 지급이 확정된 재화·보관된 장비만 기록한다.
  제작·거래처럼 전투 보상 범위 밖의 지급은 포함하지 않는다. 드랍률·수량과 지급 시점은 바꾸지 않았다.
- 희귀 이상 주요 장비는 최대 3개, 고유를 우선하여 이름·부위·등급·ID만 남긴다.
  옵션 확인은 기존 장비 툴팁을 재사용하며 PC 호버/모바일 터치를 지원한다.
  자동해체된 장비는 보유 장비로 표시하지 않으며, 이후 처분한 장비는 상세 버튼이 비활성화된다.
- 기록은 같은 여정의 구간 이동·발견 정지·실패·재도전·저장 복원에 유지된다.
  새 여정 출발 시 표시 기록만 비운다. 완료 처리를 다시 호출해도 보상을 재지급하지 않는다.
- `explorationLoot`는 표시용 저장 필드다. 기본값은 null, 저장 경계에서 잘못된 재화 키·무한 수치·
  손상된 장비 행을 제거한다. 새 모듈은 state 뒤에 로드하고 UI 의존을 갖지 않는다.
- 전체 스모크 190/190, PC·모바일 세계수/최종 관문/일반 장비/획득 확인 8/8 통과.
  브라우저 검사에서 발견한 재화 수량 formatter 오류를 수정했고, 획득 내역을 펼친 뒤
  목적지를 변경하는 회귀 검사도 통과했다. 강화 시연 장비의 비교 수치는 밸런스 근거가 아니다.
- 실제 UI로 출발 → 입구 → 숲 발견 → 획득 보기를 눌러 자연 드랍 꽃가루가 기록되는 것을 확인했다.
  이 과정에서 지도를 숨긴 채 탐험을 끝내면 첫 클릭이 내역을 펼치지 못하는 문제를 재현했다.
  기존 브라우저 검사를 같은 순서로 고쳐 PC·모바일 모두 실패함을 확인했고, 지도 재개방 시
  최신 내역을 동기 렌더한 뒤 펼치도록 수정했다. 지도가 이미 선택된 경우의 탭 전환 조기 반환이 원인이었다.
- 수정본을 실제 UI로 다시 출발해 숲 발견까지 진행했다. 자연 드랍 `꽃가루 +1`, `희귀한 구리 반지`
  가 첫 획득 보기 클릭으로 펼쳐졌고, 반지를 눌러 T14 피해 증가 등 실제 옵션을 확인했다.
  이 경우 별도 보상 fixture는 주입하지 않았다. 전투 장비 자체는 진행 확인용 강화 fixture다.
- 이어서 `남은 탐험 계속`으로 회랑·수호자를 실제로 격파했다. 최종 HUD는 `수호자 처치 · 심도 완료`,
  재화 2종/장비 4개를 표시했고, 획득 보기에서 앞서 얻은 꽃가루와 반지 및 이후 드랍한
  `열쇠: 서리 여제 +1`이 같은 내역에 유지됐다. 다음 심도 진입 버튼도 표시됐다.
- 첫 열기 수정까지 포함한 최종 소스: 전체 스모크 190/190, PC·모바일 브라우저 8/8,
  구조/lint 래칫 검사 통과. 탐험 전투의 획득 기록 연결은 완료했으며 전체 경험 목표는 계속 진행 중이다.

### 일반 진행 상태의 벌집 첫 방문

- 방어 선별 빌드로 진행하면서 첫 방문자는 벌집을 발견해도 거점이 표시되지 않는 조건을 찾았다.
  `unlockedPermanent`는 벌집 여왕 처치 후 기록인데, 세계수의 거점 표시와 열기에 사용하고 있었다.
  화면 진입은 기존 `contentProgression.canOpen('map-explore-beehive')`를 사용하도록 바로잡았다.
  영구 클리어 기록, 입장권 소모, 벌집 전투와 이후 재료 드랍 해금은 변경하지 않았다.
- 숲길의 재방문 안내는 `벌집 원정`으로 표시한다. 벌집 미클리어 상태에서 꽃가루 파밍이 바로
  가능한 것처럼 보이던 `벌집 재료` 문구를 제거했다.
- 체험 페이지 `처음부터`는 이제 벌집 미클리어 상태다. 기존 강화 시연이 영구 클리어 상태였기 때문에
  첫 방문자 문제를 가리고 있었다. 발견 완료·후반 권역 모드는 기존 클리어 상태를 유지한다.
- PC·모바일 기존 세계수 검사를 미클리어 상태로 바꿔 거점 누락 실패를 확인했다.
  수정 뒤 실제 거점 버튼 → 벌집 화면 → 열쇠 0개 입장 불가 → 1개 소모 입장,
  영구 클리어 기록이 여전히 false인 상태까지 검증했다.

### 방어 선별 감사 확장

- `node scripts/audit-world-tree-play.js --defense`는 같은 T14 후보 생성·장착 검증을 사용하여
  부위별 추가 희귀 후보 160개를 실제 전체 능력치로 비교한다. 기본 40개와 합해 부위별 200개다.
  후보 선별은 피해·생명력·저항·재생·방어도·정확도를 고려하는 휴리스틱이며 최적 빌드 보장이 아니다.
- 기존 기본 선별 자료는 보존하고 `defense-build.json`, `defense-build-report.json`,
  `defense-combat-report.json`으로 분리한다. 실제 입수 시간이나 제작 비용을 측정한 자료가 아니다.
  카오스 저항이 충분하지 않은 결과를 완성된 방어 빌드로 부르지 않는다.
- 전투 측정 상한을 5분에서 30분으로 늘렸다. 시작 인벤토리의 교체 전 장비는 획득 결과에서 제외한다.
  루프 10의 완료 루프 수를 9로 일치시키고, 잘못된 autoSalvage 설정 키를 실제 키로 수정했다.
- 이번 측정은 기존 99포인트·일부 보조 젬 외 전직과 영구 성장 수단이 없는 빌드다.
  전체 성장 수단을 갖춘 후반 캐릭터의 난이도 근거로 사용하지 않는다.
- 완료 루프 수 9로 맞춘 최종 방어 선별 빌드는 HP 4,934, DPS 32,001, 재생 5.69%,
  화염/냉기/번개/카오스 저항 66/16/32/-60%다. 6개 기본 시나리오 중 숲길 2개만 회랑에 도달했고,
  나머지는 숲 또는 균열에서 사망했다. 긴급 회피만 추가한 6개 시나리오도 결과가 같았다.
  12개 모두 완주하지 못했으며, 이 선택 알고리즘은 방어 균형을 잘 맞춘 빌드를 만들지 못했다.
  일반 빌드 snapshot도 완료 루프 수를 일치시켜 재생성했다. 예전 `legal-combat-report.json`은
  이전 루프 카운터 조건의 역사적 측정이며, 새 snapshot의 현재 난이도 수치로 인용하지 않는다.
- 첫 방문 실기 확인: 처음부터 → 실제 숲 전투 완료 → 벌집 살펴보기 → 입장 비용/보유 3개 확인 →
  벌집 입장 → 첫 3개 갈림길 선택지 표시. 별도 영구 클리어 상태를 주입하지 않았다.
- 벌집 내부에서는 이전 세계수 구간의 획득 내역을 현재 벌집 보상처럼 HUD에 표시하지 않는다.
  벌집 자체의 확보 보상/여왕 보류 보상은 기존 벌집 패널이 표시하며, 세계수 내역은 돌아오면 유지된다.
- 최종 수정본을 처음부터 실제로 다시 진행하여 첫 벌집 입장 후 HUD가 `벌집 원정 · 갈림길 0/10`,
  원래 목적지, `탐험 지도`를 표시하고 이전 획득 요약이 사라진 것을 확인했다.
  모바일 검사는 지도 화면에 숨겨진 전투 HUD를 검사하지 않고, 실제 `전투 보기`를 눌러 확인한다.
- 최종 스모크 190/190, PC·모바일 세계수 브라우저 묶음 8/8, 프로덕션 구조/lint 검사 통과.
  방어 선별 12개 전투는 완료 루프 수 수정 후 재실행했다. 이번 변경으로 전체 경험 90점 목표가
  달성됐다고 주장하지 않으며, 균형 잡힌 후반 빌드의 완주와 반복 보상 검증을 다음 작업으로 남긴다.

### 전직·루프 투자 후 실제 전투 감사

- `node scripts/audit-world-tree-growth.js`는 위 방어 선별 snapshot을 사용하고, 완료 루프 9회의
  루프 패시브 9포인트를 실제 `buySeason`으로 투자한다. 장비 추가 생성이나 합성 피해 보너스는 없다.
  전직 해금도 실제 포인트를 지불하며, 전직 시련 1·2는 `coreLoop`로 각각 36.1초·37.2초에 격파했다.
  해당 클리어로 받은 일반 전직 4포인트·키스톤 2포인트만 실제 구매 handler로 사용한다.
  확인 창만 플랫폼 경계로 대체하며, 전투·클리어·보상 판정은 대체하지 않는다.
- 저장 왕복 후 장비 비활성화가 없고 포인트 초과 투자가 없음을 확인했다.
  HP 5,609, DPS 44,938, 방어도 1,187, 피해 감소 18%, 재생 6.81%다.
  저항은 66/16/32/-60% 그대로이며 다른 영구 성장·제작·최적화 수단은 미완성이다.
- 서로 다른 난수 3개씩의 실제 경로 전투에서 숲길은 383.8~394.6초 후 회랑에서 실패했다.
  균열길은 528.6초·787.2초에 회랑에서, 1,466.2초에 수호자에서 실패했다.
  마지막 기록은 물리 2개·카오스 3개·냉기 1개로 갈렸다. 전체 후반 빌드의 대표 표본은 아니다.
  자연 보상은 시나리오별 재화 0~2종, 보유 장비 0~2개였다. 동일 전투를 재현하기 위해
  `simulateJourneyRoute`를 기존 감사와 공유하도록 이동했으며 실제 게임 로드 순서는 변경하지 않았다.
- 실제 UI의 일반 장비 체험에서는 출발 전 이미 `화력 부족 · 생존력 부족`이 표시됐다.
  이 결과만으로 적의 피해나 생명력을 낮추지 않았다. 현재 시연의 빠른 완주는 별도의 강화 장비를
  사용한 흐름 검사이며 일반 성장 빌드 난이도 검사와 구분한다.
- 전직 투자 snapshot을 기존 권장치 함수로 다시 비교하면 입구/숲/균열은 권장 DPS
  77,679/82,340/82,340, 회랑은 166,002, 첫 수호자는 3,794,047이다. 회랑 생존력은
  `적정`이나 화력은 권장의 27%라 장기전 실패를 설명할 여지가 있다. 수호자의 권장 화력은
  회랑의 약 23배이므로, 다음 검토에서는 실제 보스 체력·재생·목표 처치 시간과 대조해야 한다.
  안내 수치만 보고 수호자의 실제 난이도를 단정하거나 배율을 낮추지는 않았다.
- 같은 루프·심도에서 `createEnemy`를 고정 난수 0.5로 실행한 첫 수호자 표본은 실제 체력
  91,056,282, 기본 재생률 0.00048/초(초당 43,707)였다. 권장 DPS 3,794,047은 그 체력을
  기존 목표 시간 24초로 나눈 값과 일치한다. 현재 표본 빌드의 표시 DPS 44,938은 방어·피격
  중단을 고려하기 전부터 재생량과 비슷하므로, 이 빌드로 수호자 반복 파밍을 검증할 수 없다.
  UI 경로 완주와 적정 세팅의 전투 완주를 구분하고 기존 혼돈계 전투 배율은 보존했다.

### 실패 후 판단과 재도전

- 실패한 여정의 재도전 버튼 옆에 `사망 기록`을 연결했다. 기존 `openLastDeathLog`와 데스로그
  팝업을 재사용한다. 별도 분석 계산·새 저장 필드·자동 이동·자동 재도전은 추가하지 않는다.
  기록이 없는 이전 저장에서는 버튼을 표시하지 않으며, 재도전하면 버튼이 사라진다.
- PC·모바일 기존 탐험 테스트를 확장해 수정 전 사망 기록 진입 실패를 확인했다.
  수정 후 실제 버튼으로 팝업 열기 → 확인으로 닫기 → 정지 상태 유지 → 남은 경로 재도전,
  이후 수호자 격파·다음 심도까지 8/8 통과했다. 전체 스모크도 190/190 통과했다.
- 실제 체험 화면에서도 출발 → 실패 체험 → 사망 기록을 눌러 기존 금색 테두리 팝업이
  지도 위에 열리는 것을 확인했다. 이는 실패 UI 검사이며 자연 전투 패배 자료는 위 별도 보고서다.
- 목표는 계속 진행 중이다. 다음 검토는 여러 성장 빌드의 준비 상태별 완주 시간과
  반복 파밍의 보상 체감이며, 단일 장비 선별 알고리즘의 실패율을 전체 난이도로 일반화하지 않는다.
- 구조 검사에서 표시 함수의 복잡도 초과 1건을 발견해 사망 기록 버튼의 표시 조건만
  같은 UI 모듈 안으로 분리했다. 최종 소스의 관련 PC·모바일 재검사 2/2,
  전체 스모크 190/190, 구조/lint 래칫 검사 통과. 새 전역과 스크립트 의존 순서 변경은 없다.

## 최종 전투 곡선과 반복 탐험 검증

위 단계별 평가는 당시의 중간 기록이다. 아래는 수호자 난이도와 보상 안내를 수정한 후의 결과다.

  5,884,531, 변경 전 첫 세계수 수호자는 91,056,282였다. 첫 심도에서 약 15.5배의 체력 상승이

### 정상 옵션으로 구성한 상위 제작 표본

`node scripts/audit-world-tree-crafted.js --tier=15` 및 기본 T20 실행은 기존 성장 snapshot의
실제 베이스·99개 연결 패시브·전직 시련 보상·루프 투자에, 부위별 허용 옵션을 최대 5개씩 붙인다.
옵션은 실제 후보/티어 함수의 상위 수치이며 요구사항과 저장 왕복을 통과한다.
합성 피해·생명력은 추가하지 않는다. 옵션 선별은 휴리스틱으로, 최적 빌드·평균 드랍·제작 비용이나
입수 시간을 나타내지 않는다. 이 제한은 체험 페이지의 `T15 상위 제작` 표기와 함께 유지한다.

| 표본 | 변경 전 숲길 전체 | 변경 후 숲길 전체 |
| --- | --- | --- |
| T15: DPS 1,962,729, HP 9,230 | 난수 2개 모두 수호자에서 30분 상한 도달 | 197.6초 / 187.7초 완주 |
| T20: DPS 7,774,692, HP 9,101 | 228.0초 / 243.9초 완주 | 137.0초 / 140.6초 완주 |

- T15의 균열길은 214.9초 / 211.4초, 37킬로 완주했다. 숲길은 28킬이다.
  T20은 수호자 이전 구간 시간이 변경 전후 같았으며, 첫 보스전의 정체만 줄었다.
- `node scripts/audit-world-tree-repeat.js`는 같은 T15 캐릭터의 경험치·생명력·젬·기록을 유지한다.
  숲길 첫 완주 197.6초 뒤 직접 재도전 3회가 75.5초 / 75.5초 / 74.4초였다.
  각 재도전은 수호자 1마리만 상대한다. 이후 심도 II 균열길은 546.3초에 완주했다.
- 자연 보상에 희귀한 영혼 결속봉, 일반 장비, 마법의 새싹 등이 포함됐고, 재도전 중 1회는
  장비·재화가 없었다. UI를 풍성하게 보이게 하려고 보상이나 드랍 확률을 주입하지 않았다.
  III의 일반 장비 완주와 장기 기대 수익은 이번 표본으로 확정하지 않는다.

### 실제 화면 재평가

- 제작 장비 체험 → 이곳까지 탐험 → 숲 발견 → 남은 탐험 계속 → 수호자 처치 → 획득 보기
  → 다시 사냥 → 재처치를 실제 UI로 진행했다. 전투 시간은 시연 4배속과 위 원속도 감사 자료를 구분한다.

  보상 창 열기·지도/전투 전환 같은 선택 조작은 이 수에 포함하지 않는다.
- 주얼 미해금 상태에서 얻을 수 없는 공허의 끌이 균열 보상으로 표시되던 문제를 수정했다.
