# 바닥 드랍 연출 실제 반영 — 2026-09-11

현재 개발본 `pr-repo/index.html`에 적용했다. 배포·PR 생성은 이번 요청 범위에 없다.

## 보상과 표현의 경계

- `rollEquipmentLoot`가 습득을 확정한 뒤 `queueEnemyGroundLoot`에 읽기 전용 표시 영수증을 전달한다.
  자동해체, 공간 부족 해체, 습득 필터 거절 장비는 나타나지 않는다. 생장 아이템·주얼 습득도 같은 연출을 쓴다.
- 일반 몬스터 재화 드랍은 `awardCurrency`가 반환한 실제 지급량을 전달한다. 전문가 보너스를 포함하며
  미해금 재화는 생성하지 않는다. 특수 45면체는 전용 지급 함수의 반환량을 사용한다.
- 기존 보상 지급 시점·드랍 확률·저장 형식은 유지한다. 흡수 애니메이션은 보상을 지급하지 않는다.
  연출 중 이동·창 닫기·백그라운드 전환으로 지급된 보상을 잃거나 두 번 받지 않는다.
- 전투 결과는 기존 `battleFx`에 최소 정보(이름, 베이스, 부위, 등급, 재화 키·수량, 사망 칸, 지역)를 남긴다.
  장비 옵션 배열이나 변경 가능한 원본 장비를 보유하지 않는다.
- 방치 정산·숨긴 문서에서는 표시 영수증을 생성하지 않는다. 렌더러에서 포인트·보상 계산을 호출하지 않는다.
- 플라스크 발견·봉인 아르카나 같은 별도 콘텐츠 알림은 기존 전용 연출을 유지한다.

## 화면

- 몬스터의 실제 렌더 위치(사라진 적의 마지막 위치 포함)에서 아이템이 포물선으로 떨어진다.
  아직 렌더된 적 위치가 없을 때만 저장한 사망 칸을 화면 좌표로 바꾼다.
- 같은 프레임의 같은 적 드랍은 원형으로 배치한다. 아이템 바로 위에 이름을 표시한다.
- 아이템·이름·빛기둥은 불투명도 82%이며 캐릭터 뒤, 흡수 잔광은 캐릭터 앞이다.
- 수량 1은 생략한다. 황금률은 재화창의 `getStyledOrbName` 결과를 그대로 사용한다.
  빛은 기존 황금률 획득 배너의 금색·옅은 금색을 사용한다.
- 고유·목표 장비·황금률은 빛기둥과 약 3.3초 표시, 일반 드랍은 약 2.4초 표시 후 자동 흡수한다.
- 실제 캐릭터와 바닥을 같은 프레임에서 한 번씩 그린다. 전경 캔버스는 필요할 때만 크기를 할당하며,
  연출이 끝나면 1×1로 축소한다. 숨긴 전투의 모바일 PiP는 원래 단일 캔버스로 그린다.
- 지역 이동, 전투 시각 효과 초기화, 문서 숨김 시 노드·타이머·입자를 정리한다.

## 성능과 제한

- 좁은 전투 화면은 동시 16개, 넓은 화면은 24개. 한 프레임 생성량도 같은 상한을 사용한다.
  초과하면 중요한 드랍 표시를 우선하고 일반 표시를 생략하거나 교체한다. 실제 보상은 전부 지급된다.
- 흡수 잔광·도착 섬광은 합계 48개 이내. 별도 requestAnimationFrame·무한 빛기둥 애니메이션은 없다.
- 로컬 Chromium 측정: 준비 프레임 10회 후 렌더 호출 80회.
  PC 중앙값 약 0.20ms → 0.20ms, 모바일 에뮬레이션 약 0.20ms → 0.20~0.30ms.
  80개 표시 요청을 상한으로 줄여 새 DOM을 만드는 첫 프레임은 PC 약 14.7ms, 모바일 에뮬레이션 약 14.2ms.
- 최대 표시 상태의 추가 RGBA 비트맵: PC 2,824,464바이트(약 2.69MiB), 모바일 1,233,232바이트(약 1.18MiB).
  GPU 합성·전체 전투 비용·실제 Android 발열 측정은 아니다. CPU 중앙값만으로 무비용이라 주장하지 않는다.
