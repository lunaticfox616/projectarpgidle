# 설정과 화면 배율

## 현재 설정 구성 (2026-10-16)

분류는 화면과 소리 / 전투 / 자동 진행 / 알림과 채팅 / 조작 / 저장과 계정 여섯이다. PC는 왼쪽 목록,
좁은 창과 모바일은 위쪽 세 칸 두 줄이다. 한 분류는 묶음(`.cfg-block`)과 한 줄 항목(`.cfg-row`: 이름과 짧은 설명,
오른쪽 끝에 조절)으로 짓고 자주 쓰는 항목을 접지 않는다. 접는 곳은 메뉴 순서 바꾸기, 저장 복구와 진단 둘이다.
단축키 묶음은 터치 기기에서 숨기고, 로그인 전에는 로그아웃, 클라우드 불러오기, 계정 연결을 숨긴다.

- `js/settings-ui.js`: 일반 설정의 DOM 읽기·쓰기·동기화와 분류 선택. 이벤트가 발생한 필드만 저장한다.
- `js/main.js`: 저장 복원 뒤 `settingsUi.sync()`. 설정 창을 다시 열 때도 같은 동기화를 사용한다.
- `js/ui-audio.js`, `js/ui-display.js`, 기존 외형·저널·단축키 모듈은 각 전용 동작을 소유한다.
- `css/settings.css`: 설정 창 배치와 분류 숨김. PC/모바일에 서로 다른 분류 로직을 두지 않는다.
- 새 일반 옵션은 기존 저장 필드와 `checks` 또는 `selects` 한 항목을 연결한다. 새 저장 필드라면 기본값과 저장 마이그레이션도 필요하다.

생명력·경험치·캐릭터 쉼표 4개는 한 스위치로, 로그 집계·빈도 제한 2개는
‘반복되는 타격 묶기’로 조절한다. 저장 필드 자체는 유지한다. 예전 값이 서로 다르면
스위치에 혼합 상태를 표시하며, 해당 스위치를 직접 바꿀 때만 모두 같은 값으로 바꾼다.
분류를 열거나 다른 설정을 바꿔도 숨은 항목·진행·장비를 덮어쓰지 않는다.
일반 설정 변경은 즉시 적용하고 기존 중요 저장 대기열로 저장한다.
`showStoryLog`는 전투 분류 전투 기록의 ‘대사’에 연결하고 전투 로그 전체 표시와 따로 조절한다.

전투 기록은 150ms마다 모아서 붙이고 최근 60줄을 남긴다. 최신 줄을 보던 중이면 계속 따라가며, 이전 줄을 읽는 중이면
같은 행의 화면 위치를 보존한다. 읽던 행이 지워지면 남은 가장 오래된 행을 보여 준다. 숨긴 기록은 위치를 재지 않는다.
접었다 펼치면 최신 줄부터 보여 준다. 모바일 전투 화면에서 기록을 펼친 동안에는 같은 내용을 복제한 기록 알림을 숨겨
읽던 글과 터치 스크롤을 가리지 않게 한다. 기록을 접으면 남아 있는 알림과 탭해서 닫는 동작이 다시 보인다.
기록에 복제되지 않는 게임 알림은 유지하되, 세로 화면에서는 펼친 기록 막대 위로 쌓아 접기 버튼을 가리지 않는다.
위치 보정은 화면 배율(`uiDisplay.factor`)을 반영하고, 코드가 옮긴 위치와 실제 스크롤 위치를 비교한다.
시간창으로 스크롤 입력을 무시하지 않는다(2026-10-17: 자동 스크롤 직후 휠 입력이 사라지던 문제 수정).

하나뿐인 UI 스킨 선택 UI, 방 단위 전투에 해당하지 않는 몬스터 과밀 로그 선택 UI,
중복 계정 화면 단추를 제거했다. 과밀 로그의 이전 저장 선호와 비무대 콘텐츠 동작은 유지한다.
전장 그림을 숨기던 ‘전투 화면 표시’(`showCombatScene`)도 지웠다(2026-10-16). 이전 저장의 값은 읽지 않는다.
‘일시 정지’는 현재 구현대로 안내·선택 창에 적용하며 일반 메뉴 창 전체를 멈춘다고 안내하지 않는다.

글꼴과 아이템 그림 선택은 삭제했다. 갈무리 역할 규칙과 원화 경로를 항상 사용하며,
저장된 `uiFont`·`iconArtStyle`은 불러올 때 버린다. 수집한 몬스터로 변신하는 선택·렌더링·새 획득 알림도
제거한다. `selectedMonsterSkin`은 버리고, 과거 수집 기록과 플레이어 외형 선택은 보존한다.
전투 전술은 설정에서 빼고 **스킬 젬 → 전술 규칙**의 기본 전술과 조건부 규칙으로 통합했다.
새 게임의 해금은 [콘텐츠 진행 규칙](content-progression.md)의 전투 전술 항목을 따른다.

## 글꼴과 텍스트 규칙 (2026-10-16)

글꼴은 갈무리로 고정한다. OS 배율·브라우저 줌·게임 UI 배율이 달라져도 일반 글꼴로 전환하지 않는다.
수동 글꼴 선택도 없다. 이전 저장의 `auto`·`pixel`·`smooth` 등 글꼴 선택값은 모두 폐기한다.
배율 보정 계산과 저장된 `uiScale`은 그대로다.

| 역할 | 글꼴 / 실제 굵기 | 기준 CSS 크기 | 적용 |
| --- | --- | --- | --- |
| 조작·짧은 정보 | Galmuri11 Regular 400 | 12px | 버튼, 탭, 설정 이름·값, 전투 기록, 짧은 수치 |
| 긴 글 | Galmuri14 Regular 400 | 15px | 대사, 이야기 본문, 설명, 툴팁 본문 |
| 독립 제목 | Galmuri11 Bold 700 | 24px | 창 제목, 창 안 h1·h2, 이야기 장면 제목 |
| 소제목·강조 | Galmuri11 Bold 700 | 12px | 설정 분류, h3, 툴팁 제목·구획, 짧은 강조·주요 조작 |
| 선택적 보조 표기 | Galmuri9 Regular 400 | 10px | 패치 날짜, 좁은 칸의 표식(조건 부족, 가방 칸의 긴 부위 이름, 출처 꼬리표, 보조 룬 ◆), 시작 화면의 약관 링크. 조작 안내·아이템 옵션·대사에는 쓰지 않음 |

- 기본 가족·크기·굵기 토큰은 `css/tokens.css`의 `--font-pixel*`, `--font-size-*`, `--font-weight-*`에 둔다.
  DOM 역할 배정은 `css/themes/pixel.css`가 소유하고, 설정 등 컴포넌트는 같은 토큰을 재사용한다.
  같은 역할의 크기를 바꿀 때 개별 창마다 덮어쓰지 않고 공통 토큰·소유 규칙을 고친다.
  아래 층(components, features)에서 고른 글꼴 가족은 `pixel.css`의 `:where(*)` 되돌림에 지워진다.
  갈무리14와 9를 쓸 요소는 `pixel.css`의 역할 목록에 넣는다(크기만 바꾸면 갈무리11 15px처럼 번진다).
- 자간은 0이다. 갈무리는 글자 사이의 한 도트가 글자 폭에 들어 있어, em 자간은 글자마다 소수 화소씩 밀려 획이 번진다.
  넓혀야 하는 곳만 정수 px를 쓴다(`pixel.css`가 아래 층의 자간을 0으로 둔다).
- 글이 정수 기기 화소에서 시작해야 획이 한 화소에 선다. 똑같이 나누는 격자 칸은 `round(down, …, 1px)`로 정수 px를 쓴다
  (첫 칸만 `minmax(0, 1fr)`로 남는 폭을 받으면 칸 끝이 맞는다). 칸 수가 폭에 따라 바뀌는 격자(auto-fill)는 크기 기준인
  바깥 칸의 `100cqw`로 칸 수와 정수 폭을 계산한다(`talent-bloom.css`의 `.talent-board`). 길이를 길이로 나누는 식은
  `calc()` 없이 `round()` 안에 바로 쓴다(빌드의 postcss-calc가 `calc()` 안의 그 나눗셈에서 멈춘다). 계산으로 놓는 노드(루프 원환,
  아틀라스 지도)는 `left`, `top`, `translate(-50%)`를 `round(…, 1px)`로 감싼다.
- 가운데 맞춘 글은 글 폭과 칸 폭의 홀짝이 다르면 반 화소에 놓인다. 한 줄 글은 span으로 감싸 `.px-center`를 붙인다
  (`pixel.css`, 가운데로 맞추는 칸에서만 켠다). 두 줄로 접히는 가운데 글은 줄마다 반 화소가 남을 수 있다.
- 캔버스 글은 `drawCrispCanvasText`(`js/utils.js`)로 정수 화소에 그리고, 크기는 갈무리의 제 크기(`pixelFontSize`)를 쓴다.
  글 테두리(stroke)는 짝수 폭이다(홀수 폭은 테 바깥이 반 화소에 걸린다).
- 11과 14를 같은 문장 중간에 섞지 않는다. 11 문장의 강조는 실제 Bold 700을 쓸 수 있다.
  14 본문은 400을 유지하고 기존 능력치·상태·희귀도 색상 규칙으로 강조한다. 고유명사 전부에
  임의의 새 색상을 부여하거나 이야기 원문에 자동으로 강조 표식을 삽입하지 않는다.
- `font-synthesis: none`을 유지한다. Thin·Light·Medium·Black을 있다고 간주하지 않으며,
  겹쳐 찍기로 가짜 굵기를 만들지 않는다. 이탤릭이 필요하면 사용자의 의도를 먼저 확인한다.
- 독립 읽기 영역은 위아래 `--space-1`(4px), 좌우 `--space-2`(8px), 툴팁 바깥 판은
  `--space-3`(12px)를 기준으로 한다. 문장 안의 span·강조 단어에는 별도 padding을 주지 않는다.
  기존 상위 판·제목 줄의 여백을 중복 적용하지 않고, 버튼의 클릭 영역·HUD 그림 칸은 해당 컴포넌트가 소유한다.
- 작은 보조 글도 Regular를 쓰고 `--color-text-secondary`로 충분히 밝게 둔다. 중요한 정보는 작은 글꼴로 낮추지 않는다.
  툴팁의 베이스·레벨 같은 짧은 표기는 11/12px, 옵션 설명은 14/15px로 구분한다.
- 도트 기준 크기(11→12px, 14→15px, 9→10px)와 정수 배율을 우선한다. 사용자의 UI 배율은 강제로 반올림하지 않는다.
  캔버스의 카메라 확대·축소나 연출 크기는 유지하고, 그리기 글꼴은 갈무리로 통일한다.
  외부 로그인 서비스의 공식 버튼 글꼴은 예외다.

폰트 파일은 `assets/fonts`에 함께 배포한다. 추가한 11·11 Bold·9는 제작자의
[공식 저장소](https://github.com/quiple/galmuri)의 `71e1cacf1437a11220307120e63e30bc275312d4` 배포본이다.
기존 Galmuri14와 `LICENSE-Galmuri.txt`를 유지한다. SIL OFL 1.1의 저작권 고지·원문을 배포본에도 포함한다.

## UI 배율

PC에서는 `최종 CSS 배율 = uiScale / 100 / (DPR / floor(DPR))`를 사용한다(DPR 최솟값 1).
Windows 125/150% 같은 소수 배율을 보정하며, 200%·Retina의 정수 배율은 유지한다.
창이 작아져도 사용자 설정을 자동으로 바꾸지 않는다. 가용 공간이 부족하면 기존 반응형 배치와
스크롤을 사용한다. 스마트폰·태블릿의 높은 DPR은 Windows 배율이 아니므로 역보정하지 않는다.

브라우저는 OS 배율과 브라우저 줌을 합친 DPR을 제공한다. 웹판의 기준은 브라우저 줌 100%이며,
크기는 게임 설정에서 변경한다. 모니터의 물리적 크기(mm)까지 같게 만드는 기능은 아니다.
향후 Steam 셸에서 OS 배율 API를 제공하면 DPR 읽기 경계만 교체한다.

## 소유와 좌표

- `js/utils.js`: 저장된 사용자 배율 정규화(80, 90, 100, 110, 125, 150, 175, 200, 225, 250; 기본 100).
- `js/state.js`, `js/save-migrations.js`: `settings.uiScale`. 모니터 배율 자체는 저장하지 않는다.
- `js/ui-display.js`: 디스플레이 배율, 루트 CSS zoom, 논리 화면 기준 media query, 설정 이벤트.
- 기존 창 관리자는 논리 좌표로 위치를 저장한다. 포인터/getBoundingClientRect 값은 화면 좌표다.
  CSS left/top에 넣을 때는 최종 배율로 나눈다. 캔버스 클릭은 표시 사각형과 논리 크기의 비로 변환한다.
- 전투·패시브 캔버스는 논리 크기와 실제 표시 배율을 함께 써서 불필요한 이중 고해상도 버퍼를 피한다.

레거시 CSS가 사용하는 vw/vh와 media query도 같은 논리 화면을 봐야 한다. 어댑터는 최초 로드와
head에 스타일시트가 추가될 때 기존 CSSOM 선언을 변환하고, 원래 media query는 별도로 보관한다.
매 프레임 DOM을 순회하지 않으며 스타일 속성 변경도 관찰하지 않는다. authored cascade는 그대로다.
새 인라인 스타일의 viewport 단위는 `calc(95vw / var(--ui-display-factor, 1))`처럼 작성한다.
JS의 UI 너비 조건은 `uiDisplay.matches()`를 사용한다. 컨테이너 질의로 전체 이전하면 CSSOM 변환을 제거한다.

## 검증

- 설정 변경 시 실제 게임에서 분류 이동, 설정 변경·재시작 복원, 작은 화면의 스크롤과 조작을 확인한다.
- 묶은 옵션은 이전 저장의 혼합 값 보존과 해당 옵션만 변경되는지 확인한다.
- 화면 배율 변경 시 PC/모바일의 글자·버튼, 창 이동과 캔버스 포인터를 확인한다.
- 소수 배율의 도트 확인은 브라우저를 실제 기기 배율로 띄운다(`--force-device-scale-factor=1.25`, 창 크기 1536×864).
  Playwright의 `deviceScaleFactor` 흉내는 루트 줌 0.8을 CSS px에서 1/64px로 잘라 거의 모든 상자가 화소 사이에 놓인다.
- `npm test`, `npm run check:architecture`, `npm run check:css`, `npm run build`.

CSS 테두리와 네이티브 컨트롤의 소수점 픽셀 반올림은 허용한다. 게임 UI 설정은 보존하며,
테스트를 위해 사용자의 실제 저장이나 Windows 디스플레이 설정을 변경하지 않는다.
