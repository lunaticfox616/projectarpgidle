# 우주계 연속 탐사

1~5은하 각각의 천체를 네 구간으로 모두 탐사한다. 무작위로 제시된 방문 경로를 확인하고 출발하면 실제 캐릭터로 자동 진행한다. 별길 후보나 적 특성을 고르는 설정과 개별 천체 탐사 메뉴는 없다. 다음 은하와 성도술은 기존 진입 조건을 유지한다. 이전 개별 전투 저장과 내부 천체 진입 계약은 호환을 위해 유지한다.

## 화면과 경험

- 현재/출발 행성 → 해당 은하 보스를 제목으로 보여준다. 네 탐사 구간은 펼칠 수 있는 행이며, 현재 구간을 자동으로 열고 실제 방문 순서대로 행성 그림과 이름을 표시한다.
- 군집·수호·폭풍은 고정된 천체 특성이다. G1은 기존 `habitatByNode`, 나머지는 천체 ID로 결정한다. 군집은 약한 적 7~8마리, 수호는 보호막 적 1~2마리와 높은 정예 비중, 폭풍은 빠른 번개 속성 적 3~4마리다. 방문 순서나 구간이 바뀌어도 같은 천체의 특성은 유지된다.
- 특성 이름이나 수치 설명을 화면에 나열하지 않는다. 적 밀도·보호막·공격 속도의 차이를 전투에서 경험한다. 행성 색상과 형태는 고정 특성/천체 종류를 반영한다.
- 현재 위치와 탐사 완료 표기를 행성 아래에 표시한다. 마지막 구간은 남은 천체 하나와 해당 은하 보스다. 보스의 고유 패턴과 개체 보정에는 천체 특성을 적용하지 않는다.
- ‘탐사 출발’로 진행하며 ‘전투 보기’는 열린 창을 정리하고 실제 전장을 보여준다. 다음 탐사 구간을 미리 펼쳐 목적지를 확인할 수 있다.
- 연속 탐사 전투 중 기존 진행도 게이지 왼쪽에 `1차 탐사 3/8`처럼 현재 구간의 완료 수/천체 수를 표시한다. 구간 전환 시 `2차 탐사 0/8`로 시작하며 마지막 구간은 `4차 탐사 0/2`다. 은하에 따라 7곳 구간도 해당 길이를 쓴다. 전체 26/25/24곳 합계는 우주계 지도에서만 표시한다. 귀환하거나 탐사가 끝나면 숨긴다. 모바일에서는 기존 진행도 제목이 숨겨져도 이 표시는 유지한다.

## 시리온 중력

시리온(`planet-0`) 한 곳에만 중력장을 적용한다. 전투 시계 기준 1.2초 예고 후 일반/정예 적을 중심 격자 `(4,3)` 방향으로 0.6초 간격 세 번 당기고 4.8초 쉰다. 기존 격자 이동과 점유 검사를 사용하므로 적이나 플레이어와 겹치지 않는다. 플레이어와 보스는 이동시키지 않고 피해량도 변경하지 않는다.

`combat.js`의 기존 틱에서 실행하고 캔버스의 기존 렌더 루프에 타원 두 개로 표시한다. 별도 타이머나 프레임마다 경로 탐색을 추가하지 않는다. 중력의 임시 시계 상태는 로드 시 초기화하며, 대상 적이 없거나 시리온 전투를 벗어나면 제거한다. 방치 전투에서도 같은 규칙을 사용하고 원본 상태와 분리한다.

## 진행과 보상 계약

- `COSMOS_ROUTE_GALAXIES`가 은하별 천체 소속, 출발점, 보스와 구간 길이의 단일 출처다. 기존 125개 천체를 유지한다. G1은 26곳 `[8,8,8,2]`, G2~4는 각 25곳 `[8,8,7,2]`, G5는 24곳 `[8,7,7,2]`다. 출발점과 보스를 고정하고 중간 천체를 중복 없이 무작위 배치한다. 기존 `createSeededRng`와 저장된 시드를 사용하며 새로고침으로 재추첨하지 않는다.
- 구간은 온라인·방치 모두 자동으로 연결한다. 구간마다 재출발 클릭이 필요하지 않다. 완주하면 멈추며 새 탐사를 자동 시작하지 않는다.
- 다음 은하는 이전 은하 보스 처치 후 출발할 수 있다. 보스 진입의 15곳 탐사 조건은 유지한다. 현재 계획의 중간 천체만 연결 제한을 우회하고 마지막 보스와 개별 탐사의 기존 조건은 적용한다. 최종 보스 전에 해당 은하의 다른 천체를 모두 방문한다.
- 실제 HP·ES·회복·스킬·플라스크를 사용한다. 구간 이동은 `startMoving(false)`이며 마을 귀환의 플라스크 충전을 하지 않는다. 상태이상과 플라스크 효과 만료는 기존 지역 이동 규칙을 따른다.
- `data/cosmos-route.js`의 프로필이 일반/정예의 체력·피해·공격 속도와 등장 수를 조절한다. 새 탐사는 기존 안정 관측 신호를 공통 적용한다. 새 전용 보상 체계는 만들지 않으며 보스·천체별 보상 정의를 재사용한다.
- 처치 보상은 즉시 지급한다. 항로의 별가루 합계는 지급 내역으로 별도 수령이 없다. `activeChallenge.rewardSettled`로 중복 지급을 막는다.
- 별가루는 우주계 전용 재화가 아니라 기존 별쐐기와 공유하는 `game.currencies.starDust`다. 천문학자 Lv.12의 별쐐기 영원 고정에 25개를 소비한다. 불완전한 별쐐기 제작 시 보유 5개당 운석 파편 비용을 1개 줄이며 최대 9개 할인한다(별가루 자체는 이때 소비하지 않음).
- 패배하면 진행 중 탐사를 종료하고 우주계 재진입을 30초 제한한다. 이미 받은 보상과 탐사 기록은 보존하며 일반 사냥은 가능하다. 개별 천체로 대기를 우회할 수 없다.
- 완주/실패 후 새 시드로 항로를 생성한다. 자발적 귀환은 경로를 재추첨하지 않는다. 대기는 벽시계 기준이며 방치 정산 중 실패는 정산 시점부터 30초다.

## 소유권과 저장 호환

`data/cosmos-route.js`는 ID·구간 크기·전투 특성·중력·대기 상수, `state.js`는 상태 shape와 전투 지역 스냅샷, `save-migrations.js`는 복원 검증을 소유한다. `js/cosmos-route.js`는 계획, 상태 전이, 전투 프로필 변환과 격자 중력 규칙을 담당한다. DOM·재화 지급에 의존하지 않는다.

`combat.js`는 프로필을 적 생성에 적용한다. `cosmos-atlas.js`는 기존 진입/완료 경계에서 특성을 전투 계약에 담고 `cosmos-route-ui.js`는 DOM과 입력만 소유한다. 데이터 → 상태 → 항로 → 전투 → UI/아틀라스 → 저장 마이그레이션 순서를 유지한다.

버전 5는 은하 번호·네 구간 전체 계획·진행 장부·남은 큐를 저장한다. 천체 특성은 ID에서 읽으며 중복 저장하지 않는다. 잘못된 은하 번호, 중복/누락 천체와 진행 장부/큐의 불일치를 복원 경계에서 거부한다. 전투 계약의 특성은 유효한 현재 항로에서 복원하며 항로가 없으면 제거한다. 손상된 항로만 폐기하고 지갑과 기존 탐사 기록을 유지한다.

이전 버전은 은하 번호가 없는 G1 항로로 복원한다. 진행 중인 버전 4 계획, 버전 3의 구간별 특성과 버전 2의 다섯 구간 계획/신호는 완주할 때까지 보존한다. 다음 출발부터 버전 5를 쓴다. 버전 1 전투 저장은 현재 천체와 기존 선택을 유지한 버전 2로 바꾸며 미선택 갈림길은 안정 관측으로 채운다. 옛 갈림길 대기 저장은 보상/기록을 유지하고 종료한다. 루프나 지역이 달라진 진행 중 항로도 종료로 복원한다.

부팅 시 지역 유효성은 `createCosmosChallengeZone(저장 스냅샷)`으로 판단한다. 아직 전투 계약이 없는 초기 `game`으로 판단하면 유효한 항로가 끊어진다. 아틀라스는 현재 `game` 바인딩을 사용하여 방치 정산 중 원본 상태에 보상을 쓰지 않는다. 방치 정산 중 DOM 렌더는 생략한다.

## 검증과 체험

`scripts/smoke-cosmos-route.js`는 5은하 125곳 완주와 은하별 저장 복원, 세 전투 프로필, 보스 조건, 중복 지급, 실패·대기·귀환, 이전 버전, 손상 특성/계획, 중력의 시간 경계·점유·보스/플레이어 제외 및 방치 상태 분리를 확인한다. 브라우저 검사는 PC/모바일에서 실제 처치와 연속 진행, 전체 은하 선택/잠금, 새로고침, 실패 대기, 중력 표시, 진행도 위치와 라이트 모드를 확인한다.

로컬 `artifacts/cosmos-route/live.html`은 실제 게임과 전투를 메모리 저장소로 격리한 체험 화면이다. 강화 장비, 첫 탐사/전체 은하, 1배/4배 전투, 실패 체험을 제공한다. ‘전체 은하’는 체험용 보스 기록을 채워 2~5은하도 선택할 수 있게 한다. 실제 저장에 영향을 주지 않으며 배포 대상이 아니다.

검증 명령: `node scripts/smoke-cosmos-route.js`, `npm test`, `npx playwright test tests/browser/cosmos-route.spec.js tests/browser/realm-workflow.spec.js tests/browser/core-ui.spec.js -g 'route|cosmos|star map'`, `npm run check:architecture`.

자동 검사는 기능과 저장 호환을 확인한다. 적 밀도와 특성에 따른 실전 난이도 및 재미는 다양한 실제 빌드의 플레이테스트로 추가 조율해야 한다.
