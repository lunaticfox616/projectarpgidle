# 엔드게임 드랍 경험 (2026-10-09)

사용자 목표: "POE식으로 정말 다양한 아이템 종류가 매판 다르게 드랍되는 느낌이 나고 이 아이템은 뭐지? 하는 도파민이 터졌으면 좋겠어.
드랍 시뮬레이터도 만들어줘."

## 1. 출발점 (드랍 시뮬레이터 측정, 바꾸기 전)

`node scripts/drop-simulate.js --tier 16 --loop 60 --maps 300 --seed 1`. 루프 100 엔드게임 영웅(scripts/lib/offline-endgame-fixture.js)이
16등급 지도를 실제 처치 경로로 끝까지 정리한 300판(무리 전원, 상자와 사건 전부, 보스, 지도 완료).

| 판마다 | 값 |
| --- | --- |
| 처치 | 일반 24.7, 정예 3.0, 보스 1, 상자와 사건 8.4 |
| 장비 | 2.5개(일반 0.94, 마법 1.00, 희귀 0.54, 고유 0.02: 50판에 하나) |
| 재화 종류 | 3.1 (마법의 새싹 7.3개가 거의 전부, 나머지는 콘텐츠 방 몫) |
| 보이는 종류 | 7.2, 다음 판과 겹침 34% |
| 황금률 | 0.04 (25판에 하나) |

6등급 루프 20은 종류 6.0, 24등급 루프 150은 8.6. 지도석 옵션은 난이도와 수량/희귀도뿐이라 어떤 종류가 나올지를 바꾸는 장치가 없고,
화석, 홀씨, 도구, 벌집, 지하계 광석, 봉인편린, 심해 재화 같은 재화는 각자의 콘텐츠에서만 나온다.

## 2. 바라는 경험

- **판마다 다른 드랍**: 지도석을 고를 때부터 "이번엔 화석 판", "이번엔 장신구 판"이 보이고, 실제로 그 판의 바닥이 그 종류로 찬다.
- **이건 뭐지?**: 처음 보는 물건, 정체를 모르는 고유, 무리 하나가 쏟아내는 보물, 모으면 무엇이 되는 수집품.
- **다시 돌아오는 이유**: 기운을 골라 원하는 재료를 노리고, 잎 도감을 채우고, 대박 판이 드물게 온다.

## 3. 설계

| 기능 | 순간 | 이어지는 시스템 |
| --- | --- | --- |
| 지도 기운 | 지도석마다 기운 하나(화석 광맥, 무기고, 고유의 메아리, 지도 제작자 …). 희귀한 지도석일수록 짙다 | 지도석 제작, 자동 지도, 각 콘텐츠의 재화, 아틀라스 효과 키 |
| 보물 무리 | 금빛 테의 "보물을 품은" 무리 대장이 쓰러지면 한 종류가 쏟아진다 | 기운 목록을 그대로 씀, 황금 방과 같은 결 |
| 기억의 잎 | 지역과 보스마다 다른 잎이 떨어지고, 같은 잎을 모아 엮으면 정해진 보상 | 고유 도감처럼 남는 수집, 지역 노드 고르기 |
| 발견 연출 | 고유는 바닥에 "미확인 고유"로 누웠다가 주울 때 이름이 드러나고, 큰 발견과 대박은 다른 빛과 소리 | 바닥 전리품, 지도 결과 |
| 드랍 시뮬레이터 | 등급, 루프, 판 수를 넣고 실제 코드로 판을 돌려 카드와 통계로 본다 | 위 모든 수치 조정 |

모든 수치는 첫 제안값이다. 드랍 시뮬레이터로 판마다 결과를 보고 고친다.

## 4. 진행 기록

### 1차: 지도 기운, 보물 무리, 기억의 잎, 발견 등급 (2026-10-09)

- **지도 기운** (data/loot-omens.js, js/loot-omens.js): 지도 노드의 지도석이 생길 때(js/atlas.js stamp) 기운 하나를 받는다. 25가지:
  처치 드랍 13(화석, 홀씨, 연장, 벌집, 별똥, 지하, 봉인, 심해, 잿불, 열쇠, 재화, 젬 잔향, 주얼), 장비 6(무기고, 장신구 함, 갑주 창고,
  고유의 메아리, 타락한 땅, 쌍둥이 그림자), 지도 효과 6(지도 제작자, 각인 무덤, 보급 행렬, 붐비는 방, 정예 행렬, 보스의 꿈).
  그 기운이 줄 것이 아직 열리지 않았으면 뽑히지 않는다(contentProgression.canDropCurrency). 세기는 일반 1, 마법 1.5, 희귀 2, 타락 +0.5.
  처치 드랍은 js/atlas-finds.js가 atlasRun.onKill에서 보통 처치와 같은 길(keepCurrencyDrop, 바닥 더미)로 준다. 장비 기운은 적 배율
  (equipmentDropMul, uniqueChanceMul), 부위 가중치(getEquipmentDropSlot), 드랍 변형 배율(equipmentDropVariants)로, 지도 효과 기운은
  지도 런의 효과(startRun)로 들어간다. 지도석 카드, 보관함 줄, 지도 안 상단 줄에 기운이 보인다.
- **보물 무리**: 지도의 보통 무리가 3.5%로 '보물을 품은' 무리가 되고(무리 키와 첫 적의 해시, Math.random을 쓰지 않음), 금빛 테와 불티의
  일반 몬스터 하나가 쓰러지면 기운 하나에서 8번, 희귀 장비 하나, 12%로 고유 하나가 쏟아진다.
- **기억의 잎** (data/memory-leaves.js, js/memory-leaves.js, js/memory-leaves-ui.js): 24종. 지역마다 셋(3, 5, 7장), 지도 보스 둘, 황금 방
  하나, 보물 무리 둘, 어느 지도나 넷. 처치마다 일반 0.4%, 정예 5%, 보스 35%, 보물 무리 대장은 40배(일반 16%, 3차에서 바꿈). 상태는 game.atlas.leaves(루프를 넘어
  남는다, atlas.normalize가 정리)이고, 바닥에는 'leaf' 줄로 눕는다. 도감의 기억의 잎 탭에서 다 모은 잎을 엮는다. 못 본 잎은 이름과 보상을
  가린다.
- **발견 등급** (data/loot-omens.js moments, js/loot.js lootMoments): 대박(요정의 고리, 우로보로스, 찬란한 봉인편린, 체이싱 고유), 큰 발견
  (황금률, 타오른 잿불가지, 마력 깃든 벌꿀, 고유, 처음 보는 잎, 보물 무리), 좋은 발견(수액 봉오리, 귀한 화석, 열쇠 등). 깊은 미궁은 귀한 화석을
  처치마다 몇 %씩 떨어뜨려서 화석은 좋은 발견에 둔다. 바닥 빛기둥과 소리, 대박 배너,
  방치 결과 재화 칩이 같은 판정을 쓴다. 고유 장비는 바닥에서 '미확인 베이스 이름'과 그림자로 누워 있다가 주울 때 이름이 떠오른다.

측정(같은 명령, 바꾼 뒤): 16등급 루프 60 300판에서 판마다 종류 7.2 → 9.9, 300판 동안 본 종류 78 → 174, 다음 판과 겹침 34% → 24%,
재화 종류 3.1 → 4.7, 고유 0.02 → 0.06, 주얼 0.03 → 0.23, 큰 발견 판마다 0.58(대박 0.01), 보물 무리 0.22, 잎 0.63(24종 모두 봄).
6등급 루프 20은 종류 6.0 → 8.8, 24등급 루프 150은 8.6 → 11.2. 재미는 측정이 아니라 플레이로 확인할 가설이다.

### 2차: 점검과 지도 결과 (2026-10-09)

- **화석은 좋은 발견**: 깊은 미궁이 귀한 화석을 처치마다 떨어뜨려 대박 배너가 흔해질 수 있어서, 대박은 어느 콘텐츠에서나 드문 셋(요정의 고리,
  우로보로스, 찬란한 봉인편린)과 체이싱 고유만 남겼다. 시뮬레이터로 대박 판마다 0.01(100판에 한 번꼴).
- **잎 엮기 보관함 검사**: 지도석을 주는 잎(지도 제작자의 잎)은 지도석 보관함에 자리가 모자라면 엮지 않는다(memoryLeaves.weaveReason).
- **이번 판의 발견**: 지도 결과(js/atlas-ui.js resultHtml)에 제목, 발견 칩, 재화 줄이 나온다. 발견 칩은 바닥과 같은 판정(lootMoments)으로
  좋은 것부터 8개: 대박과 큰 발견 장비, 잎, 등급이 있는 재화. 기록(js/combat-loot-receipts.js)은 드랍이 생기는 순간에 남는다. 처치와 상자를
  정리하는 동안 바로 받거나 바닥에 눕는 순간(js/exploration-ground-loot.js lay)이고, 나중에 줍는 순간은 세지 않는다. 그래서 떠날 때 쓸어
  담는 남은 바닥이 다음 지도의 결과에 섞이지 않는다. 바닥 전리품(2026-10-06)부터 지도 안에서 주운 재화와 장비가 결과에 빠지던 문제도
  이것으로 고쳐졌다. 결과에는 발견 장비 4개와 잎이 함께 저장된다(atlas normalizeLoot).

### 3차: 드랍풀 조정 (2026-10-09)

시뮬레이터로 본 드랍풀 평가(1000판, 출처별)에서 나온 여섯 가지를 사용자가 고르고 조정했다("고유는 10판에 하나", "마법의 새싹은 줄이지
않거나 아주 살짝만").

- **고유 10판에 하나**: 지도 몬스터와 상자의 고유 확률 ×2(LOOT_OMENS.uniqueMul, js/loot-omens.js enemyMods), 보물 무리 고유 12% → 15%.
  상자는 고유 몫이 큰데(장비의 63%가 상자와 사건에서 나온다) 지금까지 지도 배율을 받지 않았다. 상자의 대리 적(chestEnemy)이 몬스터와 같은
  배율을 받는다.
- **대박의 갈래**: 보물 무리의 4%가 황금 보물(흰 금빛 테, '황금 보물을 품은')이다. 16번 뽑고, 고유 하나, 대박 하나(요정의 고리, 찬란한
  봉인편린, 체이싱 고유)를 쏟는다. 쓰러지면 '황금 보물' 배너와 기록 한 줄(보통 보물 무리도 기록 한 줄). 체이싱 고유가 이 길과 체이싱의 잎으로
  실제로 나오게 됐다.
- **다른 재화 얹기**(마법의 새싹은 그대로): 떠도는 기운. 정예는 25%로 한 번, 지도 보스는 두 번 지도의 기운이 아닌 처치 드랍 기운에서 뽑는다.
- **장비 기운의 양**: 장비 기운 배율이 상자에도 붙는다(상자 수량과 항아리 장비 확률). 무기고, 장신구 함, 갑주 창고 판의 장비가 3.4개에서 5개로.
- **잎 평탄화**: 처치 확률 일반 0.4% → 1.2%, 정예 5% → 8%, 보물 무리 대장 40배 → 20배, 황금 방 몬스터 4배(새로). 큰 묶음도 비중을 크게
  낮추지 않는다. 한 벌에 걸리는 판이 28~7000판에서 54~400판 안팎으로(보물 무리 잎은 표본이 작아 흔들린다).
- **지도석 유지**: 지도 안 지도석 처치 확률 일반 1.5% → 0.4%, 정예 8% → 3%, 보스 추가 35% → 5%, 같은 등급 55% → 50%.
- **시뮬레이터**: 17등급 이상은 세계수 씨앗을 맞춰 연다(24등급에서 같은 등급 지도석이 0으로 잘못 나오던 결함). 황금 보물은 대박으로 센다.

측정(16등급 루프 60, 1000판, 시드 7, 바꾸기 전 → 후): 판마다 종류 9.6 → 12.2, 1000판 동안 본 종류 206 → 244, 다음 판과 겹침 24% → 20%,
재화 종류 4.6 → 7.0(마법의 새싹 6.7 → 6.8), 고유 0.05 → 0.10(체이싱 0 → 6), 아무 발견 없는 판 14% → 7%, 지도석 2.7 → 1.8(같은 등급
이상 2.1 → 1.35). 6등급 루프 20은 아무 발견 없는 판 22% → 10%, 고유 0.04 → 0.10. 24등급 루프 150은 고유 0.21, 같은 등급 이상 지도석 1.8.

### 4차: 처치 장비, 지도 보스, 새 고유, 방치 결과, 좋은 희귀 (2026-10-09)

3차 뒤 출처별 측정에서 나온 다섯 가지를 사용자가 차례대로 진행하라고 했다.

- **처치 장비**: 지도의 일반과 정예 처치의 장비 기대 개수 ×2.2(LOOT_OMENS.killGearMul, js/atlas-maps.js applyEnemyMods). 장비가 오래 안
  나오면 희귀를 보장하는 장치(js/loot.js rollEquipmentDrop의 가뭄 보장)가 그만큼 덜 터져서 실제 처치 장비는 판마다 0.6 → 0.95개.
- **지도 보스 보상**: 지도와 수호자 지도의 보스는 장비 2개(50%로 3개), 첫째는 희귀 이상, 둘째는 마법 이상(LOOT_OMENS.mapBoss,
  js/atlas-finds.js grantBossReward). 일반 몬스터의 희귀도 띠로 굴리고 지도 고유 배율을 받지 않는다. 기억 싸움과 최종 싸움은 없다.
  보스 더미의 장비가 0.24 → 2.9개(희귀 1.3).
- **고유 예산**: 보스 보상과 처치 장비로 고유가 판마다 0.16개로 넘쳐서 지도 고유 배율 2 → 1.5, 보물 무리 고유 15% → 10%로 0.10(10판에 하나)을 지킨다.
- **새 고유**: 도감에 처음 오르는 고유(lootMoments.isNewUnique, 줍기 전에 판정)는 주울 때 이름 위에 '새 고유' 표와 '도감 새 고유' 배너(체이싱
  고유는 체이싱 배너가 먼저). 지도 결과의 발견 칩에도 '새' 표.
- **방치 결과의 아틀라스 칸**: 끝낸 지도, 보물 무리, 황금 보물, 기억의 잎과 처음 본 잎. 저장의 누적 수(game.atlas.tally: maps, treasure, golden,
  atlas.normalize가 정리)와 잎 수의 전후 차이로 만든다(js/ui.js getBackgroundAtlasGains, memoryLeaves.gainedBetween).
- **좋은 희귀**: 그 장비가 가질 수 있는 가장 높은 4개 등급 안의 옵션이 2줄이면 좋은 발견, 3줄이면 큰 발견(LOOT_OMENS.fineRare). 16등급 희귀의
  약 10%와 1%. 바닥 이름표에 금빛 테, 주울 때 기록에 '좋은 옵션 N줄'.

측정(16등급 루프 60, 1500판, 시드 7): 판마다 장비 3.2 → 6.1개(희귀 0.8 → 2.0), 고유 0.10 그대로, 좋은 발견 희귀 0.31(큰 발견 0.02),
아무 발견 없는 판 7% → 6%, 판마다 종류 12.2 → 13.2. 다음 판과 겹침 20% → 28%는 보스가 판마다 희귀와 마법 장비를 주어 같은 장비 칸이 겹치는 몫이다.

## 5. 드랍 시뮬레이터

- 화면: `npm run drop:sim` 뒤 `http://127.0.0.1:4176/`(포트는 `DROP_SIM_PORT`). 등급, 루프, 지도석 희귀도, 기운(무작위, 없음, 25가지 중
  하나), 판 수, 시드를 고르면 요약(판마다 종류, 다음 판과 겹침, 큰 발견, 대박, 보물 무리, 잎, 재화 종류), 앞 40판의 판마다 카드(지도,
  기운, 콘텐츠 방, 보물 무리, 떨어진 장비와 재화와 잎과 지도석, 발견 등급 테), 판마다 평균 막대, 재화 막대, 기운별 표, 처음 본 순서가 나온다.
  서버는 tools/drop-simulator/와 저장소 assets/의 그림만 내주고 127.0.0.1에서만 듣는다.
- 명령줄: `node scripts/drop-simulate.js --tier 16 --loop 60 --maps 300 --seed 1 [--rarity rare] [--json out.json]`.
- 계산(scripts/lib/drop-simulation.js, drop-simulation-context.js): 게임 전체를 node vm에 올리고(scripts/lib/game-runtime.js) 루프 100
  엔드게임 영웅(scripts/lib/offline-endgame-fixture.js)으로 지도를 연다. 오프라인 정산(js/combat-replay-projection.js)과 같이 무리 전원을
  handleEnemyDeath로, 상자와 사건을 actExplorationProgress.objects.settleProjected로, 지도 완료를 finishEncounterRun으로 정리한다. 받은
  것은 받는 끝(가방에 넣기, 주얼 받기, 야생 부적 알림, 젬 보상)에서 기록만 하고, 가방에는 넣지 않아 가방 한도와 습득 조건이 드랍을 가리지
  않는다. 드랍 규칙을 바꾸면 시뮬레이터도 그대로 따라간다. 플레이어가 쓰러지거나 일부만 정리하는 판은 세지 않는다(모든 판이 끝까지 정리).
